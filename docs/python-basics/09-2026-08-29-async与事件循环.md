# async/await 与事件循环：单线程协作式并发

日期：2026-08-29
来源：AgentMailbox Dispatcher 多路复用讨论中的知识问答（用户连问
"async和线程有啥关联吗"、"async到底是什么"）——Python 进阶核心概念。

## 一、一句话

```
async = 单线程里"等的时候干别的活"
await = "我在这里让出——等这个结果，但你先去干别的"
事件循环 = 一个 while True 循环，轮流跑各个任务的片段（到 await 停）
```

## 二、同步 vs 异步（本质区别）

```python
# 同步：等的时候干等（线程占着啥也不干）
result = 请求网络(...)   # 等 2 秒——线程干等 2 秒

# 异步：等的时候去干别的
result = await 请求网络(...)  # 发起请求——立刻返回"凭证"，不干等
# 中间这 2 秒：事件循环去跑别的任务（另一个请求/计算）
```

```
类比（等外卖）：
  同步：站在门口干等外卖（啥也干不了）
  async：下单后该干嘛干嘛——写代码/看书，外卖到了（事件）→ 取
```

## 三、事件循环（async 的底层真相）

```
async 不是魔法——底层是一个循环：

  while True:
      task = 下一个要执行的任务()     # 队列里拿
      task.run_until_await()          # 跑这个任务直到它 await
      # 任务 await 了 → 挂起（记下"在等什么"）
      # 等的东西好了（IO 完成/超时）→ 放回队列
      # 循环继续——跑下一个任务

→ 所有"并发"是一个线程循环里轮流跑任务片段
→ 每个任务跑一段（到 await 停）→ 换下一个 → 循环往复
→ 这就是"协作式多任务"（任务自己让出，不是被系统抢）
```

## 四、线程 vs async（核心对比）

```
            线程（threading）          async（asyncio）
并发方式    真并行（多核同时跑）      单线程交错（同一时刻一个）
切换谁管    操作系统（抢占式）        程序员 await（协作式）
数据安全    共享内存要加锁           单线程天然安全（无竞态）
阻塞代价    线程阻塞浪费（等 IO）     等 IO 时让出（不浪费）
适合场景    CPU 密集 / 阻塞库         IO 密集 / 大量连接
复杂度      锁/竞态/死锁             async/await 传染（处处要改）

类比（银行柜台）：
  线程 = 开 3 个柜台（真并行）
  async = 1 个柜员 + 取号机（轮流处理，客户填表（await）时服务下一个）
```

```
关键：并发（交错）≠ 并行（同时）
  async 是并发（单线程交错）——不是并行（多核同时）
  适合"等"很多的场景（网络/IO——大部分时间在等）
  不适合"算"很多的场景（CPU 密集——单线程算不动）
```

## 五、Python 代码形态

```python
import asyncio

async def fetch(url):           # async def = 定义协程（可挂起的任务）
    print(f"请求 {url}")
    await asyncio.sleep(1)      # await = 让出（等 1 秒，期间干别的）
    return f"{url} 的结果"

async def main():
    # 同时发起 3 个请求（交错执行——总耗时 ≈ 1 秒，同步版 3 秒）
    results = await asyncio.gather(
        fetch("a.com"), fetch("b.com"), fetch("c.com"))
    print(results)

asyncio.run(main())             # 启动事件循环

关键点：
  async def = 定义协程（特殊函数——可挂起恢复）
  await 表达式 = 让出点（挂起当前协程，等结果）
  asyncio.run = 启动事件循环（驱动所有协程）
  asyncio.gather = 并发跑多个协程（交错）
```

## 六、async 与线程的关联（asyncio 内部真相）

```
asyncio 单线程为主，但【线程池辅助】处理阻塞任务：
  ① 事件循环 = 一个主线程跑（协程交错）
  ② 网络 IO：事件循环用 selectors/epoll 监听（不阻塞）
  ③ CPU 密集/阻塞库（如 requests）：
     → asyncio.to_thread() / run_in_executor()
     → 丢给【线程池】跑（绕过阻塞）→ 完成后回调回事件循环
  → asyncio = 单线程事件循环 + 线程池辅助（to_thread）

类比（Java）：
  线程 ≈ Java Thread（真并行）
  async ≈ CompletableFuture/虚拟线程（协作任务）
  asyncio.to_thread ≈ ExecutorService（线程池辅助）
```

## 七、async 的代价（没有银弹）

```
❌ 传染性：async 函数只能被 async 函数调用
   → 改一个函数 async → 所有调用链都要改（处处 await）
   → 同步库（requests）调不了——要换 async 版（httpx）
❌ 心智负担：await 位置/异步竞态（更难查）
❌ 调试难：堆栈跨 await 断裂（报错定位难）
→ 这就是"async 重构大工程 + 高回归风险"的原因（方案 C 评估 2-3 天）
```

## 八、回到项目场景（为什么讨论它）

```
qi-agent 现状：多线程模型（manager 后台线程 + AgentPool + 提炼线程）
  → 共享状态竞争（并发问题——需要锁/队列/邮箱）

async 重构（未来方案 C）：
  agent 循环改 async（await LLM/工具）→ 单线程事件循环
  → 共享状态竞争【从根上消失】（单线程——不用加锁）
  → "epoll 级优雅"自动获得（事件循环内部 selectors）

但场景账：
  现在线程版够用（几十 agent——瓶颈是 LLM 秒级，不是线程微秒级）
  async 重构 = 进化（触发：万级连接/Web 网关）不是必须
  → AgentMailbox 接口设计【不绑定线程】——async 版同样 send/drain
```

## 九、要点速记

```
1. async = 单线程协作式并发（等的时候干别的）；await = 让出点
2. 事件循环 = while True 轮流跑任务片段（到 await 停）
3. 并发（交错）≠ 并行（同时）——async 是前者，线程是后者
4. 线程：多核真并行 + 抢占 + 要加锁；async：单核交错 + 协作 + 天然安全
5. asyncio = 单线程事件循环 + 线程池辅助（to_thread 处理阻塞）
6. async 适合 IO 密集（等得多）；代价 = 全链路传染（处处 await）
7. 场景账：线程够用不强行 async；未来 Web 网关/万级连接再重构
```
