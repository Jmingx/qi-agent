# qi-agent 手工验证手册（2026-08-30——用户执行/校验版）

> 用法：本手册由【用户】执行验证。每节：① 操作步骤 ② 预期结果
>       ③ 日志检查点（tail 指定日志看什么）。
> 前置：启动 CLI 前先开 4 个日志窗口（实时观察）：
>   tail -f ~/.qi-agent/logs/events.log
>   tail -f ~/.qi-agent/logs/message.log
>   tail -f ~/.qi-agent/logs/run.log
>   tail -f ~/.qi-agent/logs/rpc.log
> 启动：cd PycharmProjects/qi-agent && uv run python -m qi_agent.cli --debug

---

## 用例 1：事件（events）——对话全链路事件流

**操作**：
1. 启动 CLI（--debug）
2. 输入：`你好，介绍一下你自己`

**预期**：
- 界面正常回复（DeepSeek 回答）
- events.log 出现完整事件序列

**日志检查**（events.log）：
```
应看到（按序）：
  emit context=ctx_xxx event=agent/turn-start listeners=1 data={'user_input': '你好，介绍一下你自己'}
  emit context=ctx_xxx event=agent/pre-step listeners=2 data={...}      ← 每轮循环触发
  emit context=ctx_xxx event=agent/pre-llm listeners=2 data={...}
  emit context=ctx_xxx event=agent/post-llm listeners=2 data={...}
  emit context=ctx_xxx event=agent/final-answer listeners=0 data={'content': '...'}
  emit context=ctx_xxx event=agent/turn-end listeners=0 data={'reason': '...'}
```
**校验点**：
- [ ] context= 后是 ctx_ 前缀 id（不是空的）
- [ ] data 是【完整】内容（不省略——你输入的话原样在）
- [ ] turn-start 和 final-answer 都出现（一轮完整生命周期）
- [ ] listeners 数字（pre-step=2 说明 context_manager + 邮局消费在听）

## 用例 2：消息（message）——邮局全链路

**操作**：
1. 继续在 CLI 里，输入：`帮我查一下 Python 的 datetime 模块有什么常用功能`
   （触发子 agent——/delegate 或工具调用）

**预期**：
- 子 agent 被拉起并返回结果
- message.log 出现完整消息流

**日志检查**（message.log）：
```
应看到（按序）：
  send owner=ctx_xxx sender=ctx_xxx target=agt_xxx type=steer id=... data=...
  deliver sender=ctx_xxx target=agt_xxx type=steer id=... data=...
  send owner=agt_xxx sender=agt_xxx target=ctx_xxx type=result id=... data={...}
  deliver sender=agt_xxx target=ctx_xxx type=result id=... data={...}
```
**校验点**：
- [ ] send 和 deliver【成对】出现（同一 id 先 send 后 deliver——投递成功）
- [ ] data= 是【完整内容】（能看到发给子的指令、子返回的结果）
- [ ] owner/sender/target 都是 ctx_/agt_ 前缀（不是空/魔法字符串）
- [ ] 子结果（type=result）投回父（target=ctx_xxx——不是 "main"）

## 用例 3：子 agent——spawn 生命周期

**操作**：
1. CLI 输入：`/delegate 帮我调研一下：Python 装饰器有哪几种用法？`

**预期**：
- 子 agent 跑起来（可能多次 LLM 调用）
- 返回结构化结果（summary/artifacts/status）

**日志检查**（run.log）：
```
应看到：
  run-start context=ctx_xxx turn=N input=/delegate 帮我调研...
  subagent-complete context=agt_xxx parent=ctx_xxx status=completed
```
**校验点**：
- [ ] subagent-complete 出现（子 agent 正常完成）
- [ ] context=agt_xxx（子 agent 有自己的 id——agt_ 前缀）
- [ ] parent=ctx_xxx（回传目标=父 context——不是 "main"）
- [ ] status=completed（成功；若是 failed 看 error 字段）

## 用例 4：子 agent 内容获取——多轮指导

**操作**：
1. CLI 输入：`/delegate 调研 Python 装饰器`
2. 子 agent 运行期间（或完成后），输入补充：
   `补充：重点讲 functools.wraps 的作用，给我一个带参数的装饰器例子`
   （这条会作为【对话投递/steer】发给子 agent——下轮生效）

**预期**：
- 子 agent 的后续输出体现补充要求（提到 wraps、带参例子）

**日志检查**：
- message.log：
```
  send owner=ctx_xxx sender=ctx_xxx target=agt_xxx type=message id=... data=补充：重点讲 functools.wraps...
  deliver sender=ctx_xxx target=agt_xxx type=message id=... data=补充：重点讲 functools.wraps...
```
- events.log：
```
  emit context=agt_xxx event=agent/pre-step listeners=2 data={...}
  （data 的 messages 里应含 "[消息投递] 补充：重点讲..." 或 "[引导] ..."）
```
**校验点**：
- [ ] message.log 出现 type=message 的投递（内容=你的补充）
- [ ] 子 agent 回复体现了补充内容（wraps 被提到）——这是最终验收！
- [ ] events.log 的 pre-step 里 messages 含注入内容（子每轮消费）

## 用例 5：记忆——/remember + /memory + 主动提炼

**操作**：
1. CLI 输入：`/remember 我最近在学 Python 装饰器`
2. CLI 输入：`/memory`
3. 连续对话 10 轮以上（正常提问），观察主动提炼

**预期**：
- /remember 后：提示"已记住"
- /memory 显示记忆内容（含刚记住的）
- 10 轮后 run.log 出现提炼记录

**日志检查**：
- run.log 搜 memory：
```
  （主动提炼触发——subagent 提炼写入）
```
- ~/MEMORY.md 或 ~/.qi-agent/ 记忆文件：应含"学 Python 装饰器"
**校验点**：
- [ ] /memory 能看到刚才 /remember 的内容（跨会话持久）
- [ ] 10 轮后 run.log 有提炼痕迹（或 ~/ 记忆文件更新）
- [ ] 提炼失败不崩主对话（继续能聊）

## 用例 6：上下文压缩——/status + /compact + /context

**操作**：
1. 连续对话几轮（制造上下文）
2. CLI 输入：`/status`（看消息数）
3. CLI 输入：`/compact`（强制压缩）
4. CLI 输入：`/context`（看压缩后构成）

**预期**：
- /status 显示当前消息数/token
- /compact 执行压缩（消息数减少或触发摘要）
- /context 显示压缩后占用

**日志检查**：
- events.log：
```
  emit context=ctx_xxx event=agent/pre-step listeners=2 data={...}
  （pre-step 每轮触发——context_manager 策略链在其中执行）
```
**校验点**：
- [ ] /status 能显示轮数/消息/token（不报错）
- [ ] /compact 后 /context 显示构成有变化（压缩生效）
- [ ] 压缩后对话继续正常（不崩）

## 用例 7：steer——主 agent 引导（脚本路径）

**操作**（脚本——CLI 暂未接 steer）：
```
PYTHONPATH= .venv/Scripts/python -c "
import time
from qi_agent.agents.agent_manager import AgentManager
from qi_agent.context.context import AgentContext
from qi_agent.agents.agent import Agent
from qi_agent.llm import ChatResult

mgr = AgentManager()
ctx = AgentContext(context_id='ctx_steertest')
mgr.register(ctx, role='main')

class C:
    def __init__(self): self.seen = []
    def chat(self, messages, tools=None):
        self.seen.append(messages)
        return ChatResult(content='ok', tool_calls=[], assistant_message={'role':'assistant','content':'ok'}, usage=None)
    def chat_stream(self, messages, tools=None, on_delta=None): return self.chat(messages, tools)

agent = Agent(C(), system_prompt='', max_turns=2, context=ctx)
mgr.steer(ctx.id, '改方向：少用工具', sender_id='unknown')
time.sleep(0.3)
agent.chat('你好')
print('OK——steer 注入完成')
"
```
**预期**：
- 打印 OK
- message.log 出现 steer 投递 + 注入

**日志检查**：
- message.log：
```
  send owner=ctx_steertest sender=unknown target=ctx_steertest type=steer id=... data=改方向：少用工具
  deliver sender=unknown target=ctx_steertest type=steer id=... data=改方向：少用工具
```
**校验点**：
- [ ] sender=unknown（外部用户发起——无 context 身份）
- [ ] target=ctx_steertest（被引导的主 agent）
- [ ] type=steer + data 完整

## 用例 8：退信回执 NACK——投递失败可感知

**操作**（脚本）：
```
PYTHONPATH= .venv/Scripts/python -c "
import time
from qi_agent.agents.agent_manager import AgentManager
from qi_agent.agents.mailbox import Message, MessageType
from qi_agent.context.context import AgentContext

mgr = AgentManager()
a = AgentContext(context_id='ctx_nack')
mgr.register(a, role='main')
mgr.dispatcher.send(Message(sender='ctx_nack', target='nobody',
                            type=MessageType.STEER, data='测试'))
time.sleep(0.5)
got = a.mailbox.drain()
print('收到回执:', got[0].type.value if got else '无')
print('原因:', got[0].data if got else '')
"
```
**预期**：
- 打印"收到回执: nack" + 原因 unknown_target

**日志检查**：
- message.log：
```
  undeliverable sender=ctx_nack target=nobody type=steer id=... data=测试
  nack-deliver sender=dispatcher target=ctx_nack id=... data={'original_id': ..., 'reason': 'unknown_target'}
```
**校验点**：
- [ ] undeliverable 和 nack-deliver【成对】出现
- [ ] 发送方（ctx_nack）收到回执（脚本打印 nack）
- [ ] 无无限递归（没有第三个 undeliverable）
