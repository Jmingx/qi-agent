# 事件地图（EventBus 全览——事件 × 生产者 × 消费者）

> 日期：2026-08-30
> 用途：事件监听分散在多个文件（plugins/8 个 + delegate_task + agent_manager），
>       本地图是"看代码时的总览"——一个事件谁发、谁听、干什么，一眼定位。
> 运行时佐证：~/.qi-agent/logs/events.log（emit/on 全记录）

## 一、事件总表

| 事件 | 生产者（emit） | 消费者（on） | 用途 |
|---|---|---|---|
| agent/turn-start | agent.py | debug_logger | 轮次开始（打印 [USER]） |
| agent/pre-step | agent.py（waterfall） | context_manager / delegate_task(_steer_watcher) | 消息历史改写/注入（裁剪/steer 消费） |
| agent/pre-llm | agent.py | debug_logger / resource_monitor | LLM 请求前（打印 [CTX]/[REQ]/估算） |
| agent/post-llm | agent.py | debug_logger / resource_monitor | LLM 响应后（usage/成本/流式估算） |
| agent/tool-result | agent.py | tool_stats | 工具执行后（统计） |
| agent/tool-approval | agent.py | approval_gate / delegate_task(审批处理) | 工具审批（权限/弹窗） |
| agent/final-answer | agent.py | （无——预留） | 最终回答（流式/记忆提炼触发预留） |
| agent/turn-end | agent.py | （无——预留） | 轮次结束（统计/审计） |
| agent-manager/register | agent_manager | （无——预留） | agent 上线（可观测） |
| subagent/steer | agent_manager | （无——预留） | steer 审计（已走邮局，事件留痕） |
| subagent/stop | context.stop | （无——预留） | stop 审计 |

## 二、消费者分布（谁在听）

```
plugins/builtin/（8 个插件——通过 load_plugins 装配）：
  debug_logger.py      agent/turn-start, pre-llm, post-llm（日志打印）
  context_manager.py   agent/pre-step（瀑布改写——裁剪/注入）
  resource_monitor.py  agent/pre-llm, post-llm（token 估算/统计）
  tool_stats.py        agent/tool-result（工具统计）
  approval_gate.py     agent/tool-approval（审批）
  security_guard.py    （安全——监听工具调用）
  memory.py            （记忆——post-llm 提炼触发）
  env_info.py          （环境信息注入）

delegate_task.py（子 agent 装配）：
  agent/tool-approval  审批处理（子 agent 权限）
  agent/pre-step       _steer_watcher（消费 steer/对话投递）

未消费（预留）：
  agent/final-answer / turn-end / agent-manager/register / subagent/*
  → 事件已 emit（审计/日志留痕），业务插件未接
```

## 三、怎么定位（读代码速查）

```
① 想找"谁触发这个事件" → grep 'emit("事件名"'（生产者）
② 想找"谁响应这个事件" → grep 'on("事件名"'（消费者）
③ 想总览 → 本地图（事件表）
④ 运行时看 → tail ~/.qi-agent/logs/events.log
   （emit event=X listeners=N data=...——N 是监听者数，0=无人听）

插件装配入口：qi_agent/agents/factory.py:125 load_plugins(context.events, config)
  每个插件文件 = register_plugin(events) 注册自己的监听
```

## 四、设计说明

```
事件 = 插件接口（机制层 emit + 插件层 on——对齐 Cordis/DSH）
  · 内核循环不感知插件（emit 后不关心谁听——横切零侵入）
  · 插件注册即监听（load_plugins 装配——加插件不改内核）
  · 部分事件"无人听"是正常（预留接口——插件逐步接入）

两条流（对齐架构总览 28 号）：
  · 事件总线 = agent 生命周期内的【同步钩子】（插件横切）
  · 邮局 = 跨线程/跨 agent 的【异步通信】（消息队列）
  → steer/结果/对话投递走邮局（异步），生命周期走事件（同步）
