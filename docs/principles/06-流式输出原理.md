# 06-流式输出原理（SSE 与 stream=True）

> 对应阶段：v0.4.1（流式输出）
> 日期：2026-08-17
> 配套代码：qi_agent/llm.py chat_stream()、agent.py stream_callback、cli.py

## 1. 为什么要流式

普通对话等完整响应一次性打印（等待期黑屏）；流式是"边生成边显示"——打字机效果。用户体验质变：等待时能看到"它正在思考"。

## 2. 底层机制：SSE（Server-Sent Events）

服务器把响应拆成小数据块，通过 HTTP 长连接**逐块推送**，客户端每收到一块立即显示。

```
普通: [等待3秒] → 一次性打印完整回答
流式: 你(0.1s) → 你好！(0.3s) → 你好！很高兴(0.6s) → ...
```

## 3. API 差异：stream=True 返回迭代器

```python
# 普通：一次拿完整响应
response = client.chat.completions.create(model=..., messages=...)
text = response.choices[0].message.content

# 流式：返回迭代器，逐块取增量（delta）
stream = client.chat.completions.create(model=..., messages=..., stream=True)
for chunk in stream:
    delta = chunk.choices[0].delta.content
    if delta:
        print(delta, end="", flush=True)   # flush=True 立即输出（关键！）
```

**核心：stream=True 时拿到的是迭代器，每块含 delta.content（一小片文本），累积即完整回答。**

## 4. 关键设计：只流式"最终回答"轮次

工具调用轮次不流式（要等完整 tool_calls 结构才能执行工具）；只有"模型直接给文本"的轮次流式。

```
用户: 现在几点了？
模型: [普通] tool_calls: get_time → 执行工具 → 拿到结果
模型: [流式] 现在是 2026-08-17 ...    ← 只有这轮流式
```

## 5. 架构：三层分工

```
llm.py   chat_stream() 生成器 —— 只管产出增量（yield），不渲染
agent.py stream_callback 参数 —— 决定何时流式（向后兼容，None=普通）
cli.py   lambda 回调 + flush=True —— 打字机显示
```

### 5.1 llm.py：生成器（只产出）

```python
def chat_stream(self, messages, tools=None):
    kwargs = {..., "stream": True}
    stream = self._client.chat.completions.create(**kwargs)
    for chunk in stream:
        delta = chunk.choices[0].delta.content
        if delta:
            yield delta
```

### 5.2 agent.py：流式分支（累积完整文本！）

```python
if stream_callback is not None:
    collected = []
    for delta in self.client.chat_stream(self.messages, tools=...):
        stream_callback(delta)
        collected.append(delta)
    full_text = "".join(collected)      # 历史必须存完整文本！
    self.messages.append({"role": "assistant", "content": full_text})
    return full_text
```

### 5.3 cli.py：打字机（flush 关键）

```python
print("agent> ", end="", flush=True)
agent.chat(user_input, stream_callback=lambda delta: print(delta, end="", flush=True))
print()   # 结束后换行
```

## 6. 踩过的坑

1. **重复打印**：流式已打印增量，又 print(reply) 会重复。解决：先打前缀，流式内容紧跟，结束换行。
2. **历史存片段**：如果历史存增量而非完整文本，多轮对话会断裂。必须 join 成完整文本再存。
3. **测试替身适配**：cli 总是流式后，所有 CLI 测试的 FakeClient 必须实现 chat_stream（否则 AttributeError 被 except 吞掉，历史残缺）。
4. **调用次数语义变化**：流式模式每轮 = chat 探测（判断是否工具调用）+ chat_stream 重取（纯文本）2 次调用。测试断言按 2 次/轮适配。

## 7. 与 Hermes 的对照

Hermes 的流式实现更完整：支持流式 + 工具调用同时（流式解析 tool_calls delta）、流式中断（Ctrl+C 停止生成但保留已生成部分）、UI 渲染（markdown 高亮）。我们的最小实现只覆盖"纯文本流式"，方向一致、规模更小。

## 8. 性能说明（诚实面对）

**当前实现有个代价：纯文本回答轮次 = 2 次 API 调用**（先 chat 探测 + 再 chat_stream 重取）。因为 agent loop 第一轮必须用完整响应判断"是否工具调用"。业界优化方案：用 stream=True 的响应同时解析 tool_calls delta 和文本增量（一轮搞定）——复杂度高，留给后续 TODO。
