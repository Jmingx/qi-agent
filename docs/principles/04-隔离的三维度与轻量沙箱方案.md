# 04-隔离的三个维度与轻量沙箱方案谱系

> 归档来源：qi-agent 开发会话问答（2026-08-17）
> 背景：用户问"uv 能隔离，有没有类似轻量方案"——引出环境/资源/安全三轴框架
> 相关：docs/todos/tool-calling.md 沙箱条目

## 1. 关键认知：uv/venv 隔离的不是"资源/安全"

uv/venv 隔离的是**环境（依赖包）**，不是资源和安全：

| 维度 | 隔离什么 | uv/venv 能做吗 |
|------|---------|---------------|
| 环境隔离 | 依赖包不冲突 | ✅ 能做 |
| 资源隔离 | CPU/内存/时间有限额 | ❌ 不能（代码照样用满资源） |
| 安全隔离 | 权限受限（防恶意操作） | ❌ 不能（代码照样能删文件/读 key） |

**类比（Java）：venv 像 Maven 模块隔离（依赖不冲突），不是 JVM SecurityManager（权限控制）。**

## 2. 隔离的三个维度（核心框架）

| 维度 | 隔离什么 | 代表技术 | 轻量度 |
|------|---------|---------|--------|
| 环境隔离 | 依赖包不冲突 | venv / uv / pipx | ⭐ 最轻 |
| 资源隔离 | CPU/内存/时间有限额 | Windows Job Objects、cgroup、ulimit、psutil 监控 | ⭐⭐ 轻 |
| 安全隔离 | 权限受限（不能碰敏感东西） | RestrictedPython、AppContainer、容器 | ⭐~⭐⭐⭐⭐⭐ |

**沙箱 = 三轴组合**（环境 + 资源 + 安全），不是单一技术。

## 3. 轻量方案谱系

### 第一梯队：纯软件、零依赖（最轻）

| 方案 | 原理 | 隔离能力 |
|------|------|---------|
| RestrictedPython | 解释器层拦截 import/属性访问 | 安全隔离（防恶意代码，含 `().__class__` 逃逸） |
| psutil 监控 + 硬超时 | 轮询子进程内存/CPU，超限杀进程 | 资源隔离 |
| Windows Job Objects | 系统级：子进程内存/CPU/句柄限制 | 资源隔离 |
| ast 白名单 | 解析 AST，只允许安全节点 | 安全隔离 |

### 第二梯队：单进程轻量虚拟化

| 方案 | 原理 | 重量 |
|------|------|------|
| pyodide / WASM | Python 编译成 WebAssembly 在沙箱跑 | ⭐⭐（无 OS 依赖，功能受限） |
| WSL2 发行版 | 轻量虚拟机 | ⭐⭐⭐ |

### 第三梯队：重量级（不可信代码/多租户才用）

Docker 容器 / 虚拟机 / 远程执行——见 TODO 清单 Docker 条目（依赖重，仅不可信代码场景值得）。

## 4. 组合式沙箱：三轴合一（全部轻量）

```python
def sandbox_run(code: str) -> str:
    # ① 环境隔离：独立 venv（uv 已有能力）
    # ② 安全隔离：RestrictedPython 解释器层拦截
    # ③ 资源隔离：psutil 监控子进程内存 + 硬超时
    pass
```

| 维度 | 方案 | 重量 | 效果 |
|------|------|------|------|
| 环境 | uv 子环境 | ⭐ | 依赖隔离 |
| 安全 | RestrictedPython | ⭐ | 拦截危险操作 |
| 资源 | psutil + 超时 | ⭐ | 内存/CPU/时间限制 |

**纯 Python 依赖（RestrictedPython + psutil），无需 Docker/虚拟机，覆盖沙箱全部维度。**

## 5. 核心结论

1. **uv 隔离环境，不隔离资源/安全**——三者是独立维度
2. **"轻量 + 有效" = 三轴各选最轻方案组合**：uv 子环境 + RestrictedPython + psutil 监控
3. **沙箱强度 = f(信任边界)**：自己代码用轻方案，不可信代码才需要重武器
