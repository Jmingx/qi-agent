# 14-2026-08-23-机制层与本体层分层（工具与插件系统）

> 项目技术原理归档（P0-1）。面向 agent 开发小白读者。
> 关联方案：`docs/plans/2026-08-23-工具与插件系统分层方案.md`

## 一句话

**把"系统怎么运作"（机制层）和"系统有哪些能力"（本体层）分到两个目录——tools/ 与 plugins/ 都是"机制文件在根、能力文件在 builtin/ 子目录"的同构结构。**

## 为什么要分（问题）

改造前 `tools/` 17 个文件、`plugins/` 9 个文件混装两类职责：

```
tools/
├── registry.py / executor.py / decision.py   ← 机制：怎么注册/执行/决策（几乎不变）
├── read_file.py / shell.py / ...              ← 本体：有哪些工具（频繁新增）
└── __init__.py                                ← 装配

问题：
  ① 找文件难：新工具开发者要在一堆机制文件里找"我该放哪"
  ② 职责不分：稳定的心脏和常变的血肉混在一起
  ③ 与 Hermes 不一致：Hermes 是"工具机制 + builtin_tools/ 分离"
```

## 分层后的结构（同构模式）

```
tools/                       plugins/
├── __init__.py               ├── __init__.py
├── registry.py               ├── registry.py
├── executor.py               ├── config.py
├── decision.py               └── builtin/          ← 本体层
└── builtin/                  ├── __init__.py
    ├── __init__.py           ├── security_guard.py …
    ├── read_file.py …        └── tool_stats.py
    └── _sandbox_runner.py
```

**心智模型**（两个包完全对称）：

```
机制层（根目录）= 系统怎么运作 —— 稳定，一次写对几乎不再改
本体层（builtin/）= 系统有哪些能力 —— 常变，新增能力只动这里
```

## 核心机制：import 即注册的触发链路

```
import qi_agent.tools
  └─ tools/__init__.py: from . import builtin        ← ① 触发子包
       └─ tools/builtin/__init__.py: from . import read_file, shell, ...
            └─ 每个工具模块执行 register()            ← ② 自注册进注册表
```

**关键**：Python 的 import 是**模块加载时执行顶层代码**——`builtin/__init__.py` 里 import 各工具文件，等价于"加载这些模块"，加载即执行 `register()`。**漏一个 import = 该工具静默不注册**（CLI 里找不到它，不报错）——这就是为什么 builtin/__init__.py 必须显式列出全部工具。

**Java 类比**：`builtin/__init__.py` 的 import 列表 ≈ 一个 `ServiceLoader` 配置清单（列出所有实现类）；`register()` ≈ 类加载时的静态注册。

## 引用面的迁移（改了什么）

```
不需要改：机制层引用（agent.py/plugins 引用 registry/executor/decision——
         绝对路径不变，工具文件内部 from qi_agent.tools.registry import register 也天然可用）

需要改：本体 import 加 .builtin 段
  from qi_agent.tools.read_file import read_file
    → from qi_agent.tools.builtin.read_file import read_file
  from qi_agent.plugins.approval_gate import ApprovalGatePlugin
    → from qi_agent.plugins.builtin.approval_gate import ApprovalGatePlugin
  约 20 个测试文件 + cli.py + 1 处 mock.patch 字符串路径
```

## 踩过的坑

### 1. 批量替换误伤机制引用

用脚本批量替换 `qi_agent.plugins.X → qi_agent.plugins.builtin.X` 时，
`from qi_agent.plugins import load_plugins`（load_plugins 是**机制**）被误改成
`from qi_agent.plugins.builtin import load_plugins`——build 直接崩。

**教训**：批量替换必须区分"本体名名单"和"机制名名单"；`from pkg import X` 这种
**不带点**的导入，X 可能是机制名也可能是本体名——不能无脑替换。

### 2. 移动文件改变 `__file__` 相对路径推导（重要！）

`write_file.py` 用 `Path(__file__).resolve().parent.parent.parent` 推导项目根
（写文件的默认范围）。移动进 `builtin/` 后多一层目录，同样代码少跳一级 →
项目根变成了 `qi_agent/` → 测试写相对路径被判"项目外写入" → 审批误触发。

**修复**：`.parent` 加一级（×4）。**教训**：**任何用 `__file__` 推导相对路径的
代码，移动目录后必须重新推导**——这是分层迁移最隐蔽的坑（测试全量回归才抓到）。

### 3. git mv 保留历史

已跟踪文件用 `git mv`（git 记录为 rename，历史保留）；未跟踪的新文件
（decision.py/executor.py——机制层，本就不移动）不受影响。
