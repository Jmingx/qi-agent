# AgentPool：运行时/执行者分离 + 并发治理技术原理

日期：2026-08-24
方案：docs/plans/2026-08-24-AgentPool方案.md（评审通过）

## 核心架构：运行时与执行者分离

```
build_runtime() → RuntimeBundle（manager + context_id + agent_id + installed）
  —— 运行时，长期存活（会话在它在），不建 agent（延迟注入）
make_agent(context, type="standard") → Agent 执行者
  —— 执行者工厂（可插拔：换实现=换 type），按需创建
AgentPool = 轻壳（工厂 + 并发治理，不复用）
  acquire() → 检查 max_workers → make_agent → 跑任务 → release（即弃）
```

**为什么分离（用户拍板 D1=B 彻底拆分）**：
- "同一 context 可被新 Agent 实例接管"的完整落地（执行者按需创建/销毁）
- 换执行者实现（agents/specialist.py）= 换 make_agent type，运行时零改动
- 插件挂 context.events（数据载体的总线），与执行者无关——延迟注入不影响

## 为什么池不复用（用户评审拍板）

```
make_agent ≈ 微秒级（配置装配，无网络 I/O）
维护池状态（借出/归还/健康检查）复杂度 >> 省下的构造开销
→ 池 = Semaphore（限并发）+ Factory（统一派活），不是 ThreadPool 式复用

类比（Java）：Executors 的工厂 + 信号量，不是线程池的 worker 复用
（线程重才复用；agent 轻，即建即用）
```

## 两种 pool（场景矩阵，用户确认两种都要）

```
主对话池（一个 context 一个 agent，串行）：
  CLI：build_runtime + make_agent（主对话执行者）
  ——本质是"执行者工厂"，不需要并发治理（用户一次一句话）

子任务池（多 context 多 agent，并行）：
  SubagentManager.spawn → pool（多个 worker 并行）
  ——并发治理在这里生效（max_workers 控制 worker 数）
  ——各 worker 用独立 context（隔离，对齐 subagent 哲学）

演进：SubagentManager 内部走 pool（统一派活）
  subagent = pool 的受限特例（工具子集 + 授权清单）
```

## 关键实现决策

### 1. 并发上限（等待而非拒绝）

```
acquire() 超限时：轮询等待（time.sleep(0.05)），不抛异常
  ——等待更友好（任务会完成），拒绝要调用方重试
release() 用 try/finally 保证额度回收（异常也不泄漏）
```

### 2. max_concurrent 真正生效

```
此前 SubagentManager.max_concurrent 存着没用（spawn 不检查）
演进后：AgentManager 持有 AgentPool(max_workers=max_concurrent)
  _run 里 acquire（超限等待）→ 跑任务 → finally release
  ——并发治理落地（子任务并行受控）
```

### 3. 循环导入处理

```
pool → factory → agent_manager → pool（循环链）
解法：pool 不模块级 import factory.make_agent（acquire 内延迟 import）
  ——pool 是轻壳，工厂延迟注入（也符合"可插拔"——工厂可换）
```

## 与业界对照

| 维度 | Hermes | qi-agent（本方案） |
|---|---|---|
| 执行者创建 | agent 随会话创建 | build_runtime + make_agent（延迟） |
| 并发治理 | max_concurrent_children | AgentPool.max_workers（等待式） |
| 执行者复用 | 不复用 | 不复用（make_agent 轻） |
| 子任务 | delegate_task | SubagentManager 走 pool（统一派活） |

## 遗留（v2+）

- 多主对话：build_runtime 可多次调用（每会话一个运行时）——会话管理 v2
- team 模式：多个 worker 并行（pool 并发治理已就位）
- 执行者类型注册表（make_agent type 映射扩展）
