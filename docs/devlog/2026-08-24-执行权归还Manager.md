# devlog: 执行权归还 Manager + ID 规范化

日期：2026-08-24
方案：docs/plans/2026-08-24-执行权归还Manager与ID规范化方案.md（用户评审通过）

## 做了什么（用户评审 5 点全落地）

1. **执行权归还 Manager**（第 5 点，核心）：CLI 不再持有 agent——
   `manager.run(context_id, input)` 执行入口（pool 取执行者 → chat → release）
2. **ID 规范化**（第 4 点）：context_id = `ctx_`+uuid，agent_id = `agt_`+uuid
   （Agent 加 id 属性——执行者身份，可观测/审计）
3. **RuntimeBundle 删 agent_id**（第 1 点）：冗余（它是 context_id 的重复）+
   加 `get_context()` 方法（数据访问入口归属运行时）
4. **删 CLI 私有 get_context**（第 2 点）：→ runtime.get_context()
5. **get_context 入参改名**（第 3 点）：agent_id → context_id（语义明确）

## 遇到的问题与解决

| 问题 | 解决 |
|---|---|
| CLI/runner 测试 mock 旧接口（agent_id/make_agent） | 全部改 manager.run 形态（runtime.get_context + manager.run） |
| eval FakeAgent 写 self.history 但 runner 读 ctx.messages | FakeAgent.chat 同时写 context.messages |
| test_auto_id 断言 12 位（ctx_ 前缀后 16 位） | 更新断言 |

## 验证

- 541 全绿（+2：manager.run + agent_id）+ ruff 全过
- 手工验收：ctx_/agt_ 前缀 + manager.run 执行 + pool 即用即弃

## 最终架构（执行权归还后）

```
CLI:     manager.run(context_id, input)     ← 不持有 agent！
         runtime.get_context()               ← 数据访问
Manager: run（pool 取执行者→chat→release）+ 控制面（stop/steer/poll）
Pool:    acquire/release（agent 生命周期，即用即弃）
Context: ctx_ 前缀（会话身份）；Agent: agt_ 前缀（执行者身份）
```
