## 遇到的问题与解决

### ① 首跑 1/4——窗口太小压缩过频（链式退化丢事实）
- 现象：window 2000 下每 3-4 轮压缩一次，20 轮触发 10+ 次 → 摘要被反复"再摘要" → 猫名丢失（模型答"没提过养猫"）
- 解决：窗口调 6000（20 轮 ~4000-5000 token 触发 1-2 次，保真与触发平衡）
- 教训：**压缩阈值和对话长度要匹配**——小窗口 + 长对话 = 压缩风暴

### ② sticky/todo 全局态并发污染
- 现象：c-long-2 的 sticky "小Q" 注入并发的 c-long-1，回答串味
- 解决：有 setup 的任务**串行**执行（runner 分 serial/parallel 两组）
- 教训：模块级单例（sticky 存储/todo 存储）在多 agent 并发下必须隔离

### ③ 评测太慢（用户反馈"太久了"）
- 现象：20 轮 × 4 任务 × 真实 LLM ≈ 15+ 分钟（首跑 836s 被杀）
- 解决：轮数砍半（20→10），目标只是"触发 1-2 次压缩"；无 setup 任务并行
- 结果：15+ 分钟 → ~5 分钟（92s/任务平均）

### ④ c-long-3 误杀（评测断言设计缺陷）
- 现象：模型答"任务是什么"时**查询** todo（list）被"todo 未再调用"一刀切误杀
- 解决：forbidden_tools 支持 `tool:action` 粒度（`todo:create` 只禁创建，查询放行）
- 教训：**"不重做"≠"不查询"**——区分重做（create）与合理确认（list）
