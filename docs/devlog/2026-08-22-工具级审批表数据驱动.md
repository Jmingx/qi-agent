# 工具级审批表数据驱动（TOOL_APPROVAL_MAP）

日期：2026-08-22 ｜ 版本：v0.4.26 ｜ 类型：重构（安全判档数据驱动）

## 背景

`security_guard.py` 的判档逻辑存在**硬编码工具名分支**：每加一个需要审批的
新工具，就要来插件里加一个 `if name == "file_delete": ...`。工具多了，插件
代码变成"工具清单 + 逻辑"的混合体——新增审批工具必须改插件代码。

用户提出：在 `security/rules.py`（规则单一来源）加一个 dict，维护
"工具名 → 审批描述"，插件变纯查表——后续加工具只改规则数据，不改插件。

## 设计

### TOOL_APPROVAL_MAP（security/rules.py 新增）

```python
TOOL_APPROVAL_MAP = {
    "file_delete": "删除文件 {path}",
}
```

- 键：工具名；值：审批描述模板（支持 `{参数名}` 占位符，从调用参数填充）
- 命中 = 该工具任何调用都需审批（**无条件审批档**）

### 判档改造（security_guard.py）

硬编码分支 → 查表：

```python
approval_template = TOOL_APPROVAL_MAP.get(name)
if approval_template is not None:
    try:
        desc = approval_template.format(**arguments)
    except (KeyError, IndexError):
        desc = approval_template  # 缺参/占位符不匹配 → 回退模板本身
    return f"NEED_APPROVAL:{desc}"
```

缺参回退模板本身（而非现有实现的尾空格 `删除文件 `）——`{path}` 字面可见
比"不知道删什么"更诚实。

## 边界分析（哪些能进表、哪些不能）

| 判档分支 | 类型 | 能否进表 |
|---|---|---|
| file_delete | 无条件审批（一调就审） | ✅ 迁入（第一个） |
| write_file 覆盖/越界 | 条件审批（文件存在才审/项目外才审） | ❌ 需 `os.path.exists()` 谓词 |
| run_python 沙箱降级 | 条件审批（import 白名单外才审） | ❌ 需代码分析 + 动态描述 |
| shell 三档 | 命令前缀匹配 | ❌ 命令级匹配非工具级 |

**结论**：表只承载"无条件审批"类；条件审批保留逻辑分支（数据表表达不了
谓词——远期 DSH 声明式规则再统合）。这是写进 rules.py 注释的设计边界。
