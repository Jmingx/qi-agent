# 2026-08-17 工具系统架构升级（v0.4.0）

## 做了什么
- 工具系统从"装饰器 + 函数混在 builtin.py"升级为"文件粒度 + register() 显式注册"
- registry.py 重写：ToolEntry dataclass + register() API + check_fn/requires_env/toolset + 初始化日志
- @tool 装饰器保留为 register() 便捷封装（向后兼容）
- builtin.py 拆分为 3 个独立工具文件：get_time.py / read_file.py / shell.py
- 15 个新 register 测试（tests/test_registry.py）+ 初始化日志（用户要求：方便定位学习）

## 怎么做的
1. TDD：写 test_registry.py（10 用例）→ RED → 重写 registry.py → GREEN
2. 迁移工具：builtin.py 拆成 3 个独立文件，各自 register()
3. 删除 builtin.py，更新 __init__.py / cli.py 导入
4. 适配旧测试（test_tools.py 的 builtin 引用、ToolEntry 结构）
5. 全量验证：51 passed + ruff 无错误
6. 手工验收：--debug 对话正常 + 初始化注册日志展示
7. commit → tag v0.4.0

## 遇到的问题与解决
1. **初始化日志**（用户要求）：register() 成功打印 `[工具注册] ✓ name (toolset=..., 参数=[...])`，跳过打印 `⚠ 跳过 name: 原因`——导入即看到工具加载全貌
2. **旧引用断裂**：cli.py / test_tools.py / test_cli_clear.py 多处 `from qi_agent.tools import builtin`——builtin.py 删除后全部改指向新文件
3. **schema name bug（测试抓到）**：register(name="schema_x", handler=tool_x) 时自动生成的 schema function.name 用了函数名 tool_x 而非注册名 schema_x——测试失败暴露。修复：生成后强制 `schema["function"]["name"] = name`
4. **ruff 行太长 ×3**：长 f-string 拆分多行
