# 2026-08-21 资源监控数据源修正（DSH 式混合）

## 做了什么

修复资源监控插件（v0.4.22）的数据源失效：DeepSeek 流式接口基本不返回 usage，
导致 `usage_history` 恒空、状态行从不出现、退出报告误报"本次会话无 LLM 调用"。

## 怎么做的

1. **实测取证**（13+ 次）：curl 原始 SSE 证实 `data: [DONE]` 直接结束无 usage
   字段；`deepseek-v4-flash` / `deepseek-chat` 流式 ×3 全无 usage chunk；
   **非流式 100% 稳定**。排除 SDK/代码问题（提取逻辑与 Hermes 一致），
   是 DeepSeek 服务端对 `stream_options` 支持不到位（~15% 偶发）。
2. **业界对照**：Hermes `chat_completion_helpers.py:2771` 同款写法、无兜底；
   DSH `packages/llm/token-meter`（estimate.ts + usage-projection.ts）——
   双层：真实样本 + `CHARS_PER_TOKEN=4` 估算 + `projectedTokens` 锚点校准。
3. **方案 D（用户批准）**：DSH 式混合——真实样本优先；缺失时
   `estimate_messages` 估算 prompt（4 字符/token + 4 结构开销 + tool_calls 计价）
   + 锚点校准（anchor_prompt + surface 增量）；completion 用内容长度/4；
   估算值 `~` 前缀诚实标注；report 真实/估算拆分。
4. **数据源补齐**：post-llm 事件 payload 加 `messages`（agent.py 一行；
   emit 是 `handler(**data)` 关键字分发，现有监听器 `**_` 兼容）。
5. **TDD**：先写 10 个新测试（估算/锚点校准/混合 report/事件 payload）RED，
   实现后 GREEN；全量 240 测试 + ruff 零错误；手工验收（管道模拟 CLI
   对话）状态行出现、`~` 标记正确、打字机无损。

## 问题与解决

| 问题 | 解决 |
|------|------|
| DeepSeek 流式不返回 usage（服务端行为） | DSH 式混合兜底，零额外成本 |
| 插件需要 messages 但 post-llm 没有 | 事件 payload 加 messages（数据源现造，同 usage 字段教训） |
| emit 关键字分发，加参数可能炸监听器 | 现有监听器 `**_` 兼容；新监听器必须 `**kwargs` |

usage 显示汇总、退出显示汇总）。
