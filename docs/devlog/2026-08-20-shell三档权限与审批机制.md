# 2026-08-20 shell 三档权限 + 审批机制（v0.4.18）

## 做了什么
- **三档权限模型**（Claude Code allow/ask/deny 对齐）：
  - ① 自动放行：只读白名单（现有）
  - ② 需审批：危险命令（rm/shutdown/git push 等前缀）→ 弹窗确认
  - ③ 硬拒绝：红线（敏感路径等）→ security_guard 硬拒（不可审批，业界共识）
- **新事件点 agent/tool-approval**（agent.py ~20 行）：
  - security_guard 返回 NEED_APPROVAL:命令 → agent 发审批事件
  - bail 监听：True=同意 / 其他(含无监听器)=拒绝 → fail-closed（Hermes deny fast 对齐）
- **新插件 approval_gate**：弹窗（y/n/a=总是允许）+ 会话级前缀记忆（决策点 5=命令前缀，
  记第一个 token）+ 非 tty 自动拒绝（评测/管道 fail-closed 双保险）
- **approved 内部参数**：shell schema 手写（只暴露 command）+ execute_tool 调用级
  internal 参数——模型传 approved 被拒（多余参数），agent 审批路径显式放行（防绕过）
- 11 个新测试（200 passed）

## 遇到的问题与解决（本阶段 3 个设计级坑）
1. **internal 放行无法区分调用方**（关键安全缺陷）：最初用全局 _INTERNAL_ARGS 放行
   approved——但模型也能传 approved（同样被放行）→ **绕过漏洞**！
   修复：internal 改为 **execute_tool 调用级参数**——模型路径不传（approved 是
   多余参数被拒），agent 审批路径显式传 internal={"approved"} 才放行
2. **测试没挂判档插件**：审批流程测试只挂了 approval_gate——security_guard（判档）
   缺失 → bail 无监听器 → 工具直接执行（shell 危险关键词拦）。修复：_make_agent
   默认挂 security_guard
3. **前缀记忆实现 bug**：a=总是允许 记了完整命令（"rm /tmp/a"）→ "rm /tmp/b"
   startswith 不匹配 → 记忆失效。修复：记**第一个 token**（用户选择的前缀语义）
