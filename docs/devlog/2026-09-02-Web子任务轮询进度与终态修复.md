# 2026-09-02 Web 子任务轮询进度与终态修复

## 做了什么

- 修复了 Web 界面子任务卡片的展示逻辑：
  - 完成态默认展开全文
  - 结果过长时才折叠
  - `need_more_info`、`stopped` 作为终态直接收口
  - 进度仅保留最近 50 条，卡片内只展示最近 5 条
- 修复了子任务轮询的生命周期问题：
  - 把定时器清理和 meta 清理拆开
  - 允许轮询 meta 从现有 entry 恢复
  - 避免 `scheduleSubTaskPoll()` 误删状态导致轮询链路死亡
- 修复了消息气泡操作按钮样式：
  - 改成右上角悬浮图标按钮
  - 去掉气泡右侧多余留白
- 补了后端通知测试：
  - 证明子上下文事件会向父会话转发为 `item/subtaskProgress`

## 怎么做的

- 前端状态侧：
  - 在 `appModel.ts` 扩展了子任务状态枚举
  - `App.tsx` 把 `entriesRef` 传给 `useSubtask`
  - `useSubtask.ts` 增加 meta 恢复逻辑、终态判断和进度裁剪
- 前端展示侧：
  - `SubTaskCard.tsx` 改成“完成态默认展示结果、长结果再折叠”的规则
  - `MessageBubble.tsx` 改成 SVG 图标按钮
  - `style.css` 重做了悬浮动作区和子任务状态样式
- 后端验证侧：
  - `tests/test_serve_notifications.py` 增加了子任务进度转发回归测试

## 遇到的问题

1. 我在重写 `SubTaskCard.tsx` 和 `useSubtask.ts` 时，前一次补丁里混进了截断字符串，导致 TS 文件语法不完整。
2. `npm run build` 第一次执行时，`vite`/`esbuild` 在当前沙箱里报了 `spawn EPERM`，这不是代码错误，而是进程启动权限问题。

## 怎么解决的

- 先把两个 TS 文件整段重写成干净版本，避免局部修补继续残留语法碎片。
- 后端测试先跑回归，确认功能行为没有偏掉。
- 前端构建再用提升权限重跑一次，确认 `EPERM` 是环境限制，最终 build 通过。

## 验证结果

- `pytest -q tests/test_serve_notifications.py tests/test_gateway.py tests/test_subagent_phase3.py`
  - 结果：`16 passed`
- `npm run build`
  - 先在普通权限下失败于 `spawn EPERM`
  - 重新以提升权限运行后通过
