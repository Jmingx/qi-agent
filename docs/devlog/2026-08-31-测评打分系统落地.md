## 做了什么

Phase 1-3 全部落地（方案验收 1-6）：

1. **Phase 1 指标采集**（evaluation/runner.py + report.py）：
   - result 加 tokens（prompt/completion/total）+ cost（estimate_cost，
     DeepSeek 单价常量：输入 ¥1/1M、输出 ¥2/1M）
   - 报告输出总 token / 总成本
2. **Phase 2 打分系统**（runner.py + tasks.py）：
   - EvalTask 加 expected_rubric 字段；score_task()：规则不过 → 0 分短路
     （不进 judge——省成本）；无 rubric → None；judge 失败 → None 不阻塞；
     分数夹取 0-100；judge 输入只给证据（目标/rubric/最终回答/工具摘要——
     不透传内部信息）
   - 报告输出质量均分 + "未打分 N 个（无 rubric）"（显示不误导）
3. **Phase 3 历史完整保留**（新文件 evaluation/history.py）：
   - eval_runs/ 每 run 全量落盘（tmp+rename 原子写，永不覆盖）
   - runs_index.jsonl 追加式索引（永不重写）
   - trends() / window_regression()（滑动窗口）/ task_trend()（任务归因）
   - run.py 接入 save_run 归档
4. **Rubric 全配**（32 个任务）：tool 6 + error 3 + security 7 + context 3 +
   memory 7 + LONG 4 + SUBAGENT 2——每个任务 1-3 行评分标准
   （正确性/过程/完整性 三维，与任务期望语义对齐）
5. **expected_tools_any 新增**（任一即可语义）：e1 侦察类任务修正——
   expected_tools 是 AND 语义（全部必须调用），改 3 工具反而更难；
   任一语义才匹配"模型用任一侦察工具都算合格"

## 遇到的问题与解决

1. **e1 断言过严**（用户质疑"预期看着是正确的"）：模型侦察（list_dir/
   search_files）后直接答"不存在"是合理行为——先放宽 expected_tools 为
   3 工具（AND 语义反而更难）→ 加 expected_tools_any（任一即可）字段解决
2. **t4 期望过时**（用户质疑）：有专用 list_dir 后锁 shell 过时 → 改 list_dir
3. **报告显示误导**（用户质疑"21 个通过分数是 0"）：实际通过任务 score=None
   （未配 rubric 不打分），0 分的是失败任务（规则短路）——报告加
   "未打分 N 个（无 rubric）"标注，不再误导
4. **run_id 同秒冲突**：时间戳秒级 → 加 uuid4 短码（防覆盖）
5. **误跑一次评测**（输出被截断重跑）：多花 ¥0.24——教训：评测输出别 grep
   截断，直接 tail 完整看
6. **对比跨任务集误导**（-1200%）：快速集 26 vs 子代理 2 对比无意义——
   已知局限，compare 加任务集标识留 TODO
