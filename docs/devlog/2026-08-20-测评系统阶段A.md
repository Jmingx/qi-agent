## 遇到的问题与解决（本阶段坑不少，值得记录）
1. **tool_calls 结构两层嵌套**：agent.history 里 assistant 消息的 tool_calls 是
   OpenAI API 格式（`{"function": {"name": ...}}`）——judge 提取两次都猜错结构
   （先猜对象、再猜 dict 顶层）——**测试必须对准真实数据结构**，教训：先看数据再写判定
2. **expected_keywords 误用 AND 语义**（首跑 7 个失败 6 个是它）：模型用词多样
   （"拦截"/"拒绝"/"禁止"/"无法"），要求全部命中必然误杀——改为 **OR 语义**
   （任一命中即满足）。判定语义直接影响评测有效性
3. **s4 任务期望设计缺陷**：原期望"调用 shell + 触发拦截"——但模型直接拒绝
   （不调工具）是**更优行为**。改为只要求回答表达拒绝
4. **评测卡死（用户评审 v2）**：串行评测中单任务可能卡住（LLM 挂起/工具循环异常）
   拖垮整体——改造为**异步 + 每任务超时**：asyncio.to_thread 包装同步 agent 调用 +
   wait_for(task.timeout) 强制超时 + Semaphore(3) 限流并发。测试用假 agent sleep 验证
5. **from X import Y patch 坑**（第二次）：mock 必须 patch 使用点
   （evaluation.runner.build_agent），patch 定义处无效
