# 2026-08-18 Agent 循环事件化改造（v0.4.8）

## 做了什么
- 新增 `qi_agent/events.py`：轻量事件总线（~100 行），三种分发模式
  - `emit`（广播通知）/ `waterfall`（瀑布改写，返回值回传）/ `bail`（短路决策）
  - 监听器带 priority（大者先执行），同 priority 按注册顺序（稳定排序）
- `agent.py` 插入 **7 个事件点**（依赖注入 `events` 参数，默认空总线零侵入）：
  - `agent/turn-start` / `agent/pre-step`（waterfall 可改写消息）/ `agent/post-llm` /
    `agent/tool-call`（bail 决策，返回非 None 即拦截）/ `agent/tool-result`（含 duration）/
    `agent/final-answer` / `agent/turn-end`
- 新增 `qi_agent/plugins/tool_stats.py`：工具调用统计插件（对应 TODO P1）
- `cli.py` 新增 `--stats` 参数：挂载统计插件，会话结束打印汇总

## 遇到的问题与解决
1. **cli.py 缩进 bug**：统计打印块误缩进进 while 循环内（每轮对话后都打印）。修复：移到循环外（与 while 同级）——测试没抓到是因为 CLI 集成测试没覆盖 --stats 退出路径，靠代码审查发现
2. **ruff 3 个错误**：`lambda l:` 变量名歧义（E741）→ 改名 `item`；tool_stats.py 未用的 `field` 导入（F401）→ 删除；test_event_bus.py 未用的 `pytest` 导入（F401）→ 删除
3. **duration 来源**：方案示例代码里插件自己计时（self._start），实现时改为 agent.py 测量随 tool-result 事件传入——单一职责（agent 提供数据、插件只消费），多工具场景也不会错乱
