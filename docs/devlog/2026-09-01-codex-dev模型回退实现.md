# codex-dev 模型自动回退 + 死锁防护（2026-09-01）

## 做了什么

### 1. codex-dev 模型自动回退（方案：docs/plans/2026-09-01-codex-dev模型回退方案.md）
- **背景**：`~/.codex/config.toml` 模型 `gpt-5.4-mini` 即将弃用（codex 启动提示 GPT-5.6 Luna 替代）；订阅 Plus，5h 限额 69% 剩余 / 周限额 48% 剩余。
- **实现**（原生 Codex CLI 开发，P1-10 流程）：
  - `codex_dev_core.py`：`MODEL_UNAVAILABLE_PATTERNS`（8 条模式）+ `EventParser.model_unavailable` 标记（error / turn.failed 双位置检测）+ `CodexResult.model_unavailable` 字段。
  - `codex_dev.py`：`build_model_chain()`（--model → config.toml 当前模型 → `[notice.model_migrations]` 迁移目标 → 内置兜底 gpt-5.4，去重）+ main 重试循环（quota / model_unavailable 才切换，timeout/error 不重试；链耗尽返回 EXIT_QUOTA=3 / EXIT_CODEX_FAIL=2）+ `state.model_attempts` 记录每次尝试。
  - 测试：+4（模型不可用检测 / 回退链构造去重 / 重试成功路径 / 链耗尽退出码），共 30 passed。

### 2. 验收发现并修复 2 个超范围问题（Codex 修复轮）
- **问题 1**：`run_verify` pytest 被缩成 `pytest tests -q`（漏验 codex-dev 自身测试）→ 恢复全量 `pytest -q`。
- **问题 2**：`build_prompt` 任务锚定被简化 → 恢复原版详细约束（禁止读取 docs/plans、todos、devlog 等）。

### 3. 死锁事故与防护
- **事故**：Codex 自验收时**并发起两个 pytest 进程**，Windows 下两个 pytest 的 tmp 目录清理互相锁死——`PermissionError: [WinError 5] 拒绝访问: ...\tmp\pytest-xxx\basetemp-xxx`（pytest_sessionfinish 清理阶段），进程挂住 ~1 分钟无输出。
- **处理**：kill + 清理孤儿 codex.exe 进程树（8 个进程，防上 session 孤儿改坏仓库的事故重演）。
- **防护**：`build_prompt` 新增「【验收纪律】测试必须顺序执行，禁止同时启动多个 pytest 进程（Windows 下并发 pytest 的 tmp 目录清理会互相锁死，实测 PermissionError 卡死）」——每次转交 Codex 自动携带，从源头防复发。
