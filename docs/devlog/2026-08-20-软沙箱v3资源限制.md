## 遇到的问题与解决（本阶段 4 个硬核坑，全部记录）
1. **Popen 不支持 input= 参数**：那是 run/communicate 的参数——改用 stdin=PIPE +
   communicate(input) 写入（后改为"先写 stdin + drain 线程读输出"）
2. **Popen 轮询死锁（用户报告卡死）**：轮询循环不读管道 → 子进程输出超 64KB
   （管道缓冲）阻塞在 write → 互相等待。**修复：drain 线程持续读 stdout/stderr**，
   轮询期间管道不被填满。测试从 81s 降到 15s
3. **Windows 工作集 trim 陷阱**：分配 400MB 后闲置（sleep/死循环不访问），
   Windows 修剪工作集 → psutil 的 rss（工作集）暴跌到 4MB → 检测不到。
   **测试改为持续增长型炸弹**（while True: x.append(0)）——真实攻击模式
4. **venv launcher 陷阱（最隐蔽）**：Windows venv 的 python.exe 是**重定向启动器**——
   proc.pid 是 launcher（RSS 4MB），真实解释器是它的**子进程**（append 炸弹 469MB）！
   只查主进程永远检测不到。**修复：_tree_rss_mb 递归求和进程树 RSS**
