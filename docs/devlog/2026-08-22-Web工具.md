# 2026-08-22 Web 工具（web_search 双后端 + web_extract）

## 需求

用户方向（2026-08-22）：先丰富工具 → 补 web 搜索工具。背景调研：Hermes
无国内免配置方案（check_web_api_key=False 实测）；用户现状靠 curl 手动搜索
（脆弱试错流程）——工具化价值明确。

## 方案（用户拍板：Bing + DeepSeek 双后端参考）

- **web_search 双后端自动降级**：DeepSeek 官方搜索（web_search_20250305
  server tool，Anthropic 兼容端点 + 复用 DEEPSEEK_API_KEY）主 →
  Bing HTML 爬（www.bing.com + b_algo 解析）兜底——模型无感知
- **web_extract**：网页标题 + 正文提取（html.parser）；**SSRF 防护**
  （拒绝内网/本地地址——云元数据 169.254.169.254 等经典攻击目标）
- 零新依赖：urllib + json + html.parser（标准库）

## 实测发现（踩坑全集）

1. **DeepSeek 官方搜索**：`web_search_20250305` 实测通过（参考 DSH
   web-search-deepseek）——国内直连、复用 key、结构化结果
2. **cn.bing.com 空壳页 / 百度安全验证 / DDG 被墙**——只有 www.bing.com 可用
3. **mock 坑：`with urlopen() as resp` 时 resp 是 `__enter__.return_value`**
   ——不设置 `__enter__.return_value = resp` 会拿到未配置的 MagicMock
4. **Bing 块内嵌套 li**：只数 b_algo 的 li 会提前截断——所有 li 深度计数
5. **Bing 链接全是 /ck/a 跳转包装**：u 参数 = a1 前缀 + base64url 编码的
   真实 URL——`_decode_bing_url` 还原（否则 url 空 → 结果块被丢弃）

## 验证

- 全量 **289 passed + ruff 零错误**（+17：web_search 10 + web_extract 7，
  全部 mock 网络层不碰真实网络）
- 手工验收：真实 DeepSeek 搜索（量子计算 → 新华网/IBM 结构化结果）✓
  Bing 兜底（禁用 key → python.org/python.jp 真实链接还原）✓
  web_extract（Python 官方文档提取 + SSRF 拦截 127.0.0.1）✓

## 遗留

- SSRF 局限：域名解析到内网（DNS rebinding）需解析后检查——当前只查
  host 文本/IP 字面（诚实记录，避免工具被利用做内网扫描）
- Bing 兜底 HTML 结构变化风险（仅兜底缓解）；DeepSeek 搜索耗 token
  （~500 max_tokens/次，成本可忽略）
