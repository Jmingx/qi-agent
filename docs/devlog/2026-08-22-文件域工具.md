# 2026-08-22 文件域工具（list_dir + search_files + file_delete）

## 需求

继续丰富工具（用户要求"工具边界要清晰"）——补文件域空缺：read_file/write_file
有读有写，但缺"列目录/搜索定位/删除"——模型只能用 shell 的 dir/findstr
（文本解析脆弱 + 职责混在 shell 里）。

## 工具边界设计（用户核心关注）

```
读内容    → read_file      | 写内容  → write_file
列目录    → list_dir       | 搜文件  → search_files
删文件    → file_delete    | 任意命令 → shell
```

三原则：①正交性（能力不重叠）②安全主线（只读放行 / 写删审批）③描述交叉
引用（每个工具说清"什么时候用我、什么时候用别的"）。

## 实现

1. **list_dir(path=".")**：结构化列目录（名称/类型/大小）——只读放行；
   敏感目录（.git/.env/__pycache__）不列出（防模型看到敏感路径）
2. **search_files(pattern, path, file_glob, limit)**：纯 Python 内容搜索
   （os.walk + 正则，**不依赖 rg 二进制**——跨平台零新依赖）——返回
   文件:行号:匹配行（截断）；跳过隐藏/敏感目录与二进制文件
3. **file_delete(path, approved=False)**：删除文件——**破坏性 → 审批档**
   （security_guard 判 NEED_APPROVAL:删除文件 → 弹窗）+ **敏感路径红线**
   （.env/.git 等 approved 也拒——审批管不到红线，对齐 write_file 四档）；
   只删文件不删目录（边界）；approved 内部参数防绕过（v0.4.18 机制）

## 验证

- 全量 **304 passed + ruff 零错误**（+15：list_dir 4 / search_files 5 /
  file_delete 6，含红线/防绕过/目录拒绝）
- 手工验收：list_dir 真实目录结构化 ✓ search_files 真实搜索（文件:行号）✓
  file_delete 审批判档 + .env 红线 ✓
- 注册表：**10 个工具** ✓

## 遗留

- search_files 跳过 .lock/.pdf 等扩展（已知取舍）；超大目录搜索慢（无
  并发/索引——rg 级性能是 P2）
- file_delete 无回收站（直接 os.remove——误删需 git 恢复；回收站是 P2）
