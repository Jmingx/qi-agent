## 怎么做的

### 1. 修 ServeTransport 的 attach 语义

原来的实现把 `context.id` 当作“是否已经 attach 过”的依据。
这个做法在 session resume / 新对象替换旧对象时会出错，因为“业务 session id”不等于“Python 对象实例”。

我改成了按对象身份去重：

- `self._attached_contexts: set[int]`
- 用 `id(context)` 记录

这样同一个对象不会重复挂监听器，但新对象即使 session id 一样，也会正常 attach。

### 2. 补回归测试

新增测试模拟了这种场景：

- 两个不同的 `AgentContext` 对象
- 但它们的 `session_id` 一样
- 两个对象都发出 `agent/tool-call`

期望是两次都收到转发通知。

这个测试能直接挡住“同 id 新对象 attach 被误跳过”这个回归。

## 遇到的问题

### 问题 1：测试变量名误改

我在改测试时把几个测试里的 `transport` / `_transport` 命名弄乱了，导致 ruff 和 pytest 先后报错。

处理方式：

- 前两个需要显式调用 `_attach_context` 的测试保留 `transport`
- 新增的回归测试只需要实例化对象，不需要引用，改成 `_transport`

### 问题 2：`uv` 默认缓存目录权限失败

直接跑 `uv run pytest` 时，`uv` 试图写入用户目录下的 cache，当前环境报了权限错误。

处理方式：

- 把 `UV_CACHE_DIR` 指到 `C:\Users\xie\AppData\Local\Temp\uv-cache`
- 再运行测试和 lint

### 问题 3：全量 pytest 在这个环境里还有大量既有失败

全量 `pytest -q` 跑完后，出现了不少和本次修复无关的失败，主要是：

- 临时目录清理权限问题
- 其他工具类测试的既有断言失败

这些不属于这次 Web 四问题修复的范围，所以我没有在这里扩成另一个大修。
