## 做了什么

1. **storage 独立包**（qi_agent/storage/——基础设施，用户拍板独立）：
   - base.py：存储抽象基类（业务只依赖抽象，换实现=换类）
   - sqlite_store.py：SQLite 实现（stdlib 零依赖）
   - __init__.py：get_storage() 单例（配置驱动）

2. **SQLite 双模型**（用户拍板快照 + append 日志）：
   - 快照 = sessions 表状态字段 + snapshot_at 时间点（O(1) UPDATE）
   - 日志 = messages 表逐条追加（INSERT 天然 append）
   - 恢复 = 快照状态 + 增量重放（Event Sourcing 标准）

3. **会话持久化接入**（manager.run 完成后）：
   - persist=True + storage 注入 → write-behind 异步落盘（后台线程）
   - 增量 append（_persisted_count 防重复）
   - build_runtime(persist=True) 默认；评测 persist=False（任务隔离）

4. **CLI 会话命令**：
   - /resume（列表 + 恢复指定会话——同 id 新 context + 数据恢复）
   - /new（开新会话——同一运行时换 context）
   - 启动崩溃恢复提示（发现历史会话提示 /resume）

5. **记忆系统**（§ 分隔——用户拍板对齐 Hermes，不用 Markdown 解析）：
   - memory_store.py：MEMORY.md（长期知识）+ USER.md（用户画像）
     **§ 条目分隔**（Hermes MemoryStore 同款——raw.split("§")，
     零 Markdown 解析）+ 去重 + 字符上限（2200/1375）
   - memory 插件（pre-step 瀑布注入 system 副本——不污染原消息）
   - /remember → sticky（会话内）+ MEMORY.md（跨会话）
   - /memory 查看跨会话记忆
   - SQLite memory 表移除（记忆不该在数据库——业界实证）
