# 2026-08-22 LLM 调用超时（根治评测线程残留）

## 需求

TODO P1（docs/todos/tool-calling.md）：LLMClient 加请求超时——评测 `wait_for`
超时无法终止线程（asyncio.run join 卡 300s RuntimeWarning），根治 = LLM 调用
自带 timeout，挂起调用最多 timeout 秒返回。

## 实现（用户拍板"直接搞"，3 处小改动）

1. `LLMClient.__init__` 加 `timeout: float = 60.0` → `OpenAI(..., timeout=timeout)`
2. `chat` / `chat_stream` 的 create 调用**显式传** `timeout=self.timeout`
   （防客户端默认漂移——SDK 客户端级超时可能被后续代码改）
3. 配套验证：评测 runner 的异常兜底**早已存在**（`_run_task` 的 except Exception
   → 单任务失败不中断整体）——新测试确认此行为（非假通过：先确认了
   TimeoutError 与 asyncio.TimeoutError 在 3.11+ 同类的坑，实际走了
   except Exception 分支）

## 完整闭环

```
LLM 挂起 → SDK timeout 60s 抛 APITimeoutError → 线程必然结束（不再残留）
  → CLI: cli.py except Exception → "API 失败不崩溃，继续对话"
  → 评测: _run_task except Exception → 单任务失败不中断整体
```
