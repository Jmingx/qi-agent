## 先理解：为什么需要测评（以及测什么）

**没有测评的 agent 开发 = 盲改**——改了工具系统，怎么知道对话质量提升了还是退化了？

### 测评的三个维度

| 维度 | 测什么 | 类比 |
|------|--------|------|
| **单元测试**（已有） | 每个函数/模块行为正确 | 零件质检 |
| **集成测试**（已有） | 工具调用链/Agent loop 正确 | 组装测试 |
| **任务级评测**（本节目标） | **agent 能否完成真实任务**（成功率） | 整车路测 |

**关键认知：单测通过 ≠ agent 好用。** 单测验证"代码对不对"，评测验证"任务完没完成"——后者才是 agent 价值的核心。

### 业界评测方法论（三种主流）

| 方法 | 原理 | 适用 |
|------|------|------|
| **任务成功率** | 预定义任务 + 预期结果，跑 N 次统计成功率 | 有明确答案的任务（计算/查时间/读文件） |
| **LLM-as-judge** | 用强 LLM 评判 agent 输出质量（打分/对比） | 开放性问题（回答质量/风格） |
| **人工评测** | 人打分 | 终极标准（贵、慢） |

## 备注（演进思路）

- **先 v1 后升级**：精确/包含匹配（简单可靠）→ LLM-as-judge（强大但贵、慢）→ 人工（终极）
- **测评是"回归保险"**：最大的价值不是第一次跑出成功率，而是**每次改动后对比**——成功率下降自动发现退化
- **对抗性评测最实用**：agent 变强过程中最怕"变强的同时变危险"，安全任务集是必选项（配合审批机制 TODO）
- **与工具 TODO 联动**：path_security/审批做完后，对抗性任务集才有意义（安全防线测什么）
- **Hermes 对照**：Hermes 有 2135 个测试文件，但那是单测/集成；任务级评测业界多用 benchmark（如 GAIA、HumanEval、SWE-bench）——我们自建小评测集是理解这套方法论的最佳路径
