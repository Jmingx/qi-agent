## 1. 目标

run_python 子进程的工作目录从**项目根目录**改为**临时目录**（tempfile.mkdtemp）：
沙箱代码的相对路径操作全部落在临时目录，**物理上碰不到项目文件**。

## 2. 设计原理（导师讲解）

### 2.1 现状风险：沙箱的工作环境 = 项目根

```
现状：run_python 子进程 cwd = 项目根（继承父进程）
→ 沙箱代码的相对路径操作全部落在项目目录里
```

**真实风险场景**：
1. **v1 预检拦不住拼接**：`("op"+"en")('probe.txt','w')`——v1 扫描无 "open(" 特征，
   legacy 模式（完整 Python）会真执行 → 在项目根写文件
2. **未来扩展**：配置放行更多内建/模块，或守卫配置失误——有文件能力时 cwd 在项目根 = 能碰项目文件
3. **信息纵深**：即使 v2 现在无文件能力，cwd 隔离是"物理碰不到"的最后防线

**类比**：把访客安排在**独立接待室**（临时目录），而不是**书房**（项目根）——就算他带了
笔（文件能力），也只能在接待室的纸上写。

### 2.2 为什么现在做（v2 已无文件能力还要隔离？）

- **legacy 模式是真实风险路径**：v1 预检 + 完整 Python——拼接绕过可写文件（v1 拦不住拼接）
- **纵深防御哲学**（对齐 env 双重过滤）：隔离层独立工作，即使上层（静态扫描/受限环境）
  全部失效，沙箱代码也物理碰不到项目文件
- **未来准备**：阶段 B 若放行更多能力，隔离已就位

## 3. 设计（~10 行改动）

### 3.1 run_python.py 改造

```python
def run_python(code: str) -> str:
    # 1. v1 快速预检（不变）
    blocked = _check_code(code)
    if blocked:
        return f"[安全拦截] {blocked}"
    # 2+3+4+5. 临时工作目录 + 子进程执行 + 时间锁 + 安全锁
    try:
        with tempfile.TemporaryDirectory() as tmpdir:  # 隔离锁升级：临时工作目录
            ...subprocess.run(cmd, cwd=tmpdir, env=_build_safe_env(), ...)
    except subprocess.TimeoutExpired:
        ...
```

- `TemporaryDirectory()`：系统临时目录（%TEMP%）创建，with 退出自动清理
  （成功/超时/异常均清理——项目零污染）
- `cwd=tmpdir`：子进程相对路径操作全部发生在临时目录
- 其余不变：env 双重过滤/编码/超时/截断

### 3.2 与沙箱模式的关系

| 模式 | 隔离价值 |
|------|---------|
| restricted（v2） | **纵深**：守卫失误时的最后防线（当前 v2 无文件能力，隔离是保险） |
| legacy（v1 预检+完整 Python） | **真实防线**：拼接绕过写文件 → 只能写临时目录 |

## 8. 风险与说明

- **TemporaryDirectory 清理失败场景**：Windows 上目录被占用时清理报错（子进程残留）——
  run_python 子进程 10s 超时已 kill，无残留；若有异常用 try/finally 兜底（实现时保证）
- **性能**：临时目录创建/销毁 ~ms 级，可忽略
- **legacy 模式的定位**：隔离让 legacy 的风险从"能碰项目文件"降为"只能碰临时目录"——
  legacy 仍是降级模式（TODO 沙箱降级需用户审核），隔离是缓解不是消除
- **不做的**：目录内容预置（给沙箱放输入文件——阶段 B）；Windows 原生隔离（P2）
