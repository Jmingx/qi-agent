## 1. 目标

把插件装配从"cli.py 手动 `import + 实例化 + install`"升级为**"注册表自注册 + 配置文件管理"**：

- 插件文件自己调用 `register_plugin()` 登记（对齐工具系统 register 哲学）
- 配置文件声明哪些插件启用（用户决策，不进代码）
- cli.py 装配逻辑收敛为一行，**以后加插件永不再改 cli.py**

## 2. 设计原理（导师讲解）

### 2.1 三种装配模式回顾（业界）

| 模式 | 加插件的动作 | 代表 |
|------|-------------|------|
| 配置驱动 | 改配置文件 | DSH cordis.yml、Django INSTALLED_APPS |
| 目录扫描 | 丢文件进目录 | pytest conftest、Spring |
| 注册表自注册 | 写文件 + 登记 + import | **工具系统先例**、Java ServiceLoader |

**本项目选择：注册表自注册（登记"存在"）+ 配置驱动（决定"启用"）** —— 用户决策，两模式互补：
注册表让插件"能被发现"，配置让用户"能控制"，互不干扰。

### 2.2 默认开关的优先级规则（关键设计）

```
配置显式写了 → 配置说了算
配置没写     → 回落插件自声明默认值（default_enabled）
配置文件不存在 → 全部用默认值（零配置也能跑）
```

这条规则让：老配置兼容新插件（没登记的插件按默认开）、新项目零配置可跑（不需要先写配置文件）。

## 3. 设计

### 3.1 插件注册表（新文件 qi_agent/plugins/registry.py，~50 行）

```python
"""插件注册表：插件自注册 + 按配置统一装配（对齐 tools/registry.py 哲学）。"""

from dataclasses import dataclass
from typing import Callable

from qi_agent.events import EventBus

# 注册表：插件名 -> 插件元信息（对齐 _TOOL_REGISTRY 模式）
_PLUGIN_REGISTRY: dict[str, PluginEntry] = {}


@dataclass
class PluginEntry:
    """注册表中的一个插件条目。"""
    name: str                    # 插件名（唯一）
    factory: Callable            # 工厂：无参构造插件实例（如 ToolStatsPlugin）
    description: str = ""        # 一句话描述
    default_enabled: bool = True # 默认开关（配置文件未覆盖时使用）


def register_plugin(
    name: str,
    factory: Callable,
    description: str = "",
    default_enabled: bool = True,
) -> None:
    """插件自注册入口。

    Args:
        name: 插件名（唯一，重复注册抛错）
        factory: 无参工厂函数/类（实例化插件对象）
        description: 一句话描述
        default_enabled: 默认是否启用（配置文件可覆盖）

    Raises:
        ValueError: 插件名重复
    """
    if name in _PLUGIN_REGISTRY:
        raise ValueError(f"插件 '{name}' 已存在（重复注册）")
    _PLUGIN_REGISTRY[name] = PluginEntry(
        name=name, factory=factory,
        description=description, default_enabled=default_enabled,
    )


def load_plugins(bus: EventBus, config: dict | None = None) -> list:
    """按配置装配所有启用的插件：实例化 + install(bus)。

    Args:
        bus: 目标事件总线（agent.events）
        config: 插件配置 dict（插件名 -> {"enabled": bool}）；None=全用默认

    Returns:
        已安装的插件实例列表（测试/汇报用）
    """
    config = config or {}
    installed: list = []
    for name, entry in _PLUGIN_REGISTRY.items():
        enabled = config.get(name, {}).get("enabled", entry.default_enabled)
        if not enabled:
            continue
        plugin = entry.factory()
        plugin.install(bus)  # 统一入口约定（v0.4.8 确立）
        installed.append(plugin)
    return installed


def get_plugin_names() -> list[str]:
    """返回全部已注册插件名（调试/日志用）。"""
    return list(_PLUGIN_REGISTRY.keys())
```

### 3.2 配置加载（新文件 qi_agent/plugins/config.py，~30 行）

**格式决策：TOML（Python 3.11 内置 tomllib 只读解析，零新依赖）**
> 对比：YAML 需新增 pyyaml 依赖——为 30 行功能加依赖不值；TOML 标准库即可，且 pyproject.toml 本身就是 TOML，用户熟悉。

```python
"""插件配置加载：读取 plugins.toml（可选），解析启用状态。

优先级（2.2 节）：
配置文件显式声明 → 配置优先
配置文件缺失/未声明 → 插件 default_enabled
"""

import tomllib
from pathlib import Path

DEFAULT_CONFIG_PATH = Path("plugins.toml")  # 项目根，可选存在


def load_plugin_config(path: Path = DEFAULT_CONFIG_PATH) -> dict:
    """读取插件配置。文件不存在时返回空 dict（全用插件默认开关）。

    plugins.toml 格式：
        [tool_stats]
        enabled = true

        [security_guard]   # 将来
        enabled = false
    """
    if not path.exists():
        return {}
    with open(path, "rb") as f:  # tomllib 要求二进制模式
        data = tomllib.load(f)
    return data  # {插件名: {"enabled": bool}}
```

## 8. 风险与说明

- **行为变化**：tool_stats 的默认开关从"无 --stats 不装"变为"default_enabled=False 不装"——语义等价，但 --stats 的处置影响 CLI 兼容（决策点 3）
- **tomllib 只读**：插件配置无写入需求（用户手改文件），只读足够；将来阶段 4 配置化可并入 config.yaml 体系
- **YAGNI 红线**：不做插件依赖解析/热加载/卸载（档位 C 再说）；factory 无参（插件如需配置参数，将来升级 factory 签名）
- **配置文件不进 git**：插件开关是用户偏好（同 .env 逻辑），示例文件进 git 作模板
