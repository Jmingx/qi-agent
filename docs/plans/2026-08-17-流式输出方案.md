## 1. 目标

让 CLI 的模型输出变为**流式**（打字机效果）：模型边生成边显示，而不是等完整响应一次性打印。这是 agent 使用体验的质变——等待时能看到"它正在思考"。

**本次不做的事（YAGNI）：** 不做流式渲染美化（markdown 语法高亮等）、不做中断恢复（Ctrl+C 已处理）、不改工具调用轮次为流式（工具调用是结构化 JSON，流式无意义）。

## 2. 技术原理（导师讲解：SSE 与 stream=True）

### 2.1 底层机制：SSE（Server-Sent Events）

普通对话是一次性等完整响应；流式是服务器把响应拆成小数据块，通过 HTTP 长连接**逐块推送**，客户端每收到一块立即显示。

```
普通: [等待 3 秒] → 一次性打印完整回答
流式: 你(0.1s) → 你好！(0.3s) → 你好！很高兴(0.6s) → ... 打字机效果
```

### 2.2 API 差异：stream=True 返回迭代器

```python
# 普通：一次拿完整响应
response = client.chat.completions.create(model=..., messages=...)
text = response.choices[0].message.content

# 流式：返回迭代器，逐块取增量（delta）
stream = client.chat.completions.create(model=..., messages=..., stream=True)
for chunk in stream:
    delta = chunk.choices[0].delta.content
    if delta:
        print(delta, end="", flush=True)   # flush=True 立即输出
```

**核心：`stream=True` 时拿到的是迭代器，每块含 `delta.content`（一小片文本），累积即完整回答。**

### 2.3 流式 + 工具调用的关键设计

**只有"模型直接给文本"的最终回答轮次才流式；工具调用轮次不流式**（要等完整 tool_calls 结构返回才能执行工具）。

```
用户: 现在几点了？
模型: [普通] tool_calls: get_time   → 执行工具 → 拿到结果
模型: [流式] 现在是 2026-08-17 ...    ← 只有这轮流式
```

## 3. 架构设计

```
llm.py 提供流式能力（chat_stream）
  ↑
agent.py 决定何时用流式（最终回答轮次）
  ↑
cli.py 决定如何显示（flush 打印）
```

**分层不变：llm 提供能力，agent 做决策，cli 管显示。**

### 3.1 llm.py：新增 chat_stream 方法

```python
class LLMClient:
    def chat_stream(self, messages: list[dict],
                    tools: list[dict] | None = None):
        """流式调用：逐块产出文本增量（生成器）。

        返回一个生成器，每次 yield 一小段文本；
        仅用于"纯文本回答"轮次（工具调用轮次用 chat()）。
        """
        kwargs = {"model": self.model, "messages": messages,
                  "temperature": self.temperature, "stream": True}
        if tools:
            kwargs["tools"] = tools

        stream = self._client.chat.completions.create(**kwargs)
        for chunk in stream:
            delta = chunk.choices[0].delta.content
            if delta:
                yield delta
```

**设计说明：**
- 返回**生成器**（yield），调用方逐块消费
- 不处理工具调用（工具轮次走 chat()）
- 不打印、不渲染——只产出文本增量（llm 只管能力）

### 3.2 agent.py：最终回答轮次改用流式

```python
def chat(self, user_input: str, stream_callback=None) -> str:
    """支持流式：stream_callback 非空时，最终回答逐块回调。"""
    self.messages.append({"role": "user", "content": user_input})
    if self.logger:
        self.logger.log_user_input(user_input)

    for _ in range(self.max_turns):
        result = self.client.chat(self.messages, tools=get_tool_schemas())
        if self.logger:
            self.logger.log_request(self.messages, get_tool_schemas())
            self.logger.log_response(result)

        if result.tool_calls:
            ...（工具调用轮次，逻辑不变）
        else:
            # 最终回答：如果调用方想要流式，改用 chat_stream
            if stream_callback is not None:
                collected = []
                for delta in self.client.chat_stream(self.messages):
                    stream_callback(delta)          # 逐块回调
                    collected.append(delta)
                full = "".join(collected)
                self.messages.append({"role": "assistant", "content": full})
                return full
            else:
                self.messages.append(result.assistant_message)
                return result.content or ""
```

**设计说明：**
- **向后兼容**：`stream_callback=None` 时行为与现在完全一致（普通模式）
- 调用方传 `stream_callback` 才走流式分支
- 流式时历史消息用**累积的完整文本**（不能存增量片段！历史必须完整）

### 3.3 cli.py：传流式回调，flush 打印

```python
def main(argv=None):
    ...
    while True:
        ...
        try:
            reply = agent.chat(
                user_input,
                stream_callback=lambda delta: print(delta, end="", flush=True),
            )
            print()   # 流式结束后换行
            print(f"agent> 完成")
        ...
```

**设计说明：**
- `lambda delta: print(delta, end="", flush=True)` 实现打字机
- `flush=True` 是流式关键——强制立即输出到终端（否则被缓冲，等全部结束才显示，流式就白做了）

## 8. 风险与说明

- **流式 + 调试日志**：--debug 模式 log_response 打印的是普通 chat 的完整响应；流式轮次没有完整 ChatResult——日志会缺失流式轮次的 RESP 块（可接受，或后续补 stream 日志）
- **DeepSeek 流式兼容**：deepseek-v4-flash 支持 OpenAI 兼容流式（SSE），如遇问题降级方案是自动回退普通模式
- **历史完整性**：流式分支必须用累积完整文本存历史——这是最容易踩的坑
