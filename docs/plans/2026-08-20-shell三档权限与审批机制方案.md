## 1. 目标

shell 权限从"两档"（只读白名单放行 / 其他拒绝）升级为**三档决策**：

```
① 自动放行（只读白名单）      → 直接执行（现状不变）
② 需审批（危险但可审）         → 弹窗问用户 → 同意才执行（新增）
③ 硬拒绝（红线：读 .env 等）   → 直接拒绝（现状 security_guard 已有）
```

**核心价值**：`shutdown`、`git push`、`rm` 这类"危险但用户可能确实想执行"的命令，
从"一刀切拒绝"变为"**给用户选择权**"——弹窗确认后执行。

## 2. 设计原理（导师讲解）

### 2.1 架构：事件点 + 审批插件（用户方案，评审确认）

```
模型调 shell("git push")
  → agent/tool-call bail：security_guard（决策插件）
      ① 白名单命令 → None（放行）
      ② 危险命令   → 返回 "NEED_APPROVAL:<命令>"（新档）
      ③ 红线命令   → "[安全拦截]"（现有）
  → agent 循环识别 NEED_APPROVAL 前缀（引擎只认标记，不管审批细节）
       → 发新事件点 agent/tool-approval（bail）
       → approval_gate 插件（交互插件）：弹窗 → True(同意)/False(拒绝)
       → 同意：注入 approved 内部参数 → 执行工具
       → 拒绝：回填 "[审批拒绝] 用户不同意执行: <命令>"
       → 无监听器（fail-closed）：None → 默认拒绝
```

**分层**：工具管执行（shell 只管跑）· 插件管决策（security_guard 判档）·
插件管交互（approval_gate 弹窗）· 引擎管转发（agent 只发事件）。

### 2.2 三档模型与业界对齐（评审对照结论）

| 本方案 | Claude Code | Hermes | 说明 |
|--------|------------|--------|------|
| ① 自动放行 | allow | 检测通过 | 只读白名单 |
| ② 需审批 | **ask** | 审批回调 | 弹窗确认（用户选择权） |
| ③ 硬拒绝 | **deny** | hardline | **红线不可审批**（业界共识） |
| 无审批环境 | print 跳过 | **fail-closed**（deny fast） | 默认拒绝（业界共识） |
| 会话记忆 | 会话规则 | per-session allowlist | 同意过的命令不再问 |

DSH 无交互审批（声明式 policy）——不参考其交互，但**命令前缀匹配**（Claude Code
`Bash(git *)` 模式）吸收为我们的白名单/危险清单匹配方式。

### 2.3 关键安全设计：approved 参数不进模型 schema

```
shell 工具的 schema 里【没有】approved 参数（模型看不到、传不了）
审批同意后由 agent 内部注入 arguments["approved"]=True
→ 模型无法用 approved=True 绕过白名单（安全底线：工具层兜底保持）
→ 无插件环境（评测）：非白名单命令永远拒绝（工具层兜底不变）
```

**工具层兜底保持**：shell 工具仍内置白名单检查——`非白名单 && 非 approved → 拒绝`。
插件体系挂了不影响工具自身安全（"安全底线硬编码"哲学）。

## 3. 设计

### 3.1 新事件点：agent/tool-approval（agent.py ~15 行）

```python
# agent.py 工具执行链（tool-call bail 之后）：
decision = self.events.bail("agent/tool-call", name=name, arguments=arguments, ...)
if isinstance(decision, str) and decision.startswith("NEED_APPROVAL:"):
    command = decision.split(":", 1)[1]
    # 审批事件（bail）：插件返回 True=同意 / False=拒绝 / None=无监听器
    approved = self.events.bail(
        "agent/tool-approval", name=name, arguments=arguments, command=command
    )
    if approved is True:
        arguments = {**arguments, "approved": True}  # 内部注入（模型不可见）
        decision = None  # 放行执行
    else:
        decision = f"[审批拒绝] 用户不同意执行: {command}"
```

**fail-closed**：无监听器 → bail 返回 None → `approved is True` 不成立 → 拒绝 ✅
（与 Hermes "deny fast" 一致）。

### 3.2 security_guard 三档化（决策插件升级）

```python
# 新增：需审批档（命令前缀匹配——Claude Code 借鉴）
_APPROVAL_PREFIXES = (
    "rm ", "rmdir ", "shutdown", "git push", "git reset --hard",
    "git checkout --", "del ", "rd ", "format ", "taskkill",
    "net user", "reg delete",
)

# _on_tool_call 升级（shell 命令判定）：
def _classify_command(self, command: str) -> str | None:
    """三档判定：None=放行 / NEED_APPROVAL:cmd / [安全拦截]。"""
    # ③ 红线优先：危险关键词（现有）+ 敏感路径（现有）→ 硬拒
    blocked = self._check_dangerous(command)
    if blocked:
        return f"[安全拦截] {blocked}"
    # ② 需审批：危险清单前缀匹配（token 化后小写）
    if any(command.lower().lstrip().startswith(p) for p in _APPROVAL_PREFIXES):
        return f"NEED_APPROVAL:{command}"
    # ① 白名单：只读命令放行（现有 shell 白名单逻辑上移？见 3.4）
    return None
```

**红线不进审批**：③ 在 ② 之前判定——`.env` 读取永远硬拒，不提供"用户同意"路径。

### 3.3 新插件：approval_gate（交互插件）

```python
# qi_agent/plugins/approval_gate.py（~60 行）
class ApprovalGatePlugin:
    """审批交互插件：弹窗确认 + 会话级记忆。

    - 有交互（stdin 是 tty）：弹窗 input("执行命令 'x'？(y/n/a=总是允许) ")
    - 无交互（评测/管道）：自动拒绝（返回 False）
    - 会话级 allowlist：a=总是允许 → 本会话同前缀命令不再问
    """

    def __init__(self, config: dict | None = None):
        self._approved_prefixes: list[str] = []

    def _on_tool_approval(self, command: str, **_) -> bool | None:
        """监听 agent/tool-approval：True=同意 / False=拒绝 / None=无意见。"""
        # 会话记忆：同前缀已允许 → 直接同意
        if any(command.startswith(p) for p in self._approved_prefixes):
            return True
        if not sys.stdin.isatty():  # 无交互环境（评测/管道）→ fail-closed
            return False
        answer = input(f"[审批] 执行命令 '{command}'？(y/n/a=总是允许) ").strip().lower()
        if answer in ("y", "a"):
            if answer == "a":
                self._approved_prefixes.append(command)  # 会话记忆
            return True
        return False

register_plugin("approval_gate", ApprovalGatePlugin, default_enabled=True)
```

**default_enabled=True**：CLI 是主场景（要交互）；评测环境**不加载审批插件**
（plugins.toml 控制或 build_agent 排除）→ 无监听器 → fail-closed 拒绝（无需改评测逻辑）。

### 3.5 评测适配

- 评测 runner 用 build_agent()（真实形态）——plugins.toml 控制 approval_gate：
  - **默认关闭**（评测场景 plugins.toml `[approval_gate] enabled = false`）
  - 或 approval_gate 检测非 tty 自动拒绝（双保险）
- 评测任务 s4（危险删除）期望不变：fail-closed 拒绝 ✅

## 8. 风险与说明

- **模型绕过 approved**：schema 不暴露 + 参数校验拒绝 → 模型无法传（测试覆盖）
- **弹窗阻塞**：审批等待用户输入（同步 input）——agent 循环暂停，符合"用户选择权"
  语义；评测/无交互环境 fail-closed 不阻塞
- **会话记忆边界**：a=总是允许 记的是**命令前缀**（不是全命令）——`rm /tmp/a` 允许后
  `rm /etc/passwd` 也放行？**风险**！前缀记忆只用于"完全一致的命令"更安全——
  **决策点 5**：前缀 vs 精确匹配（方案倾向：精确命令记忆，Claude Code 是规则化
  允许（用户显式写 allow 规则），我们是会话内临时允许——精确更安全）
- **红线优先级**：③ 先于 ② —— 危险命令里的红线（`rm -rf /` + 读 .env）永远硬拒
- **不做的**：permission modes（YOLO 模式，YAGNI）；永久 allowlist 持久化
  （config.yaml，阶段 B）；智能审批（Hermes Smart approval，阶段 B）
- **工具层兜底语义变化**：shell 的"白名单外拒绝"升级为"白名单外 + 非 approved 拒绝"——
  无插件时行为不变（安全底线保持）
