## 现状（调研实况）

| # | 位置 | 规则 | 用途 |
|---|---|---|---|
| 1 | `shell.py:_DANGEROUS_KEYWORDS` | format/mkfs/dd/shutdown/reboot + 组合语法(> >> \| && ;) | 工具层硬拒（兜底） |
| 2 | `security_guard.py:_HARDLINE_PREFIXES` | format/mkfs/dd/shutdown/reboot | 插件层红线（不可审批） |
| 3 | `security_guard.py:_APPROVAL_PREFIXES` | git push/rm/del/curl/wget/python/py/pip/npm/taskkill… | 审批档 |
| 4 | `security_guard.py:_CODE_EXEC_PREFIXES` | python/py/node/npm/pip/npx | 沙箱升级档（v0.4.23） |
| 5 | `security_guard.py:_RESTRICTED_MODULES` | math/random/json/… | run_python 降级判据 |
| 6 | `run_python.py:_FORBIDDEN_PATTERNS` | import os/eval(/open(… | v1 静态扫描（代码模式） |
| 7 | plugins.toml 黑名单（用户配置） | 运行时注入 | 用户自定义拦截 |

**重复实例**：①format/mkfs/dd/shutdown/reboot 在 1 和 2 双份（曾不同步——
v0.4.21 加 _HARDLINE_PREFIXES 时差点漏）；②python/py/pip/npm 在 3 和 4 双份
（4 先判定，3 里的实际死代码但仍在维护）。

## 设计（方案 B：共享规则模块——数据单一来源，分层检测保留）

新增 `qi_agent/security_rules.py`（纯数据模块，零依赖）：

```python
# 红线段：删库跑路 + 重启关机（任何层不可执行，审批也管不到）
HARDLINE_PREFIXES = ("format", "mkfs", "dd ", "shutdown", "reboot")
# 组合语法（shell 专属：前缀检测盲区兜底，echo a | rm 场景）
SHELL_COMBINATOR_SYNTAX = (">", ">>", "|", "&&", ";")
# 审批档：危险但可审（用户批准后执行）
APPROVAL_PREFIXES = ("git ", "rm ", "del ", "curl ", "wget ", "python",
                     "py ", "pip", "npm", "npx", "taskkill", ...)
# 代码执行档：沙箱升级（完整权限弹窗明示，v0.4.23）
CODE_EXEC_PREFIXES = ("python", "py ", "node", "npm", "pip", "npx")
```

- `shell.py`：`from qi_agent.security_rules import HARDLINE_PREFIXES, SHELL_COMBINATOR_SYNTAX`
  ——工具层硬拒**保留**（安全底线哲学：插件可关，工具层兜底不可关），数据从共享模块来
- `security_guard.py`：`from qi_agent.security_rules import ...`——三档判定数据共享；
  用户黑名单（plugins.toml）运行时 union 内置规则（现状保持）
- 删 `_RESTRICTED_MODULES` 双份？——不，它只在 security_guard 一处，保留原位
- `run_python._FORBIDDEN_PATTERNS` **不纳入**（见决策点 2）

## 决策点

| # | 决策点 | 方案 | 我的意见 |
|---|--------|------|---------|
| 1 | 规则放哪 | 独立模块 `security_rules.py` | ✅ 工具层 import 插件（security_guard）是反向依赖，必须独立纯数据模块 |
| 2 | run_python 代码检测纳入吗 | **不纳入**（本次只统一"命令权限类"） | ✅ `_FORBIDDEN_PATTERNS`/`_RESTRICTED_MODULES` 是沙箱内容策略（代码模式正则），与命令权限（前缀规则）正交；远期 DSH 声明式再统合 |
| 3 | shell 工具层兜底保留？ | **保留**（数据共享） | ✅ 插件可关（plugins.toml）→ 工具层兜底是"关了插件也有防线"的安全底线 |
| 4 | 用户黑名单融合 | 运行时 union（现状保持） | ✅ 内置规则 + 用户配置 = 判定时合并，用户配置仍是"增量" |
| 5 | DSH SandboxPolicy 声明式 | 远期方向，本次不做 | 📌 每个工具声明 auto/approval/deny + 沙箱级别的完整声明式是终极形态，本次共享模块是过渡 |

## 收益

- **改一处全生效**：加新危险命令只改 security_rules.py（shell 兜底 + 插件判档同时更新）
- **消除死代码**：_APPROVAL_PREFIXES 里的 python/py/pip/npm 由 _CODE_EXEC_PREFIXES 先判定——共享后显式声明"审批档排除代码执行段"
- **npm 硬拒缺口类问题根除**：工具层关键词与插件层审批档永不脱节（同源）

- 全量 pytest + ruff 零错误

- 手工验收：三档判定（白名单/审批/红线/代码执行）+ shell 硬拒兜底行为不变
