## 一、背景：为什么需要"主动记忆"

```
现状（V0 被动记忆，已实施）：
  /remember 显式记录 + pre-step 注入
  → 记忆靠【用户主动告诉】——agent 不会自己记

问题：
  ① 用户不说"记住"→ 重要信息丢失（对话完就忘）
  ② 记忆质量依赖用户判断（用户不知道什么值得记）
  ③ 长对话/多会话下，关键上下文（用户偏好/项目约定/决策）
     散落在对话里——无法沉淀

主动记忆：agent 自己判断"什么值得记"→ 自动提炼 → 注入
  → 对齐业界：Hermes agent-curated memory（agent 定期 review 提炼）
```

## 二、V1 设计：长短记忆分层

```
关键：记忆分两层（长短时记忆——对齐认知科学）

① 短期记忆（工作记忆——会话内）：
   已有：context.messages（对话历史）+ sticky（/remember 会话内）
   新增：短期记忆区（turn 级自动提炼——最近 N 轮的要点）
   生命周期：会话结束 → 短期记忆【合并进长期】或【丢弃】
   类比：人的工作记忆（当前任务上下文）

② 长期记忆（跨会话——文件持久化）：
   已有：MEMORY.md（agent 知识）+ USER.md（用户画像）
   新增：自动提炼写入（agent 判断值得长期记的）
   生命周期：永久（直到用户/agent 删除或整合）
   类比：人的长期记忆（经历/知识沉淀）

分层流转：
  对话 → 短期记忆（turn 级提炼）→ 会话结束整合 → 长期记忆（MEMORY.md）
                      ↘ 过期丢弃（不重要的）
```

## 三、主动记忆机制（V1：规则触发 + 间隔提炼 + subagent 异步）

```
核心（用户评审修正）：
  ① 不可能每轮提炼——至少每 10 轮触发一次（间隔提炼，非每轮）
  ② 用 subagent 能力做提炼（异步后台线程）——复用现有执行链，
     架构负担小（不新造机制）
  ③ 记忆文件写入无需审批（MEMORY.md/USER.md 直接写）

① 规则触发（零成本——程序判断，post-llm 监听）：
   - 用户偏好表述："我喜欢/我习惯/请记住" → 自动写 USER.md
   - 项目决策："我们决定/以后用 X" → 自动写 MEMORY.md
   → 无需审批（用户明说"记住"= 授权）

② 间隔提炼（每 10 轮——spawn subagent 异步）：
   - context 加 turn 计数，每 10 轮触发一次提炼
   - 触发 → spawn 一个 subagent（后台 daemon 线程）：
     subagent 读取最近 10 轮对话 → LLM 分析提炼 →
     结果写入 MEMORY.md/USER.md（无需审批）
   - 主对话不阻塞（subagent 异步跑，用户继续聊）
   - 失败容错：提炼 subagent 失败不影响主对话（结果丢弃）

   ｜ 为什么用 subagent（架构优势）：
   ｜   复用 spawn 执行链（后台线程/上下文隔离/失败容错）
   ｜   提炼逻辑 = 一个特殊 goal 的 subagent（prompt 驱动）
   ｜   不需要新的"提炼引擎"——就是一次 subagent 任务
   ｜   对齐：Hermes background_review（后台 review 提炼）
```

## 四、V2 路线：完整记忆体系（情景/语义/程序）

```
用户要求 V2 完整实现三类记忆（认知科学分类——对齐业界）：

① 情景记忆（Episodic）："发生了什么"
   = 对话历史/会话记录（时间线）
   → 已有：SQLite 会话持久化（messages 时间线）✅
   → V2 增强：会话摘要索引（每会话一段摘要——可搜索恢复）

② 语义记忆（Semantic）："知道什么"
   = 事实/概念/知识（去时间化）
   → 已有：MEMORY.md/USER.md（§ 条目）✅
   → V2 增强：相关性检索（embedding——按需注入而非全量）

③ 程序记忆（Procedural）："怎么做"
   = 技能/流程/方法（可执行的步骤）
   → 缺失：skill 系统（怎么做事）
   → V2 新增：skill-system（17 项 TODO）——流程/技能存为 Markdown 技能
   → 类比：Hermes skills / DSH skill 系统

V2 完整图景：
  情景记忆（会话历史） + 语义记忆（知识事实） + 程序记忆（技能流程）
  = 完整认知记忆体系（对齐认知科学 + 业界 agent 架构）
```

## 五、V1 实施范围（本方案）

```
① 规则触发（零成本——memory 插件扩展）：
   - 用户偏好表述检测（post-llm 监听 → 自动写 USER.md）
   - 项目决策检测（post-llm 监听 → 自动写 MEMORY.md）
   - 无需审批（用户明说"记住"= 授权）
② 间隔提炼（每 10 轮——subagent 异步）：
   - context 加 turn 计数 + 提炼触发标记（每 10 轮）
   - 触发 → manager.spawn 提炼 subagent（后台 daemon）：
     goal = "分析最近对话，提炼值得长期记住的信息"
     读最近消息 → LLM 提炼 → 写 MEMORY.md/USER.md
   - 主对话不阻塞（subagent 异步）；失败容错（结果丢弃）
③ 记忆文件写入无需审批（MEMORY.md/USER.md 直接写）
```

## 六、决策点

```
D1：提炼触发频率
    倾向：每 10 轮一次（用户拍板——不可能每轮提炼）
    —— 非最终方案（v2 可动态调整/按对话复杂度）

D2：提炼执行者
    倾向：subagent 异步（用户拍板——复用 spawn 执行链，
    架构负担小；对齐 Hermes background_review）
    —— 不新造提炼引擎

D3：记忆文件写入权限
    倾向：无需审批（用户拍板——MEMORY.md/USER.md 直接写）
    —— 用户明说"记住"= 授权；文件可编辑可删（Markdown）

D4：短期记忆存储
    倾向：context 内存区（short_term 列表）——会话内
    —— 不落盘（会话结束即整合/丢弃）

D5：提炼结果去向
    倾向：自动分节写 MEMORY.md（事实/决策）+ USER.md（偏好）
    —— 无需审批（D3）；用户可编辑/删除

D6：V2 语义记忆检索
    倾向：embedding 相关性（记忆多时按需注入）——V2 做
    —— V1 全量注入（记忆少）

D7：程序记忆（skill 系统）
    倾向：V2 独立项目（skill-system TODO 17 项）——V1 不做
```

## 七、工业级落地考量

```
可靠性：提炼失败不阻塞对话（try/except 容错）；规则误触发可
        关（插件配置）；提炼结果用户可见可删（Markdown）
安全性：提炼内容先扫描（prompt injection——Hermes 同款）——
        v1 至少做"提炼结果不自动注入"（用户确认后注入？）
        —— 简化：自动写但用户可删（可见即可审计）
记忆：  短→长整合防重复（去重）；长期超限走整合 TODO
可观测：提炼日志（提炼了什么/写到哪）；/memory 查看全貌
```

## 八、验收标准

```
① 用户说"我喜欢 X" → 自动写入 USER.md（无需 /remember）
② 对话说"我们决定用 X" → 自动写入 MEMORY.md
③ 会话结束 → 提炼出 1-3 条长期记忆（LLM 分析）
④ pre-step 注入含短期要点 + 长期记忆
⑤ 全量测试 573+ 全绿（新增规则/提炼/注入测试）
```

## 九、遗留（v2+）

- 语义记忆：embedding 相关性检索（按需注入）
