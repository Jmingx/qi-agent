## 2. 关键问题：L3 如何触发压缩

压缩阈值 = window × threshold。默认 128K × 0.7 = 89.6K token——**真实对话达不到**（30 轮普通对话约 5-10K token）。

**方案**：评测任务级插件配置覆盖（小窗口）：

```python
EvalTask("c-long-1", "context", "事实保持",
    steps=[...20 轮穿插事实 + 问猫名...],
    expected_keywords=["咪咪"],
    plugin_overrides={"context_manager": {
        "compress": {"window": 2000, "threshold": 0.5},  # 1000 token 即触发
        "async_compress": False,  # 评测用同步（确定性）
    }},
)
```

- 20 轮穿插事实对话（含工具调用输出）轻松超 1000 token → 压缩触发
- 压缩后问"我的猫叫什么" → 断言答对 = **事实保持验证**
- 同步压缩（async=False）：压缩在 pre-step 完成，评测确定性（不依赖后台线程时序）

## 3. 基建改动（3 处）

### 3.1 EvalTask 扩展（evaluation/tasks.py）

```python
@dataclass
class EvalTask:
    ...
    plugin_overrides: dict | None = None  # 任务级插件配置覆盖（如 context_manager 小窗口）
    setup: Callable | None = None         # 任务前置（如 sticky 记忆注入）
```

### 3.2 build_agent 支持配置覆盖（agent_factory.py）

```python
def build_agent(debug=False, stats=False, interactive=True,
                plugin_overrides: dict | None = None) -> tuple[Agent, list]:
    plugin_config = load_plugin_config()
    ...
    if plugin_overrides:
        for name, cfg in plugin_overrides.items():
            plugin_config[name] = {**plugin_config.get(name, {}), **cfg}  # 深合并
```

CLI 不传（None）——只评测用。

### 3.3 runner 传参（evaluation/runner.py）

```python
def _run_task(task: EvalTask) -> dict:
    if task.setup:
        task.setup()  # 前置（sticky 注入等）
    agent, _ = build_agent(interactive=False, plugin_overrides=task.plugin_overrides)
```

## 4. L3 三个任务（评测集新增）

### c-long-1：事实保持（核心）

```
steps（程序化生成 ~20 轮）：
```

### c-long-2：sticky 压缩后仍在

```
setup: context.sticky.remember("用户叫小Q")（sticky 挂载进 system，不参与压缩）

```

### c-long-3：压缩后不重做已完成工作（todo 联动）

```
steps:
  1. "帮我建一个任务：写周报"（todo 工具创建）
  2-15. 闲聊触发压缩
  16. "我刚才创建的任务是什么？"
断言：最终回答含 "周报"（模型从压缩摘要读 todo 内容，而非重新创建）
扩展：judge 检查 todo 工具未再次被调用（不重做）
```

## 5. C3 压缩模型独立配置

```toml
# plugins.toml
[context_manager.compress]
compression_model = "deepseek-chat"   # 缺省 None = 复用主模型（现状）
```

- `default_summarizer` 改造为**工厂**：`make_summarizer(model=None)` → 惰性建
  LLMClient(model=model)；None 时用当前主模型配置
- context_manager 插件读 `compress.compression_model` → 传给工厂
- 收益：压缩用便宜小模型，主对话用主模型——压缩本身也烧 token，
  独立模型 = 压缩成本可控

## 6. C4 手动命令（CLI）

```
/context  → 打印上下文占用构成（breakdown：system/工具/历史 估算占比
           + 最近真实 usage）
/compact  → 手动同步压缩（installed 插件里找 ContextManagerPlugin →
           compact_now() 同步压缩当前消息 → 打印压缩摘要 + 消息数变化）
```

- 触发路径：CLI 在 installed 插件列表找 ContextManagerPlugin（构造时记录引用）
- `compact_now()`：新方法——同步执行压缩链（复用策略链，异步开关绕过）

## 7. L4 一致性对比（评测任务 c-long-4）

```
steps:
  事实穿插 10 轮 → "我的猫叫什么？"（压缩前问）→ 再 10 轮触发压缩
  → "我的猫叫什么？"（压缩后问）
judge 扩展：检查历史中 assistant 回答含 "咪咪" 的条数 ≥ 2
  （压缩前 1 次 + 压缩后 1 次 = 内容一致性）
```

## 8. 决策点

| # | 决策 | 推荐 | 理由 |
|---|---|---|---|
| D1 | L3 触发压缩方式 | **任务级小窗口覆盖**（plugin_overrides） | 真实 128K 窗口不可达（30 轮 ~10K）；小窗口验证"压缩机制本身"而非"撑爆窗口" |
| D2 | EvalTask 扩展 | **plugin_overrides + setup 回调**（dataclass 加字段） | 最小侵入；setup 支持 sticky 等前置注入 |
| D3 | C3 配置字段 | `compress.compression_model`（None=主模型） | 与现有 compress 配置段同层；None 语义 = 行为不变 |
| D4 | /compact 触发 | installed 插件查找 + `compact_now()` | 复用策略链执行；不动 agent 核心（零侵入哲学） |
| D5 | L4 形式 | 评测任务 c-long-4 + judge 双回答检查 | 复用 L3 基建，不造新评测框架 |

## 10. 风险

- L3 真实 LLM 评测耗时（每任务 ~20 轮 × 2-3s ≈ 1 分钟；4 任务 ~5 分钟）
  → 评测集按需跑（run.py 支持指定任务？评估现状——单独跑 L3 脚本）
- 压缩质量波动（DeepSeek 摘要可能丢细节）→ L3 失败即暴露，摘要提示词调优
- sticky 是内存态（进程内 remember）→ setup 回调在跑 steps 前执行即可
