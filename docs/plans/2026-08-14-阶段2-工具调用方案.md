## 1. 目标

让 qi-agent 从"聊天机器人"升级为"**能动手的 Agent**"——LLM 在回答过程中可以**自主决定调用工具**（获取时间、读文件等），拿到结果后继续推理，直到给出最终答案。

**这是 agent 与聊天机器人的分水岭：** 聊天机器人只会"说"，agent 会"做"。

**本次不做的事（YAGNI）：** 不做会话持久化（阶段 3）、不做配置系统（阶段 4）、不做流式输出（阶段 5b）、不做危险操作防护体系（只做最小安全提示）。

## 2. 技术原理（导师讲解：Tool Calling 协议与 Agent Loop）

### 2.1 模型怎么"知道"有工具可用？

**关键认知：工具调用不是魔法，是"提示词 + 结构化输出"。**

我们在请求里多传一个 `tools` 参数——用 **JSON Schema** 描述每个工具的签名：

```json
{
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "get_time",
        "description": "获取当前日期和时间",
        "parameters": {
          "type": "object",
          "properties": {},      // 无参数
          "required": []
        }
      }
    },
    {
      "type": "function",
      "function": {
        "name": "read_file",
        "description": "读取指定路径的文件内容",
        "parameters": {
          "type": "object",
          "properties": {
            "path": {"type": "string", "description": "文件路径"}
          },
          "required": ["path"]
        }
      }
    }
  ]
}
```

模型看到这些"工具说明书"后，如果判断需要调用，**不再返回普通文本**，而是返回一个结构化的 `tool_calls` 对象：

```json
{
  "role": "assistant",
  "content": null,
  "tool_calls": [
    {
      "id": "call_abc123",
      "type": "function",
      "function": {
        "name": "get_time",
        "arguments": "{}"       // JSON 字符串
      }
    }
  ]
}
```

**训练原理（一句话）：** 模型在训练时见过大量"工具使用"示例，学会了"什么时候该调工具、参数怎么填"。我们只需要按协议传对格式，它就会"配合演出"。

### 2.2 Agent Loop：循环直到"想好为止"

工具调用的完整流程是一个**循环**：

```
用户提问
   │
   ▼
┌──────────────┐   模型返回内容
│ 发给 LLM     │ ───────────────► 如果没调工具 → 这就是最终答案，结束
│ (带工具清单)  │
└──────────────┘
   │ ▲
   │ │ 模型返回 tool_calls
   ▼ │
┌──────────────┐
│ 执行工具     │ ── 把结果以 role="tool" 的消息回填给模型
│ (本地函数)    │
└──────────────┘
```

**大白话：** agent 先"想"（调 LLM），想调工具就"动手"（执行函数），把结果告诉它，让它继续想……直到它觉得"想清楚了"（直接返回文本）为止。

**关键机制：tool 结果如何回填？** 每次工具执行结果以 `{"role": "tool", "tool_call_id": "...", "content": "结果"}` 追加进消息历史。`tool_call_id` 把结果和模型发起的调用**一一对应**——这是协议的要求，必须带上。

**一轮对话的完整消息序列：**

```
[system] 你是一个有用的助手，可以调用工具。
[user]   现在几点了？
[assistant] tool_calls: [get_time]
[tool]   2026-08-14 21:30:00        ← 工具执行结果
[assistant] 现在是 2026-08-14 晚上 9 点半。   ← 最终答案
```

### 2.3 为什么需要 max_turns（最大轮数）？

**风险：** 如果工具逻辑有 bug，或模型陷入"调工具→失败→再调"的死循环，请求会无限进行（每次都是一次 API 计费）。

**对策：** 限制循环次数（如 8 轮），超限即停止并返回提示。这是所有 agent 框架的标准防护。

### 2.4 与 Hermes 的对照

Hermes 的 agent 循环（`agent/` 目录）就是这套机制的完整工业实现：工具注册、参数校验、循环控制、错误处理。**我们现在写的是它的最小版本**——规模小但原理一致。

## 4. 核心设计

### 4.1 tools.py —— 工具注册机制（本项目第一个自写装饰器）

```python
"""工具注册机制：@tool 装饰器把函数登记进注册表。"""

# 注册表：name -> {fn, description, schema}
_TOOL_REGISTRY: dict[str, dict] = {}


def tool(description: str = ""):
    """装饰器：把函数注册为可被 LLM 调用的工具。

    用法:
        @tool(description="获取当前时间")
        def get_time() -> str: ...
    """
    def decorator(fn):
        name = fn.__name__                       # 函数名即工具名
        _TOOL_REGISTRY[name] = {
            "fn": fn,
            "description": description,
            "schema": build_schema(fn, description),  # 自动生成 JSON Schema
        }
        return fn                                # 原样返回，不改变函数本身
    return decorator


def get_tool_schemas() -> list[dict]:
    """返回所有工具的定义（给 LLM 的 tools 参数）。"""


def execute_tool(name: str, arguments: dict) -> str:
    """按名字执行工具，返回字符串结果。"""
```

**关键点：**
- **函数名即工具名**（`get_time()` → 工具名 `get_time`）——简单直接
- **schema 自动生成**：从函数签名 + 类型注解推导 JSON Schema（用 `inspect.signature`），写工具的人不用手动维护 schema
- **`@tool` 原样返回函数**（不包装）——因为 LLM 不需要被包装后的版本，只需要注册信息

### 4.2 builtin.py —— 三个内置工具

```python
from qi_agent.tools import tool

@tool(description="获取当前日期和时间")
def get_time() -> str:
    """返回当前本地日期时间。"""
    from datetime import datetime
    return datetime.now().strftime("%Y-%m-%d %H:%M:%S")

@tool(description="读取指定路径的文件内容")
def read_file(path: str) -> str:
    """读取文本文件，返回内容。"""
    ...

@tool(description="在 shell 中执行命令（只读命令，如 dir/ls/pwd）")
def shell(command: str) -> str:
    """执行命令并返回输出。"""
    ...
```

**⚠️ shell 工具的安全设计（重要）：**
- 阶段 2 只允许**只读命令**（`dir`/`ls`/`pwd`/`echo` 等），方案里写死白名单校验
- 执行前在返回值里**不回显敏感信息**
- 危险命令（`rm`/`del`/`format` 等）直接拒绝并提示
- 完整的安全放开留给后续阶段，本阶段以"能跑通"为主

### 4.3 agent.py —— Agent Loop

```python
class Agent:
    def __init__(self, client, system_prompt=..., max_turns: int = 8):
        self.client = client
        self.messages = [{"role": "system", "content": system_prompt}]
        self.max_turns = max_turns

    def chat(self, user_input: str) -> str:
        """多轮工具调用循环：调LLM → 执行工具 → 回填 → 直到最终答案。"""
        self.messages.append({"role": "user", "content": user_input})
        for _ in range(self.max_turns):
            result = self.client.chat(self.messages, tools=get_tool_schemas())
            if result.tool_calls:
                # 1. 把 assistant 的 tool_calls 消息追加进历史
                self.messages.append(result.assistant_message)
                # 2. 逐个执行工具，结果回填
                for call in result.tool_calls:
                    output = execute_tool(call.name, call.arguments)
                    self.messages.append({
                        "role": "tool",
                        "tool_call_id": call.id,
                        "content": output,
                    })
            else:
                # 3. 没有工具调用 → 这就是最终答案
                self.messages.append(result.assistant_message)
                return result.content
        return "已达最大轮数，任务可能未完成。"
```

### 4.4 llm.py —— 返回结构设计

为了让 agent 层好判断，`chat()` 返回一个**结构化结果**而不是裸字符串：

```python
@dataclass
class ChatResult:
    content: str | None               # 最终文本（无工具调用时非空）
    tool_calls: list[ToolCall] | None # 工具调用列表（有调用时非空）
    assistant_message: dict           # 完整的 assistant 消息（含 tool_calls，原样存历史）

@dataclass
class ToolCall:
    id: str
    name: str
    arguments: dict
```

**为什么返回对象而不是字符串？** 因为 agent 需要区分"模型给了文本"还是"模型要调工具"——裸字符串装不下这个信息。

### 5.1 FakeClient 升级

```python
class FakeClient:
    """可编程测试替身：按脚本依次返回预设响应。"""

    def __init__(self, script: list[ChatResult]):
        self.script = script          # 预设响应序列
        self.calls: list[dict] = []   # 记录每次收到的请求

    def chat(self, messages, tools=None) -> ChatResult:
        self.calls.append({"messages": messages, "tools": tools})
        return self.script.pop(0)     # 依次弹出预设响应
```

## 9. 风险与说明

- **API 计费**：循环中每轮都是一次 API 调用，max_turns=8 兜底；验收时控制对话轮数
- **DeepSeek 工具调用支持**：deepseek-v4-flash 支持 function calling（OpenAI 兼容协议），如遇兼容问题降级方案是提示词式工具（在 system prompt 里描述工具格式，让模型输出 JSON，再解析执行）——备选，不首选
- **shell 安全**：本阶段只读白名单，后续阶段再设计完整权限模型
- **schema 生成边界**：只支持 str/int/float/bool/可选参数，复杂嵌套类型（list/dict 参数）暂不支持——YAGNI
