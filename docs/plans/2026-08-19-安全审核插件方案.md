## 1. 目标

新增第一个**决策类插件** `security_guard`（安全审核）：
- 监听 `agent/tool-call`（bail 决策点），黑名单命中 → 返回 `[安全拦截]` 提示拦截
- 黑名单**配置化**（plugins.toml `[security_guard]` 段）——用户可自定义防线（决策点 B）
- 与 shell 内置拦截形成**双防线**（插件做增量，不替代内置）

## 2. 设计原理（导师讲解）

### 2.1 拦截链路（principles/08 实战）

```
模型想调 shell("git push --force")
    │
    ▼
agent/tool-call（bail 分发，priority=200 先被询问）
    │
    ▼
security_guard._on_tool_call(name="shell", arguments={"command": "git push --force"})
    │  黑名单 {"shell": ["git push"]} 命中
    ▼
返回 "[安全拦截] shell 命令包含危险关键词: 'git push'，已拒绝执行"
    │
    ▼
工具【不执行】→ 拦截值作为 tool 结果回填给模型
    │
    ▼
模型（读到结果）→ "抱歉，git push 被安全策略禁止，我换个方式"
```

### 2.2 关键架构变更：factory 约定升级（决策点 B 的地基）

**现状**：`load_plugins` 里 `plugin = entry.factory()`——无参工厂，插件拿不到配置。

**升级**：factory 约定改为**接收配置段 dict**：

```python
# 升级前
plugin = entry.factory()                          # 无参，插件无法配置化

# 升级后
plugin_config = {k: v for k, v in config.get(name, {}).items() if k != "enabled"}
plugin = entry.factory(plugin_config)             # 接收除 enabled 外的配置段
```

**为什么过滤 enabled**：enabled 已被 load_plugins 消费（判断是否装配），传给插件的是"插件自己的业务配置"（如 blacklist），职责干净。

**兼容性处理**：所有现有插件 factory 统一升级签名：
- `ToolStatsPlugin.__init__` 改为 `__init__(self, config: dict | None = None)`（不用也接受）
- 测试夹具 FakePlugin 同步适配
- 这是内部约定变更（无外部消费者），一次性升级成本低——现在不做，将来插件带配置时更痛

### 2.3 配置格式（TOML，tomllib 原生解析，config.py 零改动）

```toml
[security_guard]
enabled = true

# 按工具名分组的黑名单（子串匹配，大小写不敏感）
[security_guard.blacklist]
shell = ["git push", "mkfs", "dd "]
run_python = ["os.remove"]     # 将来可扩展其他工具
```

`load_plugin_config()` 返回：`{"security_guard": {"enabled": true, "blacklist": {"shell": [...], "run_python": [...]}}}`——tomllib 原生支持嵌套表，**config.py 不用改**。

### 2.4 匹配逻辑（对齐 shell 内置拦截的风格）

- **参数名映射**（插件内置）：`{"shell": "command", "run_python": "code", "read_file": "path"}`——知道每个工具的参数名才能从 arguments 里取值
- **匹配方式**：关键词子串匹配 + 小写化（`cmd.lower()` 后 `keyword.lower() in cmd`）——与 shell.py 现有逻辑一致
- **未配置规则的工具** → 直接放行（None）
- **arguments 缺参数** → 放行（不崩溃，防御性）

## 3. 设计

### 3.1 插件类（新文件 qi_agent/plugins/security_guard.py，~70 行）

```python
"""安全审核插件：监听 agent/tool-call，黑名单命中拦截工具调用。

设计（方案 docs/plans/2026-08-19-安全审核插件方案.md）：
- 双防线：shell 内置拦截（硬编码）管"危险操作"；本插件（可配置）管"用户自定义限制"
- 黑名单来自 plugins.toml [security_guard.blacklist]，按工具名分组
- 拦截值遵循回填协议（principles/08）：[安全拦截] 前缀，可行动
"""

from qi_agent.events import EventBus
from qi_agent.plugins.registry import register_plugin

# 工具名 -> 参数名映射（从 arguments 里取待审核内容）
_ARG_PARAM_MAP = {
    "shell": "command",
    "run_python": "code",
    "read_file": "path",
}


class SecurityGuardPlugin:
    """安全审核插件：黑名单命中返回拦截提示，否则放行。"""

    def __init__(self, config: dict | None = None) -> None:
        config = config or {}
        # 黑名单：{工具名: [关键词, ...]}；默认空（零规则 = 行为不变）
        self.blacklist: dict[str, list[str]] = config.get("blacklist", {})

    def install(self, bus: EventBus) -> None:
        # priority=200：决策类插件先于观测类（统计 100）被询问
        bus.on("agent/tool-call", self._on_tool_call, priority=200)

    def _on_tool_call(self, name: str, arguments: dict, **_) -> str | None:
        """审核一次工具调用：命中黑名单返回拦截提示，否则 None（放行）。"""
        keywords = self.blacklist.get(name, [])
        if not keywords:
            return None  # 该工具未配置规则 → 放行
        param = _ARG_PARAM_MAP.get(name)
        if param is None or param not in arguments:
            return None  # 未知工具/参数缺失 → 放行（防御性）
        content = str(arguments[param]).lower()
        for keyword in keywords:
            if keyword.lower() in content:
                return (
                    f"[安全拦截] {name} 内容包含危险关键词: '{keyword}'，"
                    f"已拒绝执行"
                )
        return None


# 自注册：安全底线类插件默认开（零规则 = 行为不变，配置后生效）
register_plugin(
    name="security_guard",
    factory=SecurityGuardPlugin,
    description="安全审核（黑名单拦截，plugins.toml 配置）",
    default_enabled=True,
)
```

### 3.5 默认行为说明（零侵入原则）

- 插件默认 `enabled=true` **但黑名单为空** → 不拦截任何调用 → **行为与 v0.4.9 完全一致**
- 用户配置黑名单后才生效——安全底线可配置化，但默认不改变任何行为

## 8. 风险与说明

- **factory 约定变更**：所有插件 factory 签名升级（内部项目，一次性适配）；将来新插件必须遵守"接收 config"约定——在 register_plugin docstring 注明
- **双防线冗余**：与 shell 内置拦截可能重复命中（内置先拦或插件先拦都返回拦截，语义一致，无冲突）——将来档位 B 迁移时消除
- **子串匹配的误伤**：黑名单关键词短（如 "dd "）可能误伤正常命令——与 shell 内置同一局限，文档注明"关键词尽量带空格/上下文"
- **YAGNI 红线**：不做审批交互（"展示列表让用户选择"）——那是 shell 三档权限 TODO；本期只做黑名单拦截
