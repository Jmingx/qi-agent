## 1. 目标

run_python 的干净环境从**单层白名单**升级为**双重过滤**（对齐 Hermes）：
1. **密钥子串拦截**（第一道防线，先扫）——变量名含 KEY/TOKEN/SECRET 等特征 → 一律丢弃
2. **安全名单保留**（第二道）——白名单（_SAFE_ENV_KEYS）内的才保留

目的：**防御纵深**——即使将来白名单改宽/改成前缀匹配，密钥特征变量也过不了第一道。

## 2. 设计原理（导师讲解）

### 2.1 现状弱点（单层防线的风险）

```python
# v0.4.2：白名单是唯一防线
return {k: v for k, v in os.environ.items() if k in _SAFE_ENV_KEYS}
```

当前 10 个 key 没问题，但**一次失误就泄露**：将来改成前缀匹配（PATH*）、
加变量时手滑——带密钥的变量就进沙箱了。单层防线 = 单点故障。

### 2.2 Hermes 对照（防御纵深的教科书）

`_scrub_child_env` 五条规则，顺序关键（order matters）：

```
① 显式声明放行（skill/config）→ 通过
② 密钥子串拦截（KEY/TOKEN/...）→ 一律丢弃  ← 先扫，黑名单优先于一切白名单
③ 安全前缀匹配 → 通过
④ 精确名单 → 通过
⑤ Windows 必需变量 → 通过
```

**核心**：即使 ③④⑤ 将来写宽/写错，密钥特征变量也过不了 ②。
Hermes 的密钥子串清单（含真实世界踩坑注释）：

```python
_SECRET_SUBSTRINGS = (
    "KEY", "TOKEN", "SECRET", "PASSWORD", "CREDENTIAL",
    "PASSWD", "AUTH", "DSN", "WEBHOOK",
    "CREDS", "BEARER", "APIKEY",   # 缩写（曾漏检）
    # "PASS" 故意不加 —— 误伤 BYPASS_CACHE / COMPASS_DIR / PASSENGER_HOST
)
```

### 2.3 行为兼容性

白名单 10 个 key（PATH/SYSTEMROOT/WINDIR/COMSPEC/TEMP/TMP/HOME/
USERPROFILE/HOMEDRIVE/HOMEPATH）**均不含密钥特征** → 双重过滤下行为零变化。

## 3. 设计

### 3.1 run_python.py 修改（~15 行）

```python
# 第一道防线：密钥特征子串（对齐 Hermes _SECRET_SUBSTRINGS）
# 注意 "PASS" 故意不加：误伤 BYPASS_CACHE/COMPASS_DIR 等合法变量
_SENSITIVE_KEY_SUBSTRINGS = (
    "KEY", "TOKEN", "SECRET", "PASSWORD", "CREDENTIAL",
    "PASSWD", "AUTH", "DSN", "WEBHOOK",
    "CREDS", "BEARER", "APIKEY",
)

# 第二道防线：安全名单（OS 运行必需，原样保留）
_SAFE_ENV_KEYS = (
    "PATH", "SYSTEMROOT", "WINDIR", "COMSPEC",
    "TEMP", "TMP", "HOME", "USERPROFILE", "HOMEDRIVE", "HOMEPATH",
)

def _build_safe_env() -> dict:
    """双重过滤（对齐 Hermes _scrub_child_env 第 ② 条，先黑后白）：
    ① 密钥子串拦截：变量名含密钥特征 → 丢弃（防御纵深，名单失误也拦得住）
    ② 白名单保留：OS 运行必需的精确名单
    """
    safe = {}
    for k, v in os.environ.items():
        upper = k.upper()  # 环境变量名大小写不敏感（Windows 尤其）
        # ① 密钥子串拦截（第一道，先扫）
        if any(s in upper for s in _SENSITIVE_KEY_SUBSTRINGS):
            continue
        # ② 安全名单保留（第二道）
        if k in _SAFE_ENV_KEYS:
            safe[k] = v
    return safe
```

**顺序关键**：密钥拦截在前——即使未来白名单加宽，密钥也进不来。

### 3.2 与 shell 工具的关系（范围说明）

本升级只作用于 **run_python**（沙箱子进程 env）。shell 工具的 env
是完整透传（shell 只读白名单已拦截危险操作）——透传范围扩大留 shell

## 8. 风险与说明

- **误伤**：KEY/TOKEN 等子串可能误伤合法变量（如 MAP_KEY=地图key 场景罕见，且安全优先）；"PASS" 已按 Hermes 踩坑排除
- **大小写**：upper 扫描覆盖 Windows 大小写不敏感；POSIX 环境也统一 upper（密钥特征更严格，无害）
- **范围**：只改 run_python；shell 的 env 透传不在此方案（留 shell 权限 TODO）
- **不做的**：DSN/WEBHOOK 等子串已是 Hermes 实测清单，不再扩展（YAGNI）；无"显式声明放行"机制（Hermes 的 env_passthrough，将来需要再加）
