# 工具决策码机制方案（ToolAction + ToolDecision + 错误码）

日期：2026-08-23 ｜ 状态：待评审 ｜ 来源：agent.py:162 字符串匹配重构

## 背景

agent.py:162 目前用**字符串约定**决定是否走审批：

```python
decision = self.events.bail("agent/tool-call", ...)   # 返回 str
if isinstance(decision, str) and decision.startswith("NEED_APPROVAL:"):
    command = decision.split(":", 1)[1]               # 冒号分割
```

问题：
1. **无类型保障**：拼写错误/格式漂移静默失效（"NEED_APPROVAL:" 打错 = 审批静默跳过）
2. **三方字符串耦合**：security_guard（判档）→ agent（分发）→ approval_gate（消费）
   靠散落的字符串约定，改格式要改三处
3. **不可扩展**：加新档（WARN/ESCALATION）要再约定新前缀 + 改 agent 分支
4. **不可观测**：字符串无法进统计/日志维度（错误码语义缺失）

## 业界方案洞察（评审依据）

| 项目 | 决策模型 | 关键设计 |
|---|---|---|
| Hermes | `{"action": "approve"/"block"/"warn"/"allow", "message": ...}`（approval.py 结构化字典）+ 审批状态机 `once/session/always/deny` | action 枚举 + message（人类可读）；循环按 action 分发 |
| DSH | capability 模型：`ApprovalPolicy = 'ask'/'never'` + answerers 链 + typert 类型化协议 | 判档与交互是独立 capability，类型系统保证协议 |
| Claude Code | `PermissionResult`: allowed/denied/needs-approval/error + 规则优先级 deny>allow>ask | 结果码枚举 + 判定与交互分离 |

**共识**：①结构化决策码（枚举/对象）②判档与交互分离（统一协议连接）
③决策带人类可读 reason ④状态可扩展。

## 设计

### 1. ToolAction（决策码枚举）

```python
# qi_agent/tools/decision.py
class ToolAction(str, Enum):
    ALLOW = "allow"                 # 放行执行
    BLOCK = "block"                 # 硬拒（不弹窗——红线/黑名单/敏感路径）
    NEED_APPROVAL = "need_approval" # 需审批（弹窗确认）
    # 预留：WARN（警告放行）、ESCALATION（沙箱升级显式档）
```

### 2. ToolDecision（结构化决策）

```python
@dataclass
class ToolDecision:
    action: ToolAction
    reason: str = ""      # 人类可读说明（回填给模型的文本，如 "[安全拦截] 黑名单命令"）
    code: str = ""        # 错误码（日志/统计/测试断言用，见错误码表）
    command: str = ""     # 审批交互上下文（原 NEED_APPROVAL: 冒号后的部分）
```

### 3. 错误码表（code 字段语义）

| code | 含义 | action |
|---|---|---|
| `SEC_BLOCK_BLACKLIST` | 黑名单命中 | BLOCK |
| `SEC_BLOCK_REDLINE` | 红线前缀（format/shutdown 等） | BLOCK |
| `SEC_BLOCK_SENSITIVE` | 敏感路径（.env/.git） | BLOCK |
| `SEC_BLOCK_PATH` | 路径规则拦截（8.3/越界） | BLOCK |
| `SEC_APPROVAL_GENERAL` | 普通审批档（shell/write_file 覆盖等） | NEED_APPROVAL |
| `SEC_APPROVAL_SANDBOX` | 沙箱降级（run_python import 白名单外） | NEED_APPROVAL |
| `SEC_APPROVAL_ESCALATION` | 沙箱升级（shell 代码执行） | NEED_APPROVAL |

### 4. 交互链路（改造后）

```
security_guard（判档插件）
  └─ bail("agent/tool-call") → ToolDecision(action=NEED_APPROVAL, code=SEC_APPROVAL_GENERAL, command="rm /tmp/a")
agent.py（编排）
  └─ match decision.action:
       ALLOW → 执行
       BLOCK → 回填 f"[安全拦截] {decision.reason}"（不弹窗）
       NEED_APPROVAL → bail("agent/tool-approval", command=decision.command, code=decision.code, ...)
approval_gate（交互插件）
  └─ 读 decision.command/code（结构化字段，不再解析冒号）
```

### 5. 兼容与迁移

- **返回值兼容**：security_guard 返回 ToolDecision；agent 循环同时兼容
  `ToolDecision` 与旧 `str`（过渡期）？——不：一次性迁移（测试全量更新），
  不留双轨（旧字符串 = 技术债）
- **测试迁移**：security_guard 测试断言 `decision.action == ToolAction.BLOCK`
  （替代 `"[安全拦截]" in output`）；agent 集成测试断言回填文本不变（行为等价）
- **回填文本保持**：BLOCK 回填仍为 `[安全拦截] 原因`（模型可见行为不变）；
  NEED_APPROVAL 审批拒绝仍为 `[审批拒绝] 用户不同意执行: 命令`（CLI 体验不变）

## 决策点

| # | 决策点 | 倾向 |
|---|--------|------|
| D1 | ToolDecision 放哪个模块 | `qi_agent/tools/decision.py`（工具域决策协议；插件 import 不产生循环——decision 无依赖） |
| D2 | 是否留字符串兼容 | **不留**（一次性迁移，测试全量更新——旧字符串是技术债） |
| D3 | 错误码命名 | `SEC_` 前缀（安全域）；`CODE_EXEC`/`FILE_` 等域后续按需扩展 |
| D4 | bail 事件 payload | `agent/tool-call` 事件 data 传 ToolDecision 对象（非 dict）——监听器直接读属性 |
| D5 | 扩展档位（WARN/ESCALATION）| 本期只建机制（枚举可扩展），不加新档——避免为不存在场景预设计 |
