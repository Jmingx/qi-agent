## 1. 目标

搭建 qi-agent 的 Python 项目骨架：可安装、可测试、可扩展、代码风格可检查。这是后续所有阶段的地基。

**本次不做的事（YAGNI）：** 不写任何 agent 逻辑、不接 LLM、不做配置系统——那些是阶段 1/4 的事。

## 2. 技术选型（导师讲解：每个选择的"为什么"）

### 2.1 包管理：uv（已在用）

**原理：** 现代 Python 项目用 `pyproject.toml`（PEP 621 标准）声明元数据和依赖，`uv` 负责解析依赖树、创建虚拟环境、锁版本（生成 `uv.lock`）。

**为什么是 uv 而不是 pip + venv：**
- uv 是 Rust 写的，解析依赖和安装速度比 pip 快一个数量级
- 一条命令 `uv add <pkg>` 同时完成：安装 + 写入 pyproject.toml + 更新锁文件
- 你机器上已装 uv 0.11.12，且 Hermes 自己也是这么管理 Python 项目的

**锁文件（uv.lock）的价值：** 记录所有依赖的精确版本，保证"你机器上能跑" = "换台机器也能跑"。练手项目也该从第一天就用。

### 2.2 LLM 调用：openai SDK（而不是手写 httpx）

**原理：** DeepSeek 的 API 兼容 OpenAI 协议（同样的 `/chat/completions` 端点、同样的消息格式）。所以我们可以直接用 `openai` 官方 SDK，只需把 `base_url` 指向 `https://api.deepseek.com`。

**为什么不用 httpx 手写 REST 请求：**
| 对比项 | openai SDK | 手写 httpx |
|--------|-----------|-----------|
| 请求构造/响应解析 | 封装好了 | 要自己写 |
| 重试/超时 | 内置 | 要自己实现 |
| 类型提示 | 完整（Message、ToolCall 等） | 无 |
| 流式（阶段 5b 需要） | 原生支持 | 要自己解析 SSE |
| 工具调用（阶段 2 核心） | 原生支持 | 要自己处理 |
| 依赖体积 | 一个包 | 也要装 httpx |

**结论：** openai SDK 是"花小钱买未来"。阶段 2 的工具调用、阶段 5 的流式输出都是 SDK 原生能力，省掉我们大量底层工作，而学习原理不受影响（我们仍能看到消息结构本身）。

**为什么不直接上 langchain / llama-index 等 agent 框架：**
- 本项目的学习目标就是**理解 agent 底层机制**，框架会把这些机制封装成黑盒
- 我们的架构足够简单，不需要框架的抽象层
- 先自己造轮子，理解原理后再看框架会豁然开朗

### 2.3 配置读取：python-dotenv（最小方案）

**原理：** `.env` 文件存放 `DEEPSEEK_API_KEY=...`，`python-dotenv` 在程序启动时把它加载进环境变量。API key 是敏感信息，不进代码、不进 git（`.gitignore` 排除）。

**为什么不是 pydantic-settings：** 它更强大（带类型校验），但引入 pydantic v2 依赖较重。阶段 0-3 只需要"读一个 key"，YAGNI。阶段 4 做配置系统时如果需求变大再升级。

### 2.4 代码风格检查：ruff

**原理：** ruff 是 Rust 写的 Python linter + formatter + import 排序器，一个工具顶过去三个（flake8 + black + isort），速度极快。

**为什么需要它（对应你的 P1-5 代码规范）：** "代码风格统一"不能靠我自觉——让工具在 CI/提交前强制执行。配置好规则后，`uv run ruff check` 一秒出结果，风格问题自动暴露。

**规则选择：** 用默认规则集（E/F 类）+ 行宽 100（PEP 8 建议 79 但业界普遍放宽到 100-120），不引入激进规则，避免练手阶段被工具烦扰。

### 2.5 测试框架：pytest

**原理：** pytest 是 Python 事实标准的测试框架：`def test_xxx()` 写测试，断言用原生 `assert`，失败时自动展示详细信息。支持 fixture（夹具）机制，阶段 1 mock LLM 客户端时会用到。

**为什么用它：** 无需额外配置、生态最大、和 uv 集成好。测试文件放 `tests/`，命名 `test_*.py`。

## 4. 目录结构

```
qi-agent/
├── pyproject.toml        # 项目元数据 + 依赖 + 工具配置
├── uv.lock               # 依赖锁文件（uv 生成）
├── .gitignore            # 排除 .venv/.env/.idea/__pycache__ 等
├── .env.example          # API key 占位模板（.env 本体不进 git）
├── AGENTS.md             # 项目规范（已有）
├── docs/                 # 原理归档 + 开发记录（已有）
├── qi_agent/
│   └── __init__.py       # 包入口（含 __version__）
└── tests/
    └── test_smoke.py     # 冒烟测试：验证包可导入
```

**说明：** `qi_agent/` 下的 `cli.py`、`agent.py` 等模块**不在此阶段创建**——脚手架只搭"空包"，功能模块在各自阶段按方案新建，避免空文件堆积。

## 5. pyproject.toml 核心配置预览

```toml
[project]
name = "qi-agent"
version = "0.1.0"
description = "从零构建的类 Hermes AI Agent（练手项目）"
requires-python = ">=3.11"
dependencies = [
    "openai>=1.40",
    "python-dotenv>=1.0",
]

[dependency-groups]
dev = [
    "pytest>=8.0",
    "ruff>=0.6",
]

[tool.pytest.ini_options]
testpaths = ["tests"]

[tool.ruff]
line-length = 100
```

## 6. 实施步骤

1. 创建 `pyproject.toml`（如上配置）
2. 创建 `.gitignore`（含 `.venv/`、`.env`、`.idea/`、`__pycache__/`、`*.db`）
3. 创建 `.env.example`（`DEEPSEEK_API_KEY=sk-你的key`）
4. 创建 `qi_agent/__init__.py`（`__version__ = "0.1.0"`）
5. 创建 `tests/test_smoke.py`：
   ```python
   def test_package_imports():
       import qi_agent
       assert qi_agent.__version__ == "0.1.0"
   ```
6. `uv sync` 安装依赖
7. 运行验证：
   - `uv run pytest` → 预期 1 passed
   - `uv run ruff check .` → 预期无错误
8. 清理：把已误提交的 `.idea/` 移出版本控制（`git rm -r --cached .idea` + 加入 .gitignore）
9. git commit（`chore: 搭建项目脚手架`）
