# Web 界面四问题修复方案（2026-09-02）

> 状态：待评审
> 触发：用户实测 Web UI 报告 4 个问题（聊天气泡按钮样式、子任务返回内容不全、子任务状态不刷新、工具调用状态不显示）。
> 全部问题已用日志证据 + headless Chrome 复现定位，本文档含修复设计规格与验收标准，评审通过后转交 Codex。

## 一、问题与根因（证据链）

### 问题 1：聊天气泡复制/编辑按钮样式不合理、会换行
- 证据（headless 几何测量）：`.copy-btn` 是 28×28 的格子，里面放 16px 文字「复制」（两个汉字 ≈ 32px 宽）→ **文字在按钮内竖排换行**；`.bubble` 全局 `padding-right: 42px` 为隐形按钮预留，短消息（如「现在几点」）内容被挤到 64px 宽、气泡 1/3 是空白。
- 根因：复制按钮用文字标签 + 固定 28px 盒子，未考虑 CJK 宽度；按钮平时透明占位（opacity:0）却永久吃掉内容宽度。
- 相关代码：`components/MessageBubble.tsx`（copy-btn / bubble-actions 两套按钮）、`style.css`（`.copy-btn` / `.bubble-actions` / `.bubble` padding-right 42px）。

### 问题 2：子任务返回的内容没有展示全
- 证据：rpc.log 19:00:08 / 19:01:04 两次 delegate_async 后 **0 条 `session/status` 轮询**（全天仅 6 条，全部来自早期 Python 脚本）；卡片 body 永远停在「等待子任务状态更新...」或 300 字截断预览。
- 根因分两层：
  1. **结果根本没到前端**（与问题 3 同根因，见下）；
  2. 即使轮询恢复，还有两个展示缺陷：`SubTaskCard` completed 默认折叠只显示前 300 字（结果才是子任务的交付物，默认应收起的是过程不是结果）；`need_more_info` / `stopped` 等**合法终态不在终态集合**（轮询只认 completed/failed → 会一直轮询到 60s 超时，真实答案永远不显示——19:01:04「你好」子任务实测返回 need_more_info，message.log 有全文）。
- 相关代码：`hooks/useSubtask.ts`（终态映射）、`components/SubTaskCard.tsx`（可见文本策略）。

### 问题 3：子任务完成但状态一直「⏳ 运行中」
- 证据（headless 复现，console 实锤）：
  ```
  DBG: [subtask] poll agt_20260902_191440_131eb8
  DBG: [subtask] meta missing, skip agt_20260902_191440_131eb8
  ```
  子任务内核 24s 即完成（run.log `subagent-complete` + message.log result 投递），卡片永远运行中。
- 根因（一行级）：`scheduleSubTaskPoll()` 第一行调用 `clearSubTaskPoll(subId)`——**重置定时器的同时把 `subTaskMetaRef` 里的 meta 也 delete 了**。startDelegate 流程：`meta.set()` → `schedule()` → 立即 `meta.delete()` → 2 秒后 poll 执行时 meta 缺失 → **直接 return 且不再续期** → 轮询链一次性死亡。轮询循环内每次 reschedule 也清 meta（同样的坑）。meta 缺失分支没有重试/续期，静默死亡。
- 附带缺陷（同文件）：`updateProgress` 无上限追加 `entry.progress`（方案曾承诺 8 条上限，实际未实现，长任务数组无界增长）。
- 相关代码：`hooks/useSubtask.ts` 的 `scheduleSubTaskPoll` / `clearSubTaskPoll` / `pollSubTask` / `updateProgress`。

### 问题 4：对话中没有展示工具调用状态
- 证据：events.log 主会话（ctx_20260902_190055 / _191432）`agent/tool-result`、`agent/final-answer` 等事件 **listeners=0**；headless 发「现在几点」→ run.log 有 `tool-start get_time`（工具真执行了），但页面 `toolCards: []`。对比：子 context（agt_20260902_190104）同样事件 **listeners=1**（serve 转发生效）。
- 根因：`serve.py` ServeTransport 只在①启动时遍历存量 context、②包装 `manager.register` 时 attach 事件转发；**Gateway `session/create` 新建的主 context 走 `manager.register(role="main")`，但实测 attach 未生效**（主 context 的事件总线上没有 serve 的 5 个监听器）——机制待修复时对照 sub 路径实测确认（可能 register 包装在运行中被覆盖，或主 context 的 context.events 与 agent 实际 emit 的总线实例不一致——与 2026-09-02 子任务 EventBus 实例不匹配是同一家族 bug，见 skill ref）。
- 影响面：`item/toolCall` / `item/toolResult` / `turn/end` 全链路死 → 工具卡片、turn 结束兜底都失效（running 状态目前只靠 reply 兜底清除）。
- 相关代码：`qi_agent/serve.py`（_attach_context / _wrap_manager_register）、`qi_agent/gateway/gateway.py`（_create_session / _resume_session）。

## 二、修复设计

### 修复 1：气泡操作按钮统一为「悬浮图标组」（产品设计）
- 视觉规范：所有操作按钮（复制/编辑/重试）统一成**内联 SVG 图标按钮**（复制=方框+方框、编辑=铅笔、重试=环形箭头），图标 16×16，按钮 26×26 圆角 8px；**不再用文字标签**（CJK 宽度导致换行的根因），悬停提示用现有 i18n title（复制消息/编辑/重试）。
- 位置与显现：一组按钮绝对定位于气泡内右上角（top:6px right:6px），`.bubble-wrap:hover / :focus-within` 时显现（沿用现有 opacity/translateY 过渡）；**删除 `.bubble` 的 `padding-right: 42px` 预留**，内边距恢复对称 12px 14px（按钮悬浮在内容之上只在 hover 出现，不占位）。
- 角色差异：复制=所有非 system 气泡；编辑=user 气泡；重试=user 且 error 变体。user 渐变气泡上的按钮用半透明白底（不透明度约 0.9）+ 深色图标，assistant/工具类气泡用现有面板色 ghost 样式。
- 兼容触屏（hover:none）：操作按钮常显（降低不透明度至 0.55），保证无 hover 设备可操作。
- 布局纪律：按钮 `flex: none` + 图标无文本 → 结构上不可能换行；absolute 不参与文档流 → 不影响虚拟列表高度测量（ResizeObserver 已覆盖内容变化）。

### 修复 2：子任务结果展示（产品策略）
- **completed：默认展开全文**（结果=交付物；过程才需要折叠）。`SubTaskCard` 改：completed 时 `expanded` 默认 true；仅当结果超长（>800 字）时显示「收起/展开」切换，折叠态显示前 300 字预览。body 保留 CSS `max-height` + 内部滚动（长结果可滚到底，视为全文可达）。
- **终态集合补全**：轮询把 `need_more_info` 视为终态（状态文案「需补充信息」，展示 `summary` + `question`）；`stopped` 视为终态（文案「已停止」+ reason）；`timed_out` 保留现有前端语义（轮询自身超时）。
- 结果正文格式：`response.result` 为 object 时保留 pretty JSON（现状 stringifyValue），卡片头部加结果/原因字段名分隔，避免大 JSON 一坨无结构。

### 修复 3：轮询元数据生命周期（核心 bug）
- **职责拆分**：`clearSubTaskTimer(subId)`（只清 timer，不动 meta）+ `clearSubTaskPoll(subId)`（timer + meta 全清，仅终态/卸载时调用）。`scheduleSubTaskPoll` 改用前者。
- meta 生命周期：startDelegate 创建 → 轮询更新 → 终态（completed/failed/need_more_info/stopped/timed_out）或卸载时删除。
- **meta 缺失分支不静默死**：poll 若 meta 缺失，先检查该 subId 是否还有 entry（有→重建 meta 继续；无→停止），console.debug 留痕。
- 轮询循环内 reschedule 同样不再清 meta（同根因第二处）。
- `updateProgress` 追加进度行上限 50 条（超出丢最旧），对齐方案原「防刷爆」承诺。

### 修复 4：主 context 事件转发（serve 侧）
- 目标：新建主 context（session/create、session/resume 两条路径）保证 serve 事件监听器挂载，与子 context 行为一致（events.log 可见 listeners>0）。
- 实现方向（修复时先实测确认根因再选）：
  - A. Gateway 建主 context 后显式调用 transport 暴露的 attach（最直接、可测）；
  - B. 修 `_wrap_manager_register` 包装失效问题（若实测是包装被覆盖）；
  - C. 若根因是 EventBus 实例不匹配（主 agent 实际 emit 的总线 ≠ context.events），在 agent 装配处复用 context.events（与 delegate_task 修复同款 getattr 模式）。
- 验收必须含真实链路：起 serve + headless → 发触发工具的消息 → events.log 主 context 事件 listeners>0 → 页面出现工具卡片（运行中→完成）→ turn/end 到达后 running 清除。

## 四、验收标准

1. 修复 1：headless 截图核对——气泡右上角 hover 出现 SVG 图标组；无文字按钮、无 42px 预留空白；短消息（「你好」）内容宽度不再被挤压；按钮不换行。
2. 修复 2/3：headless 发 `/delegate 只回复：任务完成` → 卡片 running（进度行+计时）→ 子任务完成后 **≤6s 内状态变「已完成」并展示全文结果**（无需点击展开）；发一个必然 need_more_info 的目标（如「你好」）→ 终态显示「需补充信息」+ 摘要/question，不再卡 60s。
3. 修复 4：headless 发「现在几点」→ 对话流出现工具卡片（🔧 get_time → ✓ 完成）；rpc.log/events.log 佐证转发链路。
4. 回归：`PYTHONPATH= uv run pytest -q`（顺序执行，防 Windows tmp 死锁）全绿；`PYTHONPATH= uv run ruff check .` 干净；`npm run build` 通过。
5. 越界检查：`find qi_agent -newermt <任务开始时间>` 对比白名单（代码）+ 前端 dist 重建。
6. 手工复核：重启 serve（8765）+ web（9000）+ 新 build 后，用户在真实浏览器复测四项。

## 五、工业级落地考量（P0-9）

- **可靠性**：状态正确性靠轮询终态（修复 3 后恢复），进度推送/事件转发为尽力而为（通知单向增量、无重试，但 serve 转发修复后 turn/end 到齐可兜底 running 清除）；轮询 60s 无变化超时仍保留。
- **安全**：无新增权限面；通知内容为摘要/工具名，不含敏感参数全文（沿用现截断）。
- **记忆**：进度行/卡片不持久化（现状，裁剪声明：实时体验非审计）；会话恢复仍走 history（文本消息），工具/子任务卡片不恢复——本次不做，记 TODO。
- **可观测**：保留 console.debug 轮询诊断 + events.log 监听器计数（本次修复直接以 listeners 计数为验收依据）；serve 重启后 rpc.log/events.log 归零重记。
