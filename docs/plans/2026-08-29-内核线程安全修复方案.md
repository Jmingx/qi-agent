## 1. 背景

多线程化演进（后台 chat 线程 / AgentPool / 提炼线程 / gateway 层）后，并发问题集中在两类：

```
通信类：线程要【通知】另一线程 → 消息队列化（emit 保持单线程专用）
共享状态类：线程要【读写同一份数据】→ 少共享（队列化结构 / 锁 / 快照）
```

**核心判据**：并发问题不在"变量是否独立"，在"有几个线程碰它"——单线程独占 = 安全；多线程共享 = 竞态。

## 3. 修复方案

### 3.1 steer_queue → queue.Queue（context.py 4 处）

```python
import queue

# ① 定义：list → queue.Queue（put/get 原子，内部 Condition 锁）
self.steer_queue: queue.Queue[str] = queue.Queue()

# ② steer()：append → put（原子入队）
def steer(self, message: str) -> None:
    self.steer_queue.put(message)
    self.events.emit("subagent/steer", session_id=self.id, message=message)

# ③ drain_steer()：copy+clear → get_nowait 循环取空（不丢新入队的）
def drain_steer(self) -> list[str]:
    msgs: list[str] = []
    while True:
        try:
            msgs.append(self.steer_queue.get_nowait())
        except queue.Empty:
            break
    return msgs

# ④ reset()：clear → 重建队列（丢弃未消费指令，语义不变）
self.steer_queue = queue.Queue()
```

行为不变性：drain 语义 = "取走全部待处理指令"（等价且更准）；调用方接口不变。
测试点：控制线程连续 put 100 条 + worker 线程同时 drain，断言不丢一条。

### 3.3 status/result/phase 保护（context.py）

- 方案：context 内部加 RLock，protect complete/fail/stop 的状态读-判-写
- 或所有权声明：status/result 归"执行线程"独占写（stop 只 set _stop_flag，由循环线程检测后自己转换状态）——倾向此方案（改 stop() 一行：不直接写 status，留给循环线程处理）

### 3.4 跨线程 emit → 消息队列

- EventBus 记录 owner 线程；非 owner 线程 emit → fail-closed 报错
- 线程间通知（提炼回执/持久化结果/流式增量）走独立消息队列（每 agent 一个邮箱，主线程消费）
- 事件总线保持单线程语义（同步、有序、无锁）——不为并发付费

### 3.5 持久化/提炼快照化

- _persist：同步段先取 `msgs = list(context.messages[start:])` + 状态元组快照，后台线程只碰副本
- 触发点事件化：_persist/_maybe_extract_memory 从 run 返回后同步触发改为监听 turn-end 事件（与队列化统一）

### 3.6 压缩不动（已正确）

现状 = 异步算（post-llm 快照）+ pre-step 原子切换（循环线程内）——正是目标形态。**压缩改模型可见状态，写回必须同步原子**（脏数据不可接受：缓存失效 50 倍 + 角色交替破坏 + 已踩 400 事故）。

## 5. 工业级落地考量（P0-9）

- **可靠性**：修复后内核线程安全闭环（竞态消除）；持久化快照化后崩溃丢尾可接受（write-behind 语义不变）
- **安全**：控制面（steer/stop/审批）可靠性修复 = 安全属性（指令丢失会导致 agent 继续错方向执行）；审批表 uuid 防串线
- **记忆**：提炼快照化（读副本）与记忆注入无冲突
- **可观测**：消息队列可加队列深度指标（背压可见）；bus owner 检查报错留痕
