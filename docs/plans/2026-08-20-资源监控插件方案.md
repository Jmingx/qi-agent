## 1. 目标

监控 LLM 调用资源：**token 消耗 + 上下文窗口占用**，防止 token 浪费/上下文爆炸。
展示：每轮对话后状态行 + 会话结束汇总 + 接近窗口上限警告。

## 2. 设计

### 2.1 数据层（前置工作——usage 数据源不存在）

```
现状：ChatResult 无 usage 字段；LLMClient 丢弃了 API 响应的 usage
链路：DeepSeek API 响应 JSON 每次带 usage（OpenAI 兼容）
      → openai SDK 解析为 response.usage（prompt_tokens/completion_tokens/total_tokens）
      → 我们透传到 ChatResult.usage（新字段）
```

**两个取值路径**（agent 主循环都走）：

| 路径 | 现状 | 改造 |
|------|------|------|
| `chat()`（无回调） | response.usage 可直接取 | 构造 ChatResult 时透传 |
| `chat_stream()`（CLI 流式） | **流式默认不带 usage** | 请求加 `stream_options={"include_usage": True}`；usage 在**最后一个 chunk**（choices 为空的那个） |

**流式关键坑**：当前 `for chunk in stream: delta = chunk.choices[0].delta`——
最后一个 chunk **choices 为空**（纯 usage 携带者）→ `chunk.choices[0]` 会 IndexError！
改造时必须先判断 `chunk.choices` 非空，再取 usage。

### 2.2 ChatResult 扩展

```python
@dataclass
class ChatResult:
    content: str | None
    tool_calls: list[ToolCall] | None
    assistant_message: dict = field(default_factory=dict)
    usage: dict | None = None   # {"prompt_tokens": N, "completion_tokens": N, "total_tokens": N}
```

**prompt_tokens 即上下文窗口占用**（输入 token = 系统+历史+本轮，API 准确值，
零估算成本）。

### 2.3 插件 resource_monitor

```python
# qi_agent/plugins/resource_monitor.py（~90 行）
class ResourceMonitorPlugin:
    """资源监控：token 消耗 + 上下文占用（阶段 1）。

    - 监听 agent/post-llm（每次 LLM 调用后触发，含 result.usage）
    - 累积：total_tokens 累加（成本）；prompt_tokens 取最新（上下文占用）
    - 展示（决策点 2）：每轮状态行 / 会话结束汇总 / 接近上限警告
    - 静默模式（评测/自动化）：只累积不打印（不污染评测输出）
    """

    def __init__(self, config=None):
        self.usage_history: list[dict] = []
        self.total_tokens = 0
        self.quiet = bool(config.get("quiet", False))  # 评测场景静默

    def install(self, bus):
        bus.on("agent/post-llm", self._on_post_llm, priority=100)

    def _on_post_llm(self, result, **_) -> None:
        usage = getattr(result, "usage", None)
        if not usage:
            return  # 无 usage 数据（如旧响应）不崩溃
        self.usage_history.append(usage)
        self.total_tokens += usage.get("total_tokens", 0)
        if not self.quiet:
            self._print_status(usage)

    def _print_status(self, usage) -> None:
        """每轮状态行：[资源] 上下文 12,345/64,000 (19%) · 本轮 890 · 累计 45,678"""
        pct = usage["prompt_tokens"] / _CONTEXT_LIMIT * 100
        line = (f"[资源] 上下文 {usage['prompt_tokens']:,}/{_CONTEXT_LIMIT:,}"
                f" ({pct:.0f}%) · 本轮 {usage['total_tokens']:,}"
                f" · 累计 {self.total_tokens:,}")
        if pct >= 80:  # 接近上限警告（防上下文爆炸）
            line += " ⚠️ 接近上下文上限，建议 clear 或压缩"
        print(line, flush=True)

    def report(self) -> str:
        """会话结束汇总（CLI 退出时打印，tool_stats 模式）。"""
        ...
```

**上限配置**：`_CONTEXT_LIMIT` 环境变量 `QI_CONTEXT_LIMIT`（默认 64000——
DeepSeek chat 上下文，可配）。80% 触发警告。

### 2.4 评测适配（build_agent interactive=False）

- 评测 runner 用 `build_agent(interactive=False)`——resource_monitor **不装配**（同
  approval_gate 模式）→ 评测输出零污染
- 或插件 quiet 模式（配置）——二选一（方案倾向：不装配，与 approval_gate 一致）

### 2.5 CLI 展示位置

```
每轮 LLM 调用后（post-llm 事件）→ 插件打印状态行（流式打字机结束后）
agent> ...（回答）...
[资源] 上下文 12,345/64,000 (19%) · 本轮 890 · 累计 45,678
你> _
```

## 6. 附录：TUI / Web 终端预研（阶段 2+，写 TODO）

**现状**：CLI 纯 print REPL——无法固定状态栏（追加滚动式输出）。

**阶段 2：prompt_toolkit TUI（Hermes 路线）**
- Hermes 实测：Application + layout（status bar/输入框/分隔线）+ refresh_interval
  实时刷新 + erase_when_done 退出清理 + resize 处理——完整机制
- 收益：状态栏固定底部（token/上下文/权限模式实时刷新）、多行输入、历史补全
- 代价：CLI 重构为 Application 事件循环（大工程）、新依赖 prompt_toolkit
- 我们的资源监控数据（usage）届时直接喂给状态栏——阶段 1 数据层是阶段 2 的地基

**阶段 3：Web 终端（网关模式）**
- Hermes gateway 架构参考：agent 核心 + WebSocket 界面（浏览器里对话）
- 收益：多端访问（浏览器/手机）、远程使用
- 代价：网关服务（会话管理/并发/认证）——最大的工程
- 关键：agent 核心不变——事件点（post-llm 等）+ 插件（resource_monitor）天然跨界面；
  展示层替换即可（print → 状态栏 → WebSocket 推送）

**演进路径**：CLI(print) → TUI(prompt_toolkit) → Web(gateway)——
**数据层（usage/事件点）先行，界面层逐级替换，agent 核心零改动**。
