## 1. 目标

run_python 主防线从 v1（静态特征扫描）升级为 v2（RestrictedPython 受限执行），
解决 v1 的"诚实局限"：字符串拼接/反射/白名单外模块绕过。

**新增依赖**：`RestrictedPython`（纯 Python，Zope 社区维护，无重依赖）——P1-4 需评审的新增依赖。

## 2. 设计原理（回顾 principles/09）

```
v1 黑名单：   默认全放行 → 拦已知特征     → "impo"+"rt os" 拼接绕过 ❌
v2 受限环境： 默认全拒绝 → 只给安全的东西  → AST 重写 + 受限内建，拼接无效 ✅
```

关键机制（详见 principles/09）：
- **AST 重写**（编译期）：`import x` → `_import_('x')`、`obj.attr` → `_getattr(obj,'attr')`——制造"必经之路"
- **受限运行时**（执行期）：受限内建集（无 open/eval/exec/__import__）+ 守卫函数（双下划线属性受限）
- **双保险**：编译期改写（绕不过）+ 运行期守卫（改写的也要过检）

## 3. 设计

### 3.1 执行架构：受限执行器放子进程（_sandbox_runner.py）

**关键决策**：v2 的受限执行**全部在子进程内完成**（与 v1 的"子进程隔离"哲学一致）：

```
父进程（run_python.py）                    子进程（_sandbox_runner.py）
─────────────────────                    ──────────────────────────
① v1 静态扫描（快速预检，保留）             ① 读用户代码（stdin）
② 子进程管理（env 双重过滤/超时/编码）  →   ② compile_restricted（AST 重写）
③ 输出截断/回填                         ←   ③ 受限环境 exec
                                            ④ 输出（stdout）
```

- 父进程只做"进程管理"（env 白名单/超时/编码/截断——v0.4.2~v0.4.12 的成果全保留）
- 受限执行（编译 + 守卫 + 受限内建）在子进程隔离，**主进程不碰不可信代码**

```python
# 新文件 qi_agent/tools/_sandbox_runner.py（子进程入口，不注册为工具）
"""子进程受限执行器：RestrictedPython 编译 + 受限环境 exec。

由 run_python 以子进程方式调用（sys.stdin 传用户代码），
与主进程隔离——不可信代码只在受限子进程内编译执行。
"""

import sys

from RestrictedPython import compile_restricted, safe_builtins

# 受限内建：safe_builtins + 允许 print（输出结果必需）
_SAFE_BUILTINS = dict(safe_builtins)
_SAFE_BUILTINS["print"] = print
_SAFE_BUILTINS["len"] = len
_SAFE_BUILTINS["range"] = range
_SAFE_BUILTINS["str"] = str
_SAFE_BUILTINS["int"] = int
_SAFE_BUILTINS["float"] = float
_SAFE_BUILTINS["abs"] = abs
_SAFE_BUILTINS["round"] = round
_SAFE_BUILTINS["min"] = min
_SAFE_BUILTINS["max"] = max
_SAFE_BUILTINS["sum"] = sum
# 注意：不加入 open/eval/exec/__import__/getattr/setattr——攻击面最小化

def main() -> None:
    code = sys.stdin.read()
    try:
        bytecode = compile_restricted(code, "<sandbox>", "exec")
    except SyntaxError as exc:
        print(f"[错误] 代码编译失败: {exc}")
        return
    safe_globals = {
        "__builtins__": _SAFE_BUILTINS,
        "_getattr_": None,  # 保持 RestrictedPython 默认守卫（不覆盖）
    }
    try:
        exec(bytecode, safe_globals)  # noqa: S102 受限环境 exec（这正是沙箱目的）
    except Exception as exc:  # 用户代码异常 → 返回错误信息（不中断）
        print(f"[错误] 执行失败: {type(exc).__name__}: {exc}")


if __name__ == "__main__":
    main()
```

### 3.2 run_python.py 改造

```python
# 子进程命令从：
subprocess.run([sys.executable, "-X", "utf8", "-c", code], ...)
# 改为：
subprocess.run(
    [sys.executable, "-X", "utf8", _SANDBOX_RUNNER_PATH],
    input=code,          # 用户代码走 stdin（避免命令行长度/转义问题）
    capture_output=True, text=True,
    encoding="utf-8", errors="replace",
    timeout=_TIMEOUT_SECONDS, env=_build_safe_env(),
)
```

**保留 v1 静态扫描**（决策点 1：双层策略）：
- 第一层：v1 特征扫描（快速预检——明显恶意代码直接拒，省子进程）
- 第二层：v2 受限执行（兜底一切——拼接/反射/未知攻击面）

## 8. 风险与说明

- **依赖引入**：RestrictedPython 是纯 Python 库（无 C 扩展），uv 安装无坑；Zope 社区维护数十年，API 稳定
- **受限内建集的取舍**：只加"计算结果必需"的内建（print/len/range/数值函数），**不加 getattr/setattr/__import__**——攻击面最小化；将来需要更多内建时按需评审添加
- **双下划线属性受限**：依赖元类/__class__ 的代码跑不了（LLM 生成的计算代码通常用不到，可接受）
- **v1 保留的代价**：静态扫描与 v2 有少量重复（双层防御的冗余，代价可忽略）——将来 v1 稳定退役（YAGNI 现在不撤）
- **不做的**：v3 资源限制（psutil 内存监控）留下一步；RestrictedPython 守卫不做自定义放宽（保持默认严格）
