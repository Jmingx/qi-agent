## 1. 目标

run_python 主防线从 v1（静态特征扫描）升级为 v2（RestrictedPython 受限执行），
解决 v1 的"诚实局限"：字符串拼接/反射/白名单外模块绕过。

**新增依赖**：`RestrictedPython`（纯 Python，Zope 社区维护，无重依赖）——P1-4 需评审的新增依赖。

## 2. 设计原理（回顾 principles/09）

```
v1 黑名单：   默认全放行 → 拦已知特征     → "impo"+"rt os" 拼接绕过 ❌
v2 受限环境： 默认全拒绝 → 只给安全的东西  → AST 重写 + 受限内建，拼接无效 ✅
```

关键机制（详见 principles/09）：
- **AST 重写**（编译期）：`import x` → `_import_('x')`、`obj.attr` → `_getattr(obj,'attr')`——制造"必经之路"
- **受限运行时**（执行期）：受限内建集（无 open/eval/exec/__import__）+ 守卫函数（双下划线属性受限）
- **双保险**：编译期改写（绕不过）+ 运行期守卫（改写的也要过检）

**Hermes 对照**（用户提问查证）：Hermes 没有 RestrictedPython——它走"环境隔离 + 7 工具出口白名单"
（子进程 + AF_UNIX RPC），但 AF_UNIX 在 Windows Python 不可靠（源码注释原话），我们选
RestrictedPython 是"纯 Python 跨平台"的务实选择。

## 3. 设计

### 3.1 执行架构：受限执行器放子进程（_sandbox_runner.py）

**关键决策**：v2 的受限执行**全部在子进程内完成**（与 v1 的"子进程隔离"哲学一致）：

```
父进程（run_python.py）                    子进程（_sandbox_runner.py）
─────────────────────                    ──────────────────────────
① 模式开关：restricted（默认）/legacy      ① 读用户代码（stdin）
② v1 静态扫描（快速预检，保留）             ② compile_restricted（AST 重写）
③ 子进程管理（env 双重过滤/超时/编码）  →   ③ 受限环境 exec（受限内建+import白名单）
④ 输出截断/回填                         ←   ④ 输出（stdout）
```

- 父进程只做"进程管理"（env 白名单/超时/编码/截断——v0.4.2~v0.4.12 的成果全保留）
- 受限执行（编译 + 守卫 + 受限内建）在子进程隔离，**主进程不碰不可信代码**

### 3.2 执行模式开关（用户决策：支持动态降级/关闭）

```python
# run_python.py 顶部（进程启动时读取一次，.env 可配）
_SANDBOX_MODE = os.getenv("QI_SANDBOX_MODE", "restricted").strip().lower()
if _SANDBOX_MODE not in ("restricted", "legacy"):
    _SANDBOX_MODE = "restricted"   # 未知值回落最安全默认
```

| 模式 | 执行路径 | 安全性 | 用途 |
|------|---------|--------|------|
| `restricted`（默认） | v1 预检 + v2 受限执行 | 最安全（拼接/反射/未知面全拦） | 常规 |
| `legacy`（显式降级） | v1 预检 + 完整 Python（现状路径） | v1 绕过风险（用户知情放宽） | 受限代码跑不了时临时回退 |

**安全边界（P0）**：legacy 有 v1 的绕过风险，**默认必须 restricted**；legacy 是
"用户知情的显式放宽"——对齐"安全底线硬编码 + 用户决策配置化"哲学（类似 Hermes YOLO 模式）。
"动态"= 启动时配置即生效（.env 改一行），非运行时热切换。

### 3.3 受限内建集 + import 白名单（用户决策：配置化，按需放行）

**两层结构：硬编码安全底线 + 环境变量按需扩展**

```python
# _sandbox_runner.py
import os

# ── 可放行清单（用户能扩展的"上限"——只含无副作用的纯计算能力）──
# 无论配置什么，open/eval/exec/__import__/os/sys 都不在此清单 → 永远进不来
_ALLOWED_EXTRA_BUILTINS = ("round", "pow", "divmod", "isinstance")
_ALLOWED_EXTRA_MODULES = ("math", "random", "json", "statistics", "fractions", "decimal")

# ── 默认安全内建（硬编码底线）──
_SAFE_BUILTINS = dict(safe_builtins)
_SAFE_BUILTINS.update({
    "print": print, "len": len, "range": range,
    "str": str, "int": int, "float": float,
    "abs": abs, "round": round, "min": min, "max": max, "sum": sum,
})

# ── import 白名单（默认空 = import 全禁）──
_SAFE_MODULES: tuple[str, ...] = ()

def _load_config() -> None:
    """从环境变量读取用户扩展（按需放行，默认保持最严格）。"""
    # QI_SANDBOX_EXTRA_BUILTINS=round,pow
    for name in os.getenv("QI_SANDBOX_EXTRA_BUILTINS", "").split(","):
        name = name.strip()
        if name in _ALLOWED_EXTRA_BUILTINS:
            _SAFE_BUILTINS[name] = globals().get(name)
    # QI_SANDBOX_EXTRA_MODULES=math,random
    _SAFE_MODULES = tuple(
        m.strip() for m in os.getenv("QI_SANDBOX_EXTRA_MODULES", "").split(",")
        if m.strip() in _ALLOWED_EXTRA_MODULES
    )

# ── 受限 import 守卫：只放行白名单模块 ──
def _guarded_import(name, *args, **kwargs):
    if name not in _SAFE_MODULES:
        raise ImportError(f"模块 {name} 不在沙箱白名单")
    return __import__(name, *args, **kwargs)
```

**关键设计**：
- 用户扩展**有上限**：`_ALLOWED_EXTRA_*` 决定"能放行什么"（math/json/random 纯计算）
- **安全底线不变**：open/eval/exec/os/sys 永远不在可放行清单——配置再宽松也进不来
- 默认（不配置）= 最严格（内建集最小 + import 全禁）
- 将来阶段 4 config.yaml 接入时，环境变量源换成配置文件（接口不变）

### 3.4 run_python.py 子进程调用改造

```python
# restricted 模式：受限执行器 + stdin 传码（用户代码走 stdin，避免命令行长度/转义）
# legacy 模式：完整 Python（现状路径，v1 静态扫描已预检）
if _SANDBOX_MODE == "legacy":
    result = subprocess.run(
        [sys.executable, "-X", "utf8", "-c", code],
        capture_output=True, text=True,
        encoding="utf-8", errors="replace",
        timeout=_TIMEOUT_SECONDS, env=_build_safe_env(),
    )
else:
    result = subprocess.run(
        [sys.executable, "-X", "utf8", _SANDBOX_RUNNER_PATH],
        input=code,
        capture_output=True, text=True,
        encoding="utf-8", errors="replace",
        timeout=_TIMEOUT_SECONDS, env=_build_safe_env(),
    )
```

## 8. 风险与说明

- **依赖引入**：RestrictedPython 纯 Python 无 C 扩展，uv 安装无坑；Zope 社区维护数十年，API 稳定
- **受限内建集的可放行上限**：`_ALLOWED_EXTRA_*` 只含纯计算能力——即使配置失误，open/eval/os/sys 也进不来（安全底线硬编码）
- **legacy 模式风险**：回到 v1 绕过风险——默认 restricted，legacy 需显式配置（.env 写 QI_SANDBOX_MODE=legacy）
- **双下划线属性受限**：依赖元类/__class__ 的代码跑不了（LLM 生成的计算代码通常用不到，可接受）
- **v1 保留的代价**：静态扫描与 v2 少量重复（双层防御冗余，代价可忽略）
- **不做的**：v3 资源限制（psutil 内存监控）留下一步；RestrictedPython 守卫不做自定义放宽（保持默认严格）
