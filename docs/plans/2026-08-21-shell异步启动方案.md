# shell 工具异步启动方案：background 参数（常驻进程立即返回）

> **状态:** ✅ 已评审通过（2026-08-21，决策点 1-4 用户整体批准）
> **作者:** Hermes（qi-agent 开发会话）
> **日期:** 2026-08-21
> **前置:** v0.4.22 + shell 超时死锁修复（2026-08-21，Popen+communicate+杀进程树）
> **背景:** 用户问"常驻进程没法立刻返回吗"——超时杀是事后补救，异步启动才是事前正确

---

## 1. 目标

常驻进程（游戏/服务器/长驻程序）启动时**立即返回**，不阻塞 agent 对话。
对齐 Hermes terminal 工具的 `background=true` 参数。

## 2. 设计

### 2.1 接口

```python
def shell(command: str, approved: bool = False, background: bool = False) -> str:
    """
    background=False（默认）：同步执行 + 超时兜底（现状，安全网保留）
    background=True：异步启动常驻程序，立即返回
    """
```

- 安全链不变：白名单/危险关键词/审批在函数开头统一处理（approved 判断已有），
  **background 只是执行方式不同**，不绕过任何检查
- schema 增加 `background`（boolean，默认 false，模型可见）

### 2.2 异步路径

```python
if background:
    creationflags = 0
    if sys.platform == "win32":
        # Windows detach：完全脱离控制台 + 独立进程组
        # （GUI 程序无控制台概念无副作用；控制台程序后台运行无窗口）
        creationflags = subprocess.DETACHED_PROCESS | subprocess.CREATE_NEW_PROCESS_GROUP
    proc = subprocess.Popen(
        command,
        shell=True,
        stdout=subprocess.DEVNULL,   # 断管道：防 64KB 缓冲写满阻塞子进程（Java 经典死锁）
        stderr=subprocess.DEVNULL,
        creationflags=creationflags,
    )
    return f"[已启动] PID {proc.pid}（异步运行，不阻塞对话）"
```

**三个技术要点**：
1. **不等待**：Popen 后不 `communicate()`/`wait()`——立即返回 PID
2. **断管道**（DEVNULL）：输出没人读 → 缓冲写满 → 子进程阻塞在 write 假死；
   必须断管道，子进程才真正自由
3. **detach**：DETACHED_PROCESS 让程序完全脱离 agent 会话——agent 退出后
   游戏继续跑（不会跟着 agent 被收走）；非 Windows 平台跳过标志（无此概念）

### 2.3 超时兜底与 background 的关系

| 模式 | 行为 | 适用 |
|------|------|------|
| `background=false`（默认） | 同步等待 + 10s 超时 + 杀进程树 | 普通命令（dir/type/echo） |
| `background=true` | 立即返回"已启动 PID" | 游戏/服务器/长驻程序 |

- 同步路径保留超时兜底（安全网：模型忘用 background 时 10s 恢复不死锁）
- 异步路径**不设超时**（语义就是放手让它跑）

## 5. 决策点（评审）

| # | 决策点 | 方案 |
|---|--------|------|
| 1 | 异步接口形式 | `shell(command, background=True)` 参数（对齐 Hermes terminal background） |
| 2 | detach 方式（Windows） | `DETACHED_PROCESS`（完全后台，无窗口）——备选 `CREATE_NEW_CONSOLE`（独立窗口，适合要看日志的控制台程序） |
| 3 | 输出处理 | DEVNULL 丢弃（最简单，防缓冲死锁）——日志文件重定向留 TODO（进阶） |
| 4 | 生命周期 | 启动即放手，不跟踪（返回 PID 供参考）；kill 管理留 TODO |
