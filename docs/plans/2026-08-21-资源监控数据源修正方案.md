## 1. 问题：实测 DeepSeek 流式不返回 usage（数据源失效）

**现象**：CLI 正常对话（"你好"→ 模型回复），但资源监控状态行从未出现，退出报告显示"本次会话无 LLM 调用"——`usage_history` 恒为空。

**证据链（2026-08-21 实测 13+ 次）**：

| 实验 | 结果 |
|------|------|
| curl 原始 SSE（`stream_options: {"include_usage": true}`） | 流直接 `data: [DONE]` 结束，**响应无 usage 字段** |
| `deepseek-v4-flash` 流式 × 3 | 全部无 usage chunk |
| `deepseek-chat` 流式 × 3 | 全部无 usage chunk |
| **非流式 `chat()` × 3** | **100% 稳定返回** `{prompt_tokens, completion_tokens, total_tokens}` |

**结论**：DeepSeek 服务端接受 `stream_options` 参数但**基本不实现**其语义（13 次中仅最初 2 次偶发返回，~15%）。这不是 qi-agent 代码 bug——提取逻辑（`not chunk.choices` → 取 usage）与 Hermes 完全一致，是**上游数据源不可靠**。

## 2. 业界对照（项目规范：设计前查 Hermes 真实源码 + DSH）

| | Hermes | DSH（deepseek-harness token-meter） |
|---|---|---|
| 流式 usage 提取 | `chat_completion_helpers.py:2771` `if not chunk.choices: usage_obj = chunk.usage`（与 qi-agent 同款写法） | 流式 `chunk.type === 'usage'` 事件 + 非流式 `assistant/message.usage` |
| usage 缺失兜底 | **无**（None 就 None，不展示故影响小） | **双层**：真实样本 + 估算投影 |
| 估算机制 | — | `estimate.ts`：`CHARS_PER_TOKEN=4` + `BLOCK_OVERHEAD=4` + `ROLE_OVERHEAD=4`，消息逐条计价，O(1) 增量维护 surface |
| 样本校准 | — | `projectedTokens = pressureTokens + surfaceTokens − sampledSurfaceTokens`（真实样本作锚点 + 自锚点以来消息增量） |
| 成本统计 | 有 usage 才记 | totals 桶只收真实样本 |

**DSH 的答案**：接受流式可能不给 usage 的现实，用"估算 + 样本校准"兜底，**不花钱补请求**（业界无"双调用补 usage"先例）。

## 3. 决策：方案 D（DSH 式混合）——用户 2026-08-21 批准

| 备选 | 做法 | 成本 | 评价 |
|------|------|------|------|
| A. 按需补非流式 | 流式拿不到 usage 就补发非流式请求 | ~2× | 数据 100% 准，但成本翻倍，业界无此做法 |
| B. 全改非流式 + 伪打字机 | 非流式拿全文，CLI 逐字播放 | 1× | 首字延迟变长，打字机失真 |
| C. 纯估算 | 字符数/4 直接估 | 1× | 最简单，无校准，精度最低 |
| **D. DSH 式混合** ✅ | 真实样本优先；缺失时锚点校准估算 | 1× | **零额外成本；DeepSeek 修复后自动全准；业界同款** |

## 4. 设计

### 4.1 估算函数（resource_monitor.py 模块级，DSH estimate.ts 同款思路）

```python
# 固定密度启发式（DSH estimate.ts 同款参数，中英混合可接受 ±20% 误差）
_CHARS_PER_TOKEN = 4   # 4 字符 ≈ 1 token
_MSG_OVERHEAD = 4      # 每条消息 JSON 结构开销（role 字段等）

def estimate_messages(messages: list[dict]) -> int:
    """估算消息列表的 prompt tokens（无真实 usage 时的兜底）。"""
    total = 0
    for msg in messages:
        total += _MSG_OVERHEAD
        content = msg.get("content") or ""
        total += (len(content) + _CHARS_PER_TOKEN - 1) // _CHARS_PER_TOKEN  # ceil
        for tc in msg.get("tool_calls") or []:  # 工具调用消息额外计价
            fn = tc.get("function", {})
            total += (len(fn.get("name") or "") + _CHARS_PER_TOKEN - 1) // _CHARS_PER_TOKEN
            total += (len(fn.get("arguments") or "") + _CHARS_PER_TOKEN - 1) // _CHARS_PER_TOKEN
    return total
```

### 4.2 锚点校准（DSH projectedTokens 语义）

```
有真实样本:  prompt = usage.prompt_tokens（API 准确值）
             锚点更新: anchor_prompt = usage.prompt_tokens; anchor_surface = estimate_messages(本轮 messages)
无样本有锚点: prompt = anchor_prompt + (estimate_messages(当前) − anchor_surface)   # 样本 + 增量
无样本无锚点: prompt = estimate_messages(当前)                                     # 纯估算
```

- `messages` 是 post-llm 事件新增 payload（agent.py 传 `self.messages`）——**数据源补齐**（同 v0.4.22 教训：插件需要的数据源要现造，本次是 messages 列表）
- **事件点兼容性**：`EventBus.emit` 用 `handler(**data)` 关键字分发——post-llm 当前只有 resource_monitor 一个监听者且签名 `(result, **_）`，加 `messages` 安全；将来新监听器必须接受 `**kwargs`

### 4.3 每轮统计（真实 + 估算分账）

| 字段 | 真实样本轮 | 估算轮 |
|------|-----------|--------|
| `usage_history` | append usage（真实样本列表，语义不变） | 不 append |
| `total_tokens` | += usage.total_tokens | += est_prompt + est_completion（est_completion = `len(result.content or "")/4`） |
| `estimated_calls` | 不变 | += 1 |
| 状态行 | `[资源] 上下文 12,345/64,000 (19%) · 本轮 890 · 累计 45,678`（原格式） | 估算值加 `~` 前缀：`上下文 ~12,345/64,000 (~19%) · 本轮 ~890` |

**诚实标注原则**：估算值一律 `~` 前缀（用户要求诚实技术评估；估算轮不冒充真实值）。

### 4.4 边界

- `messages=None`（测试直调/旧调用方）：**有 usage 走真实分支（不依赖 messages）；无 usage 则跳过**（不崩溃，与现状一致）——现有测试零破坏
- 无任何样本也无估算：report 保持"本次会话无 LLM 调用"
- report 兼容：真实样本场景格式不变（"累计"/"N 次调用"/千分位），估算存在时追加 ` · 含估算 N 轮（~ 标注）`

### 4.5 agent.py 事件点改动（一行）

```python
# agent.py 第 91 行：post-llm 增加 messages payload（resource_monitor 估算数据源）
self.events.emit("agent/post-llm", result=result, messages=self.messages, turn=self._turn, step=step)
```

**零侵入验证**：改后先不加任何插件跑全量旧测试（现有监听器 `**_` 兼容；无监听器时 emit 无副作用）。
