## 1. 目标

在 agent 主循环的关键位置提供**插件扩展点**，让工具统计、审批、防护、日志等能力可以以"监听插件"形式接入，**无插件时行为与现在完全一致**（向后兼容）。这是"一切皆插件"（DSH 架构）的第一块地基。

### 1.1 为什么现在做（时机论证）

- 工具调用统计（P1）、成本追踪（P2）、prompt injection 防护（P1）等 TODO 条目**都需要事件点**——事件化是它们的公共前置
- 现在架构小（agent.py 117 行、90 测试），改造风险低；等代码膨胀后再加事件点，侵入面更大
- 立即落地一个真实插件（工具统计）验证机制有效性，避免"为架构而架构"

### 1.2 为什么不做全插件化（档位 C）

- Python 生态无 Cordis 等价物（pluggy 只有钩子语义，无生命周期/服务注册/作用域）
- 自研容器 = 数周工作量 + 重写全部代码，对当前阶段（工具调用深化中）是过度设计（YAGNI）
- 档位 A 是 C 的地基，先立地基，架构稳定后（阶段 5）再决定是否上 C

## 2. 设计原理（导师讲解）

### 2.1 核心认知：agent 循环需要的是"钩子语义"

主循环单线程顺序执行，**必须等外部代码的返回值来决定下一步**（如审批插件说"拒绝"→ 循环必须改变行为）。这要求扩展点**同步 + 有返回值**——即钩子语义，而非严格意义的事件驱动（异步发完就跑）。详见 principles/07。

### 2.2 解法：一套事件总线，三种分发模式

借鉴 DSH（Cordis）"接口统一、分发模式区分"的设计：

| 分发模式 | 语义 | 本项目用途 |
|---------|------|-----------|
| `emit` | 广播通知，忽略返回值 | 状态/统计/日志（agent/turn-start、agent/final-answer） |
| `waterfall` | 返回值喂给下一个监听者，最终结果回传发布者 | 数据改写（agent/pre-step 注入上下文） |
| `bail` | 第一个非 None 返回即停止 | 决策（agent/tool-call 审批/拦截） |

`parallel`（异步并行）延后——当前单线程场景无收益，Cordis 有它是因为要服务多租户 UI。

### 2.3 关键设计约束

1. **零侵入默认行为**：事件点没有监听者时零开销跳过（空列表判断），现有 90 测试全绿即验证
2. **事件名对齐 DSH**：`agent/turn-start`、`agent/pre-step`、`agent/tool-call`、`agent/final-answer`——与 DSH 同名同语义，将来对照源码无障碍
3. **优先级排序**：监听者注册时带 priority（默认 0，数值大先执行），保证"防护类插件"能排在"统计类"前面
4. **事件 payload 用 dataclass 而非 dict**：类型注解齐全（项目规范），错误在注册时暴露而非运行时

## 3. 设计

### 3.1 事件总线（新文件 qi_agent/events.py，~90 行）

```python
"""轻量事件总线：emit（通知）/ waterfall（改写）/ bail（决策）三种分发模式。"""

from dataclasses import dataclass, field
from typing import Any, Callable


@dataclass
class _Listener:
    handler: Callable
    priority: int = 0


class EventBus:
    """事件总线：插件注册监听器，主循环在事件点分发。

    三种分发模式（对应 Cordis 子集）：
    - emit(event, **data):       广播，忽略返回值（通知/统计）
    - waterfall(event, data):    返回值喂给下一个监听者，最终结果回传（改写）
    - bail(event, **data):       第一个非 None 返回即停止（决策）
    """

    def __init__(self) -> None:
        self._listeners: dict[str, list[_Listener]] = {}

    def on(self, event: str, handler: Callable, priority: int = 0) -> None:
        """注册监听器。priority 越大越先执行（默认 0）。"""
        self._listeners.setdefault(event, []).append(_Listener(handler, priority))
        # 按优先级降序排序，保证执行顺序稳定
        self._listeners[event].sort(key=lambda l: l.priority, reverse=True)

    def emit(self, event: str, **data: Any) -> None:
        """广播通知：所有监听者按序执行，返回值被忽略。"""
        for listener in self._listeners.get(event, []):
            listener.handler(**data)

    def waterfall(self, event: str, data: Any, **extra: Any) -> Any:
        """瀑布改写：data 依次经过每个监听者，返回值作为下一个的输入。"""
        for listener in self._listeners.get(event, []):
            data = listener.handler(data, **extra)
        return data

    def bail(self, event: str, **data: Any) -> Any:
        """短路决策：第一个返回非 None 的监听者决定结果。"""
        for listener in self._listeners.get(event, []):
            result = listener.handler(**data)
            if result is not None:
                return result
        return None
```

**设计说明**：
- `waterfall` 第一个参数是待改写数据（消息列表），`**extra` 传上下文（turn/step 等只读信息）
- `bail` 返回 None 表示"无决策，继续"——与 waterfall 的"无监听者原样返回"语义一致
- 单文件 ~90 行，无外部依赖

### 3.2 事件点定义（修改 qi_agent/agent.py）

对照当前循环，插入 7 个事件点：

| 事件 | 时机 | 模式 | payload | 用途 |
|------|------|------|---------|------|
| `agent/turn-start` | 收到用户输入后、循环前 | emit | `user_input` | 统计/日志 |
| `agent/pre-step` | 每次调 LLM 前 | waterfall | `messages`（可改写）+ `turn`/`step` | 注入上下文/改写历史 |
| `agent/post-llm` | LLM 响应后 | emit | `result`（ChatResult） | usage 跟踪/成本追踪 |
| `agent/tool-call` | 每个工具执行前 | bail | `name`/`arguments`/`turn`/`step` | 审批/拦截/统计 |
| `agent/tool-result` | 工具执行后 | emit | `name`/`arguments`/`output`/`duration` | 统计/审计 |
| `agent/final-answer` | 最终答案产生时 | emit | `content` | 观察/存储 |
| `agent/turn-end` | 每轮结束（含超限） | emit | `reason`（completed/超限） | 汇总 |

**agent.py 改造点（约 30 行变更）**：

```python
class Agent:
    def __init__(self, client, system_prompt=..., max_turns=8, logger=None,
                 events: EventBus | None = None) -> None:
        ...
        self.events = events or EventBus()   # 依赖注入，默认空总线（零影响）

    def chat(self, user_input, stream_callback=None) -> str:
        self.messages.append({"role": "user", "content": user_input})
        self.events.emit("agent/turn-start", user_input=user_input)
        if self.logger:
            self.logger.log_user_input(user_input)

        for step in range(self.max_turns):
            # 事件点：pre-step（可改写消息，如注入上下文）
            self.messages = self.events.waterfall(
                "agent/pre-step", self.messages, turn=..., step=step
            )
            ...  # 调 LLM（原逻辑不变）
            self.events.emit("agent/post-llm", result=result)

            if result.tool_calls:
                ...
                for call in result.tool_calls:
                    # 事件点：tool-call（决策：返回非 None 则用返回值替代执行）
                    decision = self.events.bail(
                        "agent/tool-call", name=call.name,
                        arguments=call.arguments, turn=..., step=step,
                    )
                    if decision is not None:
                        output = str(decision)   # 拦截结果回填给模型
                    else:
                        output = execute_tool(call.name, call.arguments)
                    self.events.emit("agent/tool-result",
                                     name=call.name, arguments=call.arguments,
                                     output=output, duration=...)
                    ...
            else:
                content = result.content or ""
                self.events.emit("agent/final-answer", content=content)
                return content

        self.events.emit("agent/turn-end", reason="max_turns")
        return "已达最大轮数，任务可能未完成。"
```

**注意**：
- `turn-start` 在 `logger.log_user_input` 之前触发（事件点统一在日志前，插件可以替代日志职责，未来 debugger 迁移为插件不冲突）
- `tool-call` bail 返回的值直接作为工具结果回填（拦截语义），模型会看到拦截原因——与现有 `[安全拦截]` 前缀的返回风格一致
- 事件点不改变任何原有行为路径，只增加调用

### 3.3 验证插件：工具调用统计（新文件 qi_agent/plugins/tool_stats.py，~50 行）

对应 TODO「工具调用统计」（P1）。功能：
- 记录每个工具：调用次数、总耗时、成功/失败数
- 会话结束时（`agent/turn-end` + CLI 退出钩子）汇总打印
- CLI 新增 `--stats` 参数启用

```python
"""工具调用统计插件：监听 agent/* 事件，汇总工具使用情况。"""

from dataclasses import dataclass, field

from qi_agent.events import EventBus


@dataclass
class ToolStats:
    """单个工具的统计信息。"""
    name: str
    calls: int = 0
    total_seconds: float = 0.0
    failures: int = 0


class ToolStatsPlugin:
    """统计插件：注册到事件总线，收集工具调用数据。"""

    def __init__(self) -> None:
        self._stats: dict[str, ToolStats] = {}
        self._start: float | None = None

    def install(self, bus: EventBus) -> None:
        """注册所有监听器（插件统一入口，便于将来容器化）。"""
        bus.on("agent/tool-call", self._on_tool_call, priority=100)   # 先于审批执行
        bus.on("agent/tool-result", self._on_tool_result)

    def _on_tool_call(self, name: str, **_) -> None:
        self._stats.setdefault(name, ToolStats(name=name))
        self._start = time.perf_counter()

    def _on_tool_result(self, name: str, output: str, **_) -> None:
        stat = self._stats.setdefault(name, ToolStats(name=name))
        stat.calls += 1
        if self._start is not None:
            stat.total_seconds += time.perf_counter() - self._start
        if output.startswith(("[工具错误]", "[参数错误]")):
            stat.failures += 1

    def report(self) -> str:
        """生成汇总报告文本。"""
        ...
```

**设计说明**：
- `install(bus)` 统一入口——插件将来变成"注册即卸载"（disposer 模式）时接口不变
- 统计插件用 `priority=100` 确保在审批类插件之前记录"被拦截的调用"也算一次尝试
- `--stats` 启用：`cli.py` 增加 argparse 参数，构造插件实例 + 注册到 agent 的事件总线

## 8. 风险与说明

- **行为变化风险**：事件点只在"有监听者"时产生效果，无监听者时仅多一次空列表遍历（纳秒级），现有 90 测试全绿即验证零侵入
- **过度设计风险**：7 个事件点已覆盖当前全部已知需求（统计/审批/防护/日志/上下文注入），不再增加；`parallel` 模式明确不做
- **waterfall 改写消息的风险**：pre-step 插件改坏消息历史可能破坏 role 交替——事件点文档注明"改写者责任自负"，且现有消息构造不受影响（waterfall 只对插件返回的结果负责）
- **与 debugger 的关系**：本期**不迁移** debugger（它经历了多轮显示调试，动它风险大于收益）；将来档位 B 时再评估
- **duration 测量**：tool-call 开始时间用模块级变量暂存（单线程安全）；多线程并发时需改 per-call 上下文——当前无并发，注释说明即可
