# codex-dev 模型自动回退方案（2026-09-01）

## 背景

- `~/.codex/config.toml` 当前模型 `gpt-5.4-mini`（reasoning high、service_tier priority）。
- 2026-09-01 实测：codex 启动提示「GPT-5.4 Mini will be deprecated soon，Codex now uses GPT-5.6 Luna in place of GPT-5.4 Mini」；config 中 OpenAI 官方已给迁移映射 `[notice.model_migrations] "gpt-5.4-mini" = "gpt-5.6-luna"`。
- 现状：codex_dev.py 已检测额度超限（QUOTA_PATTERNS → 立即 kill → EXIT_QUOTA 不重试）；但**模型不可用**未检测，且额度超限/模型不可用时没有自动切换模型重试。

## 目标

codex exec 因**模型不可用**或**额度超限**失败时，自动按回退链切换「恰当的 gpt 模型」重试；全部尝试失败才返回失败退出码。

## 设计

### 1. 模型回退链（去重，最多 3 个）

```
[--model 显式值 或 config.toml 当前模型]
  → [config.toml [notice.model_migrations] 迁移目标（如 gpt-5.4-mini → gpt-5.6-luna）]
  → [内置兜底 gpt-5.4]
```

- 迁移目标从 `~/.codex/config.toml` 读取（tomllib，零新依赖；读取失败/无表则跳过该项）。
- 内置兜底 `gpt-5.4` 是当前订阅可用高配模型（config 迁移映射 `gpt-5.3-codex → gpt-5.4` 佐证其可用）。
- 去重后不足 2 个则链就只有 1 个（无可切换时保持现状行为）。

### 2. 模型不可用检测（codex_dev_core.py EventParser）

新增 `MODEL_UNAVAILABLE_PATTERNS`（大小写不敏感，命中即标记 `model_unavailable: bool`）：

```
model not found / model .* does not exist / model .* not available
model .* deprecated / model .* not supported / invalid model
unable to load model / model .* unsupported
```

- 检测位置：`error` 事件 message、`turn.failed` error message（与额度检测同位置，`_check_quota` 旁新增 `_check_model_unavailable`）。
- `CodexResult` 增加 `model_unavailable: bool` 字段。

### 3. 重试循环（codex_dev.py main 流程改造）

- 把「单次 runner.run()」包成 for 循环遍历回退链：
  - 成功（无 quota/model 错误且事件正常）→ 跳出进入验收流程（现状逻辑不变）。
  - `quota_exceeded` 或 `model_unavailable` → 打印原因 → 记录本次尝试 → 换下一个模型重试。
  - 其他失败（超时/一般错误）→ **不重试**（现状行为不变，直接返回对应退出码）。
- 每个模型只试一次；链耗尽：
  - 最后原因是 quota → `EXIT_QUOTA`（3）
  - 最后原因是 model_unavailable → `EXIT_CODEX_FAIL`（2）
- 运行统计打印每个尝试：`[codex-dev] 模型 gpt-5.4-mini 额度超限 → 切换 gpt-5.6-luna 重试`。

### 4. state 记录（可观测）

`state["model_attempts"] = [{"model": ..., "reason": "quota|model_unavailable|ok", "exit_code": ...}]`，latest.json 可见完整切换过程。

### 5. 测试（codex-dev/tests/test_codex_dev.py 追加）

- 模型不可用错误消息（not found / deprecated / not supported 各一）→ `model_unavailable=True`。
- 模型不可用消息不误伤正常错误（如普通 "command failed" → False）。
- 回退链构造：给定 config 迁移映射 + 当前模型 → 正确顺序、去重。
- main 流程：quota → 切换重试 → 成功后继续验收（mock runner）。
- 链耗尽 → 返回 EXIT_QUOTA / EXIT_CODEX_FAIL。

## 诚实局限

- ChatGPT 订阅级限额（5h 窗口/周限额）是**账号全局**的，换模型大概率仍超限；但 rate limit 常是**模型级**（如 gpt-5.4-mini 被限），切换 gpt-5.6-luna 有机会成功。重试次数被链长限制（≤3），失败立即被检测 kill，成本低。
- 内置兜底模型列表是硬编码猜测，若 OpenAI 后续调整模型名，可能需要维护——回退链以 config 迁移映射为主，内置兜底只是最后手段。

## 工业级落地考量（P0-9 四横切线简评）

- **可靠性**：重试有界（≤3 次/每模型一次），防死循环；失败原因与尝试记录落 state 文件，可审计。
- **安全**：不新增命令执行面，仅扩展错误分类与重启 codex exec（参数不变）；无凭证处理变更。
- **记忆**：不涉及（工具脚本无状态持久化需求；尝试记录即上文 state）。
- **可观测**：每次切换打印原因 + state.model_attempts 完整记录；事件日志原有机制不变。
- **取舍声明**：订阅级限额换模型大概率无效仍尝试（用户明确要求，成本低）；不做「切换前先探测模型可用性」的预检（多一次请求，收益低，失败即切换已足够快）。

## 验收标准

1. `cd codex-dev && PYTHONPATH= uv run pytest tests -q` 全绿（含新增测试）。
2. `PYTHONPATH= uv run ruff check codex-dev/` 通过（若 ruff 配置覆盖该目录；不覆盖则说明）。
3. 手工验证：构造 quota / model_unavailable 错误事件喂 EventParser 输出正确标记；mock runner 验证 main 切换流程。
4. 不执行 git commit（P0-3，等待用户确认）。
