## 背景：第一轮遗留两处

第一轮修复（见 `2026-09-02-Web界面四问题修复方案.md`）验收后遗留：

### 遗留 A：主 context 事件转发仍然失效（原问题 4，第一轮未实现）
headless 实测：发「现在几点」→ 主 agent 真执行了 get_time（run.log 有 tool-start），
但页面无工具卡片（toolCards: []）；events.log 主 context 的 `agent/tool-result` 等事件 `listeners=0`。

**根因（已定位，修复时以此为准，可再验证）**：
`qi_agent/serve.py` ServeTransport 的事件 attach 去重集合 `_attached_contexts` 以 **context.id** 为键；
而 Web UI 建会话的 RPC 序列是 `session/create` + 紧跟 `session/resume`（同一 session_id）：
1. `_create_session` → `AgentContext(persist=True)`（总线 A）→ `manager.register` → attach 总线 A，id 入去重集；
2. `_resume_session` → `AgentContext(persist=True, context_id=同id)`（**新对象，总线 B**）→ `manager.register`
   → `_attach_context` 因同 id **已存在而跳过**；
3. `_resume_session` 把 manager.contexts 里的旧对象替换为新对象（总线 B），
   之后 message/send 的 agent 跑在总线 B 上 → serve 的监听器（挂在总线 A）永远收不到。

对比证据：子任务 context 只 register 一次（无 create+resume 双注册）→ attach 正常（events.log listeners=1，进度推送可达）；
旧会话直接 resume（本进程内首注册）→ attach 也正常。**只有「create 后立刻 resume 同 id」的路径坏**。

**修复要求**（最小改动）：
`ServeTransport._attach_context` 的去重键从 `context.id` 改为**对象身份** `id(context)`
（`self._attached_contexts: set[int]`），保证每个 context **对象**都 attach 一次——
同 id 的 create/resume 两个对象都各自 attach；同一对象重复 register 仍只 attach 一次。
保留 `_wrap_manager_register` 与现有 handler 逻辑不动。修复后补一条测试：
模拟同 id 连续两次 `manager.register`（第二次为新对象）→ 断言两个对象的事件总线都收到转发监听器
（参考现有 `tests/test_serve_notifications.py` 的构造方式）。

### 遗留 B：子任务任务语义终态（need_more_info/stopped）状态标签不显示（问题 2 尾巴）
headless 实测：子任务返回 `result.status = "need_more_info"`（content 完整显示，但卡片状态标签显示「已完成」）。

**根因**：`session/status` 返回的顶层 `status` 是 **context.status**（=completed，子 agent 线程正常结束）；
任务语义终态（need_more_info / stopped / failed 的业务含义）在 **`result.status`** 字段里。
`qi_agent/web/frontend/src/hooks/useSubtask.ts` 的 `pollSubTask` 只读顶层 status →
`need_more_info`/`stopped` 分支**永远不可达**，卡片一律显示 completed。

**修复要求**（`useSubtask.ts` 内）：
轮询收到响应后，若 `response.result` 是 object 且 `response.result.status`
∈ {completed, failed, need_more_info, stopped}，则**以 result.status 为任务终态**；
否则回退用顶层 context.status（现有逻辑兜底）。终态流转其余逻辑（formatTerminalResult /
clearSubTaskPoll / expanded 规则）不动。注意 result.status 缺失/非法时不得误判。
