## 1. 背景与目标

### 1.1 现状问题

当前工具系统用 `@tool` 装饰器，所有工具函数混在 `builtin.py` 一个文件里（85 行）。对照 Hermes 的工程化架构，存在三个局限：

| 局限 | 说明 |
|------|------|
| **无法携带私有状态** | 装饰器只能注册纯函数；工具若有自己的状态（如计数器、缓存、存储）没地方放 |
| **schema 表达能力有限** | 自动生成只支持 str/int/float/bool，无法表达枚举、嵌套对象、参数级描述 |
| **无分组与元信息** | 没有 toolset 分组、环境检查（requires_env）、异步标记——工具多了以后无法管理 |

### 1.2 目标

对齐 Hermes 的架构思想，升级为**"一个工具一个文件 + 显式注册"**：

- 每个工具独立成文件，可含私有状态/辅助类
- 注册表支持 `register()` 显式注册（对齐 Hermes 的 register 调用）
- **保留 `@tool` 装饰器作为便捷封装**（现有代码零改动，兼容）
- 增加 toolset 分组能力（为后续插件化打基础）

## 2. 设计原理（导师讲解：为什么"文件粒度 + 显式注册"更工程化）

### 2.1 函数粒度 vs 文件粒度的本质区别

```
装饰器模式（现状）:                    文件粒度 + 注册（目标）:
┌──────────────┐                     ┌──────────────┐
│ builtin.py   │                     │ get_time.py  │
│ @tool def a  │                     │ 状态/辅助类    │
│ @tool def b  │                     │ def handler  │
│ @tool def c  │                     │ register()   │
└──────────────┘                     ├──────────────┤
     工具=函数                          │ read_file.py │
     无状态、无分组                     │ 状态/辅助类    │
                                      │ def handler  │
                                      │ register()   │
                                      └──────────────┘
                                     工具=文件（含注册）
```

**关键洞察：工具不只是"函数"，它是"函数 + schema + 元信息 + 可选状态"的完整单元。** 文件粒度让这个完整单元有地方安放；显式注册让这些信息被集中管理。

### 2.2 register() 为什么比装饰器信息量更大

```python
# 装饰器：只表达"函数是工具"
@tool(description="xxx")
def my_tool(...): ...

# register()：表达"工具的完整画像"
registry.register(
    name="my_tool",
    toolset="file",          # 归属分组（文件/终端/网络...）
    schema={...},            # 手写 schema（精细控制）
    handler=my_tool,         # 处理函数
    check_fn=...,            # 环境检查（如：依赖存在才注册）
    requires_env=[...],      # 需要的环境变量
    emoji="📄",              # 显示用
)
```

**信息量 = 可管理性。** 装饰器适合"快速声明"，register 适合"完整描述"。

### 3.2 ToolEntry：注册条目的数据结构（新增）

```python
@dataclass
class ToolEntry:
    """注册表中的一个工具条目（对齐 Hermes 的 ToolEntry 思想）。"""
    name: str                # 工具名（唯一）
    toolset: str             # 归属分组（默认 "builtin"）
    schema: dict             # 完整 JSON Schema
    handler: Callable        # 处理函数（接收 **arguments）
    description: str = ""    # 一句话描述
    check_fn: Callable | None = None   # 环境检查（返回 bool，False 不注册）
    requires_env: list[str] | None = None  # 需要的环境变量
```

### 3.3 register()：显式注册 API（新增，核心）

```python
def register(
    name: str,
    toolset: str = "builtin",
    schema: dict | None = None,        # None 则从 handler 签名自动生成
    handler: Callable | None = None,
    description: str = "",
    check_fn: Callable | None = None,
    requires_env: list[str] | None = None,
) -> None:
    """显式注册一个工具。

    用法:
        register(name="get_time", handler=get_time, description="获取时间")

    设计说明:
    - schema 可手写（精细控制）或省略（自动从 handler 签名生成）
    - check_fn 返回 False 时跳过注册（如依赖缺失时优雅降级）
    - 重复注册同名工具：抛错（防止意外覆盖），除非显式 override
    """
```

### 3.4 @tool 装饰器：改造为 register() 的便捷封装（兼容）

```python
def tool(description: str = "", toolset: str = "builtin") -> Callable:
    """装饰器：register() 的便捷封装（保留向后兼容）。

    用法（与现在完全一致）:
        @tool(description="获取当前时间")
        def get_time() -> str: ...
    """
    def decorator(fn: Callable) -> Callable:
        register(name=fn.__name__, toolset=toolset,
                 handler=fn, description=description)  # schema 自动生成
        return fn
    return decorator
```

**兼容性保证：现有 `@tool` 用法零改动**，装饰器内部转调 register()。

### 3.5 工具文件模板（1 工具 1 文件）

```python
"""get_time 工具：获取当前时间。"""

from qi_agent.tools.registry import register


def get_time() -> str:
    """返回当前本地日期时间。"""
    from datetime import datetime
    return datetime.now().strftime("%Y-%m-%d %H:%M:%S")


register(
    name="get_time",
    toolset="builtin",
    handler=get_time,
    description="获取当前日期和时间",
)
```

## 8. 风险与说明

- **兼容性风险：低**。@tool 保留、execute_tool 接口不变，只有内部存储结构变化（dict → ToolEntry），现有测试可验证
- **手写 schema vs 自动生成**：升级后**两者都支持**（register 的 schema 参数可省略），不强迫手写
- **YAGNI 提醒**：toolset 分组/check_fn/requires_env 目前"有 API 但用得少"——它们是给未来插件化/多环境准备的，现在实现但不过度使用
