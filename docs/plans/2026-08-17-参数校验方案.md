## 1. 目标

在 `execute_tool` 执行前用 schema 校验模型传入的参数（必填/类型/多余），失败时返回**精确可行动的错误信息**（而非模糊的 `[工具错误] 执行失败`），让模型能自我纠错，减少无效 API 轮次。

## 2. 设计原理（导师讲解：校验的价值）

### 2.1 现状问题

```python
execute_tool("read_file", {})                   # 缺 path → TypeError → "[工具错误] 执行失败"
execute_tool("read_file", {"path": 123})         # 类型错 → open() 炸 → 模糊错误
```

**模型收到模糊错误**：不知道为什么失败、该怎么改 → 盲目重试 → 浪费 API 轮次。

### 2.2 解法：schema 是现成的"校验说明书"

注册时已有 schema（参数类型/必填）——**执行前校验，失败给精确错误**：

```
模型传参 → schema 校验 → 通过 → 执行 handler
                       → 失败 → "缺少必填参数: path" / "类型错误: 期望 string"
```

**核心价值：错误信息"可行动"**——模型看到就知道怎么改，一轮纠错到位。

## 3. 设计

### 3.1 校验器（registry.py 内新增函数）

```python
def validate_arguments(schema: dict, arguments: dict) -> str | None:
    """校验工具参数。返回 None=通过，否则返回可行动的错误信息。

    校验项：
    1. 必填检查：schema.required 中缺失的参数
    2. 类型检查：参数类型与 schema.properties 声明的类型不符
    3. 多余参数：传入 schema 未声明的参数
    """
    func = schema["function"]
    params = func["parameters"]
    properties = params.get("properties", {})
    required = params.get("required", [])

    # 1. 必填检查
    missing = [r for r in required if r not in arguments]
    if missing:
        return f"缺少必填参数: {', '.join(missing)}"

    # 2. 类型检查 + 3. 多余参数
    type_map = {"string": str, "integer": int, "number": (int, float), "boolean": bool}
    for name, value in arguments.items():
        if name not in properties:
            return f"未知参数: {name}（可用参数: {', '.join(properties)}）"
        expected = properties[name].get("type")
        if expected in type_map and not isinstance(value, type_map[expected]):
            return f"参数 {name} 类型错误: 期望 {expected}, 实际 {type(value).__name__}"

    return None
```

**注意**：`bool` 是 `int` 的子类（Python 特性），类型检查用 `isinstance` 时 `True` 会通过 integer 检查——需处理（见风险节）。

### 3.2 execute_tool 接入

```python
def execute_tool(name: str, arguments: dict) -> str:
    entry = _TOOL_REGISTRY.get(name)
    if entry is None:
        return f"[工具错误] 未知工具: {name}"

    # 新增：参数校验（执行前，返回可行动错误）
    error = validate_arguments(entry.schema, arguments)
    if error:
        return f"[参数错误] {error}"

    try:
        result = entry.handler(**arguments)
        ...
```

**错误前缀用 `[参数错误]` 而非 `[工具错误]`**——让模型区分"我传参错了"（可修正）vs"工具本身失败了"（换工具/放弃）。

## 8. 风险与说明

- **bool 是 int 子类**：`isinstance(True, int)` 为 True——如参数声明 integer 而传 True 会通过校验。当前可接受（工具参数少见 bool/int 混用），严格处理需先判 bool
- **嵌套类型**：schema 只支持基础类型（当前自动生成也如此），list/dict 参数不在校验范围——与"复杂参数类型支持"TODO 联动
- **校验只防"类型错误"不防"业务错误"**：path 是合法 string 但文件不存在——那是 handler 的职责（read_file 已处理）
