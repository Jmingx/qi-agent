# 工具系统分层方案（机制层 + 内置工具层）

> 日期：2026-08-23
> 状态：待评审
> 关联：`2026-08-23-ToolExecutor执行闭环方案.md`、工具三件套方案（2026-08-22）

## 1. 问题

`tools/` 与 `plugins/` 两个目录同样混装两类职责（机制层 + 本体层）：

```
tools/（17 个文件混装）
├── registry.py      ← 机制（工具系统怎么运作）
├── executor.py      ← 机制
├── decision.py      ← 机制
├── __init__.py      ← 装配（导入即注册）
├── read_file.py     ← 工具本体（系统有哪些能力）× 13
├── shell.py
├── ...
└── _sandbox_runner.py

plugins/（9 个文件混装）
├── registry.py      ← 机制（插件系统怎么运作）
├── config.py        ← 机制（plugins.toml 配置加载）
├── __init__.py      ← 装配（导入即注册）
├── security_guard.py ← 插件本体 × 7
├── approval_gate.py
├── context_manager.py
├── debug_logger.py / resource_monitor.py / env_info.py / tool_stats.py
```

**问题**：
- 机制层（注册/执行/决策/配置，几乎不再变）与本体层（新增能力 = 频繁加文件）混在一个目录
- 新工具/新插件开发者要在一堆机制文件里找"我该放哪"
- 与参考对象 Hermes 不一致（Hermes：工具机制 + builtin_tools/ 分离）

## 2. 目标结构

```
tools/                        # 机制层（工具系统的心脏）
├── __init__.py               # 装配：import builtin 触发注册 + 导出 registry 操作
├── registry.py               # 注册表（register/execute_tool/validate_arguments）
├── executor.py               # 执行闭环（审批/并发/结果封装）
├── decision.py               # 决策码（ToolAction/ToolDecision/错误码）
└── builtin/                  # 工具层（1 工具 1 文件，新增能力只动这里）
    ├── __init__.py           # import 全部工具触发自注册
    ├── read_file.py / shell.py / write_file.py / patch.py / search_files.py
    ├── list_dir.py / file_delete.py / get_time.py / todo.py / clarify.py
    ├── run_python.py / web_search.py / web_extract.py
    └── _sandbox_runner.py    # run_python 的私有执行引擎（跟它走）

plugins/                      # 机制层（插件系统的心脏）
├── __init__.py               # 装配：import builtin 触发自注册 + 导出 registry 操作
├── registry.py               # 插件注册表（register_plugin/load_plugins）
├── config.py                 # 插件配置加载（plugins.toml）
└── builtin/                  # 插件层（1 插件 1 文件，新增能力只动这里）
    ├── __init__.py           # import 全部插件触发自注册
    ├── security_guard.py / approval_gate.py / context_manager.py
    ├── debug_logger.py / resource_monitor.py / env_info.py / tool_stats.py
```

## 3. 引用面分析（迁移清单）

### tools/ 引用面

**不需要改（机制层引用，绝对路径不变）**

```
agent.py:            qi_agent.tools.decision / executor / registry
plugins/*.py:        qi_agent.tools.decision / registry
工具文件内部互引:     from qi_agent.tools.registry import register（builtin 内引用
                    tools 根部的机制层——绝对路径不变，天然可用）
tests 的机制 import: qi_agent.tools.decision / registry / executor
```

**需要改（工具本体的 import）**

```
qi_agent/cli.py:                    from qi_agent.tools import get_time, read_file, ... 
tests 约 12 个文件:
  from qi_agent.tools.read_file import read_file
    → from qi_agent.tools.builtin.read_file import read_file
  import qi_agent.tools.web_search as ws
    → import qi_agent.tools.builtin.web_search as ws
  具体工具：read_file/shell/write_file/patch/search_files/list_dir/file_delete/
           get_time/todo/clarify/run_python/web_search/web_extract
  不变：import qi_agent.tools（test_security_guard——触发注册用）
```

### plugins/ 引用面

**不需要改**

```
agent_factory.py:    from qi_agent.plugins import load_plugins（registry 导出，路径不变）
测试的机制 import:   qi_agent.plugins.registry（register_plugin 等）
```

**需要改（插件本体的 import，约 12 个测试文件）**

```
  from qi_agent.plugins.approval_gate import ApprovalGatePlugin
    → from qi_agent.plugins.builtin.approval_gate import ApprovalGatePlugin
  具体插件：security_guard / approval_gate / context_manager / debug_logger /
           resource_monitor / env_info / tool_stats
  特殊：test_async_compressor.py 的 patch 路径
    "qi_agent.plugins.context_manager.default_summarizer"
    → "qi_agent.plugins.builtin.context_manager.default_summarizer"
```

### 注册触发链路（关键，防"工具/插件不注册"）

```
tools/__init__.py:     from . import builtin          # 触发 builtin/__init__ 执行
tools/builtin/__init__: from . import read_file, shell, ...  # 各文件 register() 自注册

plugins/__init__.py:     from . import builtin
plugins/builtin/__init__: from . import security_guard, ...  # 各插件 register_plugin() 自注册
```

漏一个 import = 该工具/插件静默不注册（CLI 光秃秃）——测试全量回归兜底。

## 4. 决策点

| # | 决策 | 推荐 | 理由 |
|---|---|---|---|
| D1 | 子目录命名 | **builtin/**（两个包一致） | Hermes 用 builtin_tools/，短命名对齐"内置"语义；std/ 有标准库歧义；tools 与 plugins 统一命名降低心智负担 |
| D2 | `_sandbox_runner.py` 归属 | **进 tools/builtin/**（跟 run_python） | 它是 run_python 的私有执行引擎（模块名下划线 = 私有），与使用者内聚；机制层只留"工具系统运作"三件套（registry/executor/decision） |
| D3 | 旧路径兼容 | **不留**（全量迁移） | 与决策码机制一致（2026-08-23 用户拍板"不留字符串兼容"）；双路径并存会让"新能力放哪"又模糊；测试一次性迁移成本可控 |
| D4 | cli.py 导入方式 | **保留具体名字 import**（改 builtin 路径） | cli 直接使用 get_time/read_file 等名字（工具注册日志打印），保持显式可追踪 |

## 5. 迁移步骤

```
1. 新建 tools/builtin/ 与 plugins/builtin/，git mv 全部本体文件
2. 新建两个 builtin/__init__.py（import 全部本体触发自注册）
3. 改写 tools/__init__.py 与 plugins/__init__.py（from . import builtin + 导出 registry 操作）
4. 改 cli.py 工具 import（qi_agent.tools.X → qi_agent.tools.builtin.X）
5. 改测试 import（约 20 个文件：工具 12 + 插件 12，路径加 .builtin）
6. 全量测试 + ruff 验证
7. 归档：principles（机制层/本体层分层原理）+ devlog
```

## 6. 验收标准

```
✅ tools/ 根目录只剩机制文件（__init__/registry/executor/decision）
✅ tools/builtin/ 含全部 14 个工具文件（含 _sandbox_runner.py）
✅ plugins/ 根目录只剩机制文件（__init__/registry/config）
✅ plugins/builtin/ 含全部 7 个插件文件
✅ 全量测试通过（含注册触发：CLI/测试 import 后工具与插件可用）
✅ ruff 全过
✅ 无 qi_agent.tools.<工具名> / qi_agent.plugins.<插件名> 残留引用（旧路径清零）
```

## 7. 收益

```
✅ 机制与本体分离：tools/、plugins/ 根 = "系统怎么运作"（稳定），builtin/ = "有哪些能力"（常变）
✅ 新增工具/插件 = builtin/ 加文件 + builtin/__init__ 加一行——零触碰机制层
✅ 对齐 Hermes 结构（工具机制 + builtin_tools 分离）
✅ 目录可读性：tools 17 混装 → 机制 3 + 工具 14 分居两层；plugins 9 混装 → 机制 2 + 插件 7 分居两层
✅ 两个包同构（tools/ 与 plugins/ 结构对称），心智模型统一
```
