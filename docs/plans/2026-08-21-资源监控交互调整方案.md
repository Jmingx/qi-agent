# 资源监控交互调整方案：命令式查看（移除每轮状态行）

> **状态:** ✅ 已评审通过（2026-08-21，决策点 1-3 用户整体批准）
> **作者:** Hermes（qi-agent 开发会话）
> **日期:** 2026-08-21
> **前置:** v0.4.22（资源监控已提交）；用户反馈：每轮对话都输出资源提示太吵

---

## 1. 需求

1. **移除每轮对话后的资源状态行**（`[资源] 上下文 X/64,000 ...`——post-llm 后自动打印）
2. **新增 CLI 命令主动查看资源消耗**（输入命令 → 显示当前累计）

## 2. 设计

### 2.1 命令

```python
# cli.py
USAGE_COMMANDS = {"usage", "资源"}   # 大小写不敏感（lower() 匹配，同 clear 模式）
```

- 命中命令 → 打印所有带 `report()` 的插件汇总（与退出时的汇总复用同一段逻辑，
  抽取为 `_print_plugin_reports(installed_plugins)`）——默认装配下即资源监控；
  用户若开了 tool_stats 会连带显示工具统计（观测类插件统一约定）
- 不消耗 LLM 调用（命令分支在 agent.chat 之前，同 clear/exit）

### 2.2 每轮状态行 → 条件警告

- `_print_status` 删除（不再每轮打印）
- **≥80% 上下文警告保留为条件打印**：平时完全安静，仅当上下文占用 ≥80% 时
  打印警告行 `[资源] ⚠️ 上下文占用 81%（52,000/64,000），建议 clear 或压缩`
  ——保留原方案"防上下文爆炸"价值，同时满足"平时不吵"

### 2.3 quiet 配置移除

- 每轮状态行删除后 quiet（评测静默）失去作用点——评测环境本就由
  `build_agent(interactive=False)` 不装配（agent_factory 双重保险），quiet 冗余
- 连带删除 `quiet` 相关测试

## 3. 测试设计（TDD）

| 用例 | 验证点 |
|------|--------|
| `test_no_status_line_normal` | 正常轮（<80%）无任何打印（替代原 status_line 测试） |
| `test_monitor_warning_threshold` | ≥80% 仍打印警告行（含 ⚠️） |
| `test_cli_usage_command` | 输入 usage → 打印插件 report（参照 test_cli_clear 模式） |
| 现有累积/锚点/report 测试 | 不变 |

## 5. 决策点

| # | 决策点 | 方案 |
|---|--------|------|
| 1 | 命令名 | `usage`（+ 中文别名 `资源`，同 clear 双语风格） |
| 2 | ≥80% 警告 | 保留为条件打印（平时安静，临界提醒） |
| 3 | quiet 配置 | 移除（无作用点，评测靠 interactive=False 不装配） |
