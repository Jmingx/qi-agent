# 工具审批声明式方案（ToolEntry.approval）

日期：2026-08-22 ｜ 状态：待评审 ｜ 关联：v0.4.26（TOOL_APPROVAL_MAP）

## 背景

v0.4.26 引入 `TOOL_APPROVAL_MAP`（工具名 → 审批描述模板的集中表），解决
"新增审批工具要改插件硬编码分支"的问题。但表只覆盖**无条件审批**类：
- write_file 覆盖/越界、run_python 沙箱降级、shell 命令前缀匹配仍是
  security_guard 插件里的硬编码分支——加这类工具还是要改插件

用户提出更彻底的方案：**审批逻辑是工具的固有属性**，不应与工具分离。
集中表整个消灭，ToolEntry 增加 `approval` 字段，每个工具在注册时自声明
审批逻辑——插件变纯执行器，从此零改动。

## 设计

### 1. ToolEntry 增加 approval 字段

```python
@dataclass
class ToolEntry:
    ...
    approval: str | Callable[[dict], str | None] | None = None
    # str     = 无条件审批模板（"删除文件 {path}"，{param} 从参数填充，
    #           缺参/不匹配回退模板本身）
    # callable = 条件审批函数：接收 arguments，返回审批描述 str（需审批）
    #           或 None（放行）
    # None    = 默认放行（不产生审批）
```

register() 增加 `approval=None` 参数；@tool 装饰器同步支持（顺带，现有
工具全用 register()）。

### 2. 各工具自声明审批

| 工具 | approval | 说明 |
|---|---|---|
| file_delete | `"删除文件 {path}"` | 无条件模板（迁移自 TOOL_APPROVAL_MAP） |
| write_file | callable | 覆盖（`os.path.exists`）→ `覆盖写入 {path}`；项目外 → `项目外写入 {path}`；否则 None |
| run_python | callable | import 白名单外模块 → `代码需要 import 'xxx'...`；否则 None |
| shell | callable | 命令前缀匹配：CODE_EXEC 命中 → `沙箱升级:{command}`；APPROVAL 命中 → 审批；否则 None |
| 其余 6 工具 | None（默认） | read_file/list_dir/search_files/web_search/web_extract/get_time 不审批 |

### 3. security_guard 改造：只留系统级底线 + 查 registry

```
保留（系统级底线，硬编码不可关）：
  ① 黑名单（用户配置，plugins.toml）
  ② 敏感路径（.env/.git，path_security）
  ③ 红线前缀（HARDLINE_PREFIXES）→ [安全拦截]（不可审批）

改为查 registry（工具级审批）：
  rule = get_tool(name).approval
  - callable → desc = rule(arguments)；None → 放行
  - str → 模板 format 填充
  → NEED_APPROVAL:desc

删除：
  APPROVAL_PREFIXES/CODE_EXEC_PREFIXES import（挪进 shell 工具）
  _RESTRICTED_MODULES / _needs_sandbox_downgrade（挪进 run_python 工具）
  TOOL_APPROVAL_MAP 查表段
```

依赖方向检查：security_guard（plugins）→ tools/registry（tools）——与现有
`security_guard → tools/write_file` 同向，无环。

### 4. rules.py 收敛

删除 `TOOL_APPROVAL_MAP`（及注释）。保留命令前缀数据
（HARDLINE/SHELL_COMBINATOR/APPROVAL/CODE_EXEC）——shell 工具层兜底与
插件红线判定共享，仍是命令规则的单一来源。

### 5. 测试改造

- **契约测试重写**：不再 monkeypatch 表——用 `register()` 显式注册带
  approval 的假工具 → 插件自动判档（验证"新工具零插件改动"契约）
- **真实注册依赖**：security_guard 判档查 registry，工具必须先注册——
  `test_security_guard.py` 顶部 `import qi_agent.tools`（触发全量注册，
  测真实行为）；或 conftest 统一处理
- 既有判档测试（shell 三档/run_python 降级/敏感路径）语义不变，适配新路径

## 决策点（待评审确认）

| # | 决策点 | 意见 |
|---|--------|------|
| 1 | ToolEntry.approval 三态（str/callable/None） | ✅ 用户已拍板（callback） |
| 2 | 系统级底线（黑名单/敏感路径/红线）保留在插件 | ✅ 安全底线硬编码哲学；随工具声明会被动态注册破底线 |
| 3 | _RESTRICTED_MODULES 挪入 run_python.py | ✅ 沙箱内容策略随工具自包含 |
| 4 | @tool 装饰器同步支持 approval | ✅ 顺带（保持便捷封装完整） |
| 5 | TOOL_APPROVAL_MAP 删除（含上一版注册式方案一并作废） | ✅ 用户方案更彻底 |
