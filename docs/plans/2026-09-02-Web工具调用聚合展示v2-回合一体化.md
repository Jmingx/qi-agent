## 一、现状（v1 已上线）

- v1：连续 tool entries 聚合渲染为 `.tool-run` 容器（一个 🔧 avatar + 容器内多行 ToolCard），
  但 **assistant 最终文本仍是独立气泡**（.row.assistant + MessageBubble）——用户在视觉上看到
  "工具一个泡泡 + 回复一个泡泡"两个独立泡泡。
- ToolCard 行结构：head（🔧 name + 状态徽章）+ `<details>` 参数 JSON + footer（✓ 结果摘要）。
  用户不想要参数 JSON。

## 二、目标形态（对齐 Hermes assistant 消息 = tool parts + text parts 一体）

一次对话回合（user 提问 → 若干工具 → 最终文本回复）在消息流中呈现为**一个 assistant
回合气泡**：
```
[我] 查一下今天天气
[qi] ┌─────────────────────────────────┐
     │ ▸ 🔧 已完成 4 次工具调用（可展开） │ ← 工具区 header（完成自动收起）
     │ ─────────────────────────────── │
     │ 北京今天晴，气温 18-31℃……        │ ← 最终文本内容（同一容器内）
     └─────────────────────────────────┘
```
展开工具区时：header 下方平铺工具行（名称 + 状态徽章 + 结果摘要，**无参数 JSON**）。

## 三、设计

### 1. 回合容器切分（渲染层，MessageList.tsx）
- 在 v1 的 `splitToolRuns` 基础上扩展：**tool-run 段 + 紧随其后的连续 assistant message
  entry 合并为一个 RenderItem**（kind: 'assistant-turn'）：
  - 数据形态：`{ kind: 'assistant-turn'; toolEntries: ToolEntry[]; textEntry?: TextEntry; id: number }`
  - 合并边界：tool 段后紧跟的第一个 entry 若为 `message && role === 'assistant'` → 并入；
    继续向后吸收**连续**的 assistant message entry（一般只有最终回复一条）。
    遇到 user/system/subtask 或列表尾 → 该回合结束。
  - 文本可能晚到（流式中）：tool 段先出现时先渲染回合容器（工具区），文本 entry 到达后
    回合 item 扩展出 textEntry → 容器内补文本区（同一 id 的 streaming 更新照常驱动文本增长）。
  - 若无后续 assistant 文本（被 stop/异常）：回合容器只有工具区，正常。
  - user 消息、子任务卡、tool 段前的孤立 assistant 文本（理论情况）保持现状独立渲染。
- 渲染：回合容器行 = `row assistant message-row` + `avatar ai`（qi 头像，替代 v1 的 🔧——
  工具是 assistant 的行为）+ `.bubble-wrap` 内回合容器。

### 2. 折叠交互（工具区）
- 折叠状态为**组件内状态**（每回合容器一个实例），规则：
  - `allDone = toolEntries.every(t => t.result)`（每行有 result = 完成/被拦截）
  - 默认跟随：`!allDone` 时展开（运行中实时可见）；`allDone` 由 false→true 转变时**自动收起**
    为 header 行（"已完成 N 次工具调用"）。
  - 用户点击 header 展开/收起后进入**手动覆盖**态（不再随完成度自动变），保证用户控制权。
  - 历史/恢复场景：回合容器只出现在实时会话（历史恢复只有文本消息，无工具 entry），无需特判。
- header 行文案（运行时/完成时区分）：
  - 未完成：`🔧 工具调用中…（N 次）`（或等价的运行中态样式）
  - 已完成收起：`✓ 已完成 N 次工具调用` + 展开箭头（chevron）
  - 点击整行 header 切换展开。
- 展开态布局：header 下平铺工具行（复用 v1 行样式）。

### 3. 工具行精简（ToolCard.tsx）
- **删除 `<details>` 参数 JSON 块**（组件里移除 details 与 `toolArguments` 的渲染；props
  签名可保留 toolArguments 但不再渲染，或一并去掉——以不破坏调用方为原则，MessageList 同步）。
- 行内容 = head（工具名 + 状态徽章）+ footer（结果摘要 ✓/⛔ + 耗时）。行更瘦、信息聚焦。
- 若删除后行过短影响视觉，可把 head 与 footer 合并单行（工具名左、状态+摘要右/下）——样式自洽即可。

### 4. 样式（style.css）
- 回合容器：延续 `.tool-wrap > .tool-run` 的容器语言，新增回合容器类（如 `.assistant-turn`）
  或复用 tool-run 容器并扩展文本区——文本区与工具区间用细分隔线。
- 工具区折叠 header 样式（hover 反馈、chevron 旋转过渡）；文本区沿用气泡文本样式
  （white-space: pre-wrap 等），**不引入 markdown 渲染**（现状纯文本）。
- 保持 v1 已验收的视觉基调（圆角 16、panel 渐变底、状态色体系）。

### 5. 虚拟滚动适配
- 估算：assistant-turn 高度 ≈ 工具区（折叠时 header 高 / 展开时 Σ行高）+ 分隔 + 文本高。
  折叠状态影响高度 → 估算给展开态保守值，运行时由既有 ResizeObserver 实测修正（机制已存在）。
- key/ref 锚定回合 id（= 段首 tool entry id 或文本 entry id，取先出现者），
  自动滚动/搜索高亮逻辑沿用。
