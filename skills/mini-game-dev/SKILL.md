# 小游戏开发

目标：任何想法都能快速变成一个"能跑、能退、输入安全"的最小可玩版本。

## 1. 定形态（先做）
按 `references/tech-matrix.md` 决策矩阵选择技术形态，理由一行带过。
无法与用户交互澄清时，套用矩阵中的默认假设，并在交付说明中列出。

## 2. 澄清需求（能问则问）
玩法一句话、操作方式、单人/双人、一局时长、是否需要计分/关卡/音效、目标平台。

## 3. 搭骨架
按 `references/blueprint.md` 对应形态的骨架初始化。默认：单文件、零外部依赖、中文界面、放到 `games/<名字>/` 目录（或用户指定位置）。

## 4. 实现（先跑通再叠加）
- 完整游戏循环：更新 → 渲染 → 输入，保证存在明确退出路径（quit 命令 / Ctrl+C / 窗口关闭）。
- 校验所有用户输入：非法输入只提示不崩溃。
- 第一版只做"最简可玩"，跑通后再加计分、关卡、音效等。

## 5. 冒烟验证（必须，不可跳过）
- CLI 文本形态：脚本内模拟一轮完整输入，确认正常开始→游玩→结束/退出。
- pygame / HTML 形态：本环境无法实机运行 GUI 时，至少验证语法/静态正确、启动代码路径可达，并在交付中明确"需本地运行"+ 精确命令。
- 验收清单见 `references/blueprint.md` 末尾。

## 6. 交付
- 说明启动命令/打开方式、玩法与控制键。
- 如用户需要设计文档沉淀，可调用 docs-archive 归档。

**完成标准**：产物能跑、能退、非法输入不崩溃、有启动说明。
